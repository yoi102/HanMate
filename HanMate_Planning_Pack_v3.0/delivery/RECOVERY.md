# 数据保留与恢复交接

1. 更新前，在“设置 → 备份与合并恢复”查看预览，生成逻辑备份并另存到自己掌握的位置。可选 `.hanbackup` 或附加 `.zip` 兼容后缀，两者内容协议相同。确认系统保存完成，不把分享面板打开当作送达。
2. 逻辑备份涵盖已保存的个人正文、人工注音、收藏及允许的音频/资源关系，设置按导入时的明确选择处理。未保存草稿、回收站、AI模型/声音选择和默认词库开关不随该备份迁移；先保存重要草稿，模型在新设备重新下载/选择。备份未加密。
3. 一般迁移先选合并：查看新增、复用、冲突另存及资源状态，不直接替换数据库。相同工程包重复导入的幂等不意味着任意修改后的资料都能无冲突合并。
4. 完整替换另有二次确认；生产实现先生成并核验私有SQLite/音频安全副本。恢复向导依数据库中的操作收据和副本完整性判断，不凭 `ready.json` 文件存在就判成功。真实资料的破坏性恢复本轮没有执行。
5. 启动异常、空间不足或导入失败时保留原数据库、音频与recovery目录。不要用空库覆盖，不要手动删除 `.part`、旧音频、恢复副本来“修复”。应用可提供明确的草稿恢复/丢弃和媒体清理入口；清理按引用、草稿、文件租约及安全副本保护规则执行。
6. 当前数据库schema=2，升级前检查版本；未知/更高版本保守拒绝。退回旧EXE/APK不等于数据库降级，也没有提供通用逆向迁移。需要回退数据时，应选择兼容版本并通过应用已支持的安全恢复流程，先保留现状。

录音和导出副本可能仍在本机。移除绑定/加入回收站不是安全擦除；应用不能删除已保存到外部位置或已交给接收应用的文件。不要把含私人正文、录音或完整备份的原始诊断附进公开问题单。

故障交接记录：平台/系统、应用版本与产物哈希、最后一个操作、脱敏错误类型/时间、备份是否存在。HM-D019保持开放；本轮没有执行完整回归、物理满盘或强杀恢复验证。
