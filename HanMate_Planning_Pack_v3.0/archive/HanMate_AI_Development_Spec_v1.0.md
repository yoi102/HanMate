# 中文学习应用：需求规格与 AI 开发执行规范

> 技术方向：.NET MAUI · iOS / Android / Windows  
> 文档版本：1.0  
> 编制日期：2026-09-14  
> 暂定工程代号：HanMate；中文产品名尚未确认，不视为已经定名。  
> 文档性质：开发基线提案。明确需求应落实；本文补充的默认方案可调整，但应记录决策，不能由开发 AI 静默删改。

---

## 0. 先回答：原来的规划是否适合交给 AI？

**适合作为产品构想，但还不适合直接作为完整的开发指令。**

原规划已经说明了平台、主要页面和核心学习方式，方向明确。欠缺的不是继续增加页面，而是把“应该怎么做”变成可实现、可验证的规则。例如：“按标点停止”究竟是单段播放还是全文自动播放；用户改完拼音，原录音是否仍然适用；分享录音是否包含文本；备份恢复时如何处理同名收藏夹和同 ID 内容。这些问题若不提前约定，AI 容易做出能演示、但实际使用不一致的程序。

本版本把原需求整理成以下开发闭环：

**浏览教学内容 → 按字显示拼音 → 点击朗读 → 搜索与收藏 → 导入自己的内容 → 校正拼音 → 录制/导入语音 → 分享与离线迁移。**

本文件可作为 `docs/requirements.md` 使用。首次开发应先做第 17 节的技术验证和第 18 节的阶段任务，不要直接一次性生成整个应用。

### 0.1 术语与优先级

| 标记 | 含义 |
|---|---|
| 必须 / P0 | 首个完整版本的验收范围；分阶段完成，但不能遗漏 |
| 默认方案 | 原需求没有明确的部分，本文提供的可执行默认值 |
| 可选 / P1 | 不阻塞首版、得到确认后再做的增强 |
| 暂不做 / P2 | 不属于首版，不能为了实现它而引入额外系统 |

**“首版”是指所有 P0 阶段完成后的版本，不是只有拼音页和几个演示按钮的原型。**

### 0.2 首版默认决策

| 决策项 | 默认方案 |
|---|---|
| 产品定位 | 离线优先的普通话/中文学习与个人学习资料工具 |
| 主导航 | 拼音、学习、搜索、收藏、设置，共五个入口 |
| 学习内容类型 | 词语、课文、诗词；统一管理，分别呈现 |
| 账户与服务器 | 首版不需要账户、服务器、登录或云数据库 |
| 教学语言 | 内置正文为简体中文，注音为汉语拼音；不跟随界面语言变化 |
| 辅助译文 | 按界面语言显示日语或英语；中文界面隐藏译文 |
| 用户文本 | 保留用户原文；自动注音，可人工修改；不承诺自动翻译 |
| 分享方式 | 通过系统分享或另存文件，分享“内容包”或单独音频；不建设社区 |
| 迁移方式 | 导出一个备份文件，再在另一设备导入，无需服务器 |
| 应用形态 | 优先使用 MAUI 原生 XAML + MVVM，不默认转为 WebView 网站壳 |

## 1. 产品目标与范围

### 1.1 面向的使用方式

用户可以从拼音入门，也可以按场景、难度或学段学习词语、课文与诗词。遇到不认识的词语时，可以输入汉字或拼音查询；希望反复学习的内容可以加入自定义收藏夹。用户也可以把自己的学习资料导入应用，修改注音，并配上自己的朗读音频。

不得把“面向日语/英语用户学习中文”和“按中国小学、初中、高中分类”视为同一套难度体系。这是两种可同时存在的分类维度。

| 需求 ID | 用户需求 | 本文落实位置 |
|---|---|---|
| R01 | iOS、Android、Windows | 第 2、16、17 节 |

| R04 | 拼音表同页滚动，点击发音 | 第 5 节 |

| R06 | 词语、课文、诗词，支持多种分类 | 第 6 节 |

### 1.3 首版不包含的能力

首版不默认包含在线 AI 聊天、语音评分、语音识别转文字、自动音文时间轴对齐、社交广场、排行榜、广告、支付、云同步、教师后台或学习管理系统。

PDF/Word/OCR 导入、自动翻译、书写笔顺、背词算法、拼音首字母搜索、全文语义搜索，可作为后续独立需求。**用户要求的文本导入、注音校正、录音和分享并不在延期范围内，它们仍是 P0。**

## 2. 平台与技术基线

### 2.1 技术建议

| 项目 | 建议 |
|---|---|
| UI | .NET MAUI、XAML、MVVM |
| .NET / MAUI | 以当前受支持的稳定版本为基线；本文核查时为 .NET MAUI 10 |
| 界面本地化 | `.resx` + 可通知 UI 刷新的语言服务 |
| 用户数据 | 本地 SQLite；正文注音结构可作为版本化 JSON 保存 |
| 系统合成朗读 | MAUI `ITextToSpeech`，作为音频缺失时的可用性补充 |
| 播放与录音 | 封装独立服务；`Plugin.Maui.Audio` 可作为候选依赖 |
| 文件导入 | MAUI `FilePicker`，通过文件流读取 |
| 保存与分享 | `FileSaver` / 系统文件保存适配、MAUI `Share` [S07][S08] |
| 导出格式 | ZIP 容器 + UTF-8 JSON + 音频文件 |
| 自动化测试 | 纯 .NET 单元测试 + 数据往返测试 + 三平台实际交互测试 |

.NET MAUI 的支持周期与 .NET 本身不完全相同，不能因为 .NET 是 LTS 就推断某个 MAUI 版本具有同样的支持期限。依赖版本应在开工时重新核对，并记录到构建说明中。[S01]

### 2.2 平台约束

iOS 构建链需要合适的 macOS / Xcode 环境；从 Windows 使用相应开发流程时，需要可用的 Mac 构建环境。不能把“Windows 上代码能编译”当成“iOS 已经完成验证”。[S02]

首轮验证必须记录具体 .NET SDK、MAUI workload、Xcode、Android SDK/JDK、Windows SDK、目标系统最低版本，以及所有 NuGet 包版本。最低系统版本按选定 SDK 和依赖确定，不在未验证时随意承诺兼容所有旧设备。

iPad 使用同一 iOS 目标，至少保证基本自适应；专门的平板多栏体验属于可选增强。Windows 必须支持鼠标、键盘与窗口缩放，不能只验证触屏交互。

### 2.3 依赖选型要求

采用第三方组件前，核对许可证、目标框架、三平台支持情况、iOS AOT/裁剪风险与必要权限。官方文档展示某个 API，不等于所有版本都存在该 API；必须针对锁定的依赖版本编译验证。

不要为了调用 Python 拼音库，在手机端引入 Python 运行环境。可以采用合适的 .NET 拼音实现，或在构建阶段加工合法可用的字音/词语数据，再由 .NET 离线服务使用；最终选型需通过多音字、声调与三平台打包测试。[S11][S12][S13]

## 3. 信息架构与全局交互

### 3.1 五个主入口

```text
应用
├── 拼音
│   ├── 声母 / 拼写辅助项
│   ├── 韵母
│   ├── 整体认读音节
│   └── 四声示例弹窗
├── 学习
│   ├── 词语 / 课文 / 诗词
│   ├── 场景 / 难度 / 学段筛选
│   ├── 来源：全部 / 内置 / 我的内容
│   ├── 词语详情
│   ├── 课文与诗词阅读器
│   └── 新建与导入 → 注音编辑 → 音频管理
├── 搜索
│   ├── 查询结果
│   └── 底部搜索输入框
├── 收藏
│   ├── 收藏夹列表
│   ├── 收藏夹详情
│   └── 收藏夹编辑与排序
└── 设置
    ├── 语言 / 阅读 / 音频
    ├── 备份导出 / 导入恢复
    ├── 数据与存储
    └── 关于 / 内容来源 / 开源许可
```

手机默认底部五项导航；Windows 可先保持相同结构，宽屏侧边导航作为可选增强。不得因为原始需求存在重复编号，而少实现搜索、收藏或设置中的某个页面。

### 3.2 通用规则

列表点击正文进入详情，点击独立播放按钮只播放，不同时跳转。详情返回后应保留原列表的筛选、搜索词和滚动位置。页面导航通过稳定 ID 定位内容，不把整篇课文和音频字节放进路由参数。

删除内容、覆盖式恢复、丢弃未保存编辑，需要明确确认。文件选择取消、权限拒绝、内容为空、音频不存在等应有正常状态，不以崩溃或无响应表示失败。

全局同一时间只允许一个朗读/播放任务或一个录音任务。切换页面时默认停止当前播放；首版不实现后台连续朗读。

## 4. 多语言与教学内容分离

### 4.1 三层语言模型

| 层级 | 内容 | 是否随界面语言切换 |
|---|---|---|
| UI 层 | 导航、按钮、提示、分类标签、设置项 | 是 |
| 教学层 | 汉字、词语、课文、诗词、例句、拼音 | 否 |
| 辅助译文层 | 词义、句子译文、标题辅助翻译、教学说明译文 | 是；中文界面不显示辅助译文 |

界面语言仅为 `zh-Hans`、`ja`、`en`。默认首次跟随系统：中文系统使用简体中文界面，日语系统使用日语，其余使用英语。之后以用户明确设置为准。该映射是产品默认决策，不代表支持繁体中文 UI。

例如正文始终显示：

```text
xué  xí
学   习
```

日语界面可在下方显示 `勉強する`，英语界面可显示 `to study`；简体中文界面不显示这一行，也不保留空白占位。

### 4.2 必须遵守的规则

- 切换 UI 语言不得改写正文、作者原名、汉字、拼音或收藏内容 ID。
- UI 文案使用资源键管理；词语、例句和译文存入内容数据，不把整个词库塞进 `.resx`。
- 译文按当前 `ja` 或 `en` 精确选择。缺译文时不擅自显示另一语言，正文仍可正常学习；编辑页可显示“尚未添加该语言译文”。
- 内置正式发布数据应具备要求的日/英译文；用户导入资料没有译文时允许保存和使用。
- 语言切换立即刷新当前页面、主导航及后续弹窗；不得只修改 `CurrentUICulture` 却让已显示页面保持旧语言。
- 中文正文的朗读语言独立指定为普通话相关语音，不使用当前 UI 语言作为朗读语言。

MAUI 提供资源文件本地化机制，但即时语言切换、教学译文选择和平台语言声明仍需要应用层实现及测试。[S03]

### 4.3 资源键示例

| Key | zh-Hans | ja | en |
|---|---|---|---|
| Nav.Pinyin | 拼音 | ピンイン | Pinyin |
| Nav.Learn | 学习 | 学習 | Learn |
| Nav.Search | 搜索 | 検索 | Search |
| Nav.Favorites | 收藏 | お気に入り | Favorites |
| Nav.Settings | 设置 | 設定 | Settings |
| Action.Play | 朗读 | 読み上げ | Read aloud |
| Action.ImportText | 导入文本 | テキストを取り込む | Import text |
| Action.ExportBackup | 导出备份 | バックアップを書き出す | Export backup |

以上翻译是初始文案，发布前需要校对。辅助译文“小字”不等于使用难以阅读的字号，应支持系统字体缩放。

## 5. 拼音页面

### 5.1 内容组织

同一页面按教学分组纵向滚动，分组标题固定清晰，避免给每个声母、韵母单独创建页面。初始内容清单建议如下，发布前由教学内容维护者校对：

| 分组 | 建议条目 |
|---|---|
| 声母 | b p m f d t n l g k h j q x zh ch sh r z c s |
| 拼写辅助项 | y w，附适合初学者的说明 |
| 单韵母 | a o e i u ü |
| 复韵母及特殊韵母 | ai ei ui ao ou iu ie üe er |
| 前鼻韵母 | an en in un ün |
| 后鼻韵母 | ang eng ing ong |
| 整体认读音节 | zhi chi shi ri zi ci si yi wu yu ye yue yuan yin yun ying |

这是入门教学编排，不宣称是完整的普通话音系分析。基础声母、韵母、拼写和声调规则参考《汉语拼音方案》。[S14]`y/w` 的教学归类、缩写韵母的说明，应在数据说明里明确，不能把不同教材的分类混在一起后仍声称完全一致。

### 5.2 点击发音

点击一个条目播放对应的、经过核对的拼音教学音频。声母等条目的示范应按选定教学读法提供，不能让英语 TTS 直接读字母名称，也不能把随机选取的汉字朗读伪装成标准声母示范。

播放时有轻量选中状态。快速点击另一条目立即切换，旧音频必须停止，不允许声音叠加。已发布条目缺少教学音频属于数据缺陷，应明确显示不可播放状态，不静默使用错误发音替代。

### 5.3 长按弹出四声示例

默认长按阈值为 500 ms，可在平台验证后微调。长按触发后，不再触发同一次手势的点击朗读；拖动滚动应取消长按判定。Windows 同时提供右键菜单或可点击的“示例”入口，不能只依赖长按。

弹窗按第一声、第二声、第三声、第四声纵向展示四行，每行包含声调标签、带调拼音、汉字例词、辅助译文及播放入口。点击整行播放整个例词。

**重要修正：声母本身不是带四声的完整音节。** 对声母的“四声示例”，应理解为“包含该声母、分别使用四种声调的真实例词”，不能给 `b/p/m/f` 直接套四个调号。[S14]

以 `m` 为教学示例时，可使用如下待校对内容：

| 声调 | 示例词语 | 拼音 | 标红目标 |
|---|---|---|---|
| 一声 | 妈妈 | mā ma | 第一音节的 m |
| 二声 | 麻木 | má mù | 第一音节的 m |
| 三声 | 马上 | mǎ shàng | 第一音节的 m |
| 四声 | 骂人 | mà rén | 第一音节的 m |

默认保留四声行位，但对确实没有合适常用例词的条目，显示“暂无常用示例”，而不是编造字词或误标声调。轻声可另设说明，不当作四声之一。

### 5.4 标红规则

标红的是**目标拼音部分**，不是默认把整行汉字或整段拼音染红。例如选择 `m` 时标红 `mā` 中的 `m`；选择 `a` 时，标红相应 `ā/á/ǎ/à` 字符。

例词数据应记录目标注音单元和高亮范围，渲染时正确处理声调字符。不要直接对整段文本做忽略声调的全局字符串替换，以免重复词或组合字符发生错误高亮。红色以外还应有选中/强调提示，不能仅依靠颜色表达状态。

长按交互可评估 Community Toolkit 的 `TouchBehavior`，但应针对当前依赖版本明确绑定上下文，并测试点击、长按、滚动的冲突。[S05]

## 6. 学习页面与词语详情

### 6.1 内容类型和筛选

学习页顶部切换“词语 / 课文 / 诗词”。右上角统一提供“新建/导入”，通过来源筛选查看“全部、内置、我的内容”，避免为用户资料再增加第六个主导航。

| 分类维度 | 默认示例 | 数据规则 |
|---|---|---|
| 场景 | 日常、问候、家庭、学校、饮食、交通、购物、工作 | 可多选、多标签 |
| 难度 | 入门、基础、进阶、高级 | 独立字段，可未标注 |
| 学段 | 不限、小学、初中、高中 | 可空，不把“未标注”当作小学 |
| 年级 | 小学一至六年级、初中一至三年级、高中一至三年级 | 必须与学段一致，可空 |
| 来源 | 内置、个人创建、文件导入、分享导入 | 与内容类型分开 |

不同维度的筛选用 AND；同一维度多选值用 OR。界面显示当前筛选并支持一键清除。切换内容类型时，不适用的条件应清除或明确提示，不能得到莫名其妙的空列表。

“学段/年级”默认只是内容标签；没有明确教材版本和授权数据时，不宣称覆盖某一版本的全部教材。

### 6.2 词语列表

每项显示词语、带声调拼音、小字译文及必要的难度/收藏提示。信息应简洁，不在列表里展开全部例句。

词语数据允许一个汉字作为词条。相同汉字串但读音或词义不同的词条，应使用独立的词条/读音义项 ID，不能仅用汉字文本作为唯一键。

### 6.3 词语详情

顶部大字显示词语，上方显示对齐的带调拼音；点击该区域朗读当前词条的读音。旁边提供收藏按钮。词义说明与辅助译文按第 4 节显示。

下方展示例句，每个汉字的拼音在上，汉字在下。点击一条例句，朗读**整个句子**；默认不跳进逐字发音模式。例句播放不改变词条收藏状态。

内置词条默认至少提供两条简短、自然的例句。无例句的个人词条允许保存，页面显示正常空状态，不生成未经确认的虚构例句。

### 6.4 内置内容范围

软件能力和内容规模分开验收。首轮技术样例只需足够验证各类交互；建议首版初始内容包以约 100 个词条、6 篇短课文、6 首诗词作为可调整目标，而不是一开始抓取整套教材。

词条、课文、诗词必须带内容来源和审核状态。正式发布数量按实际通过内容校对的条目统计，不能把 AI 生成草稿算作已审核成品。内容治理要求见第 15 节。

## 7. 课文与诗词阅读器

### 7.1 排版

标题、作者信息、正文分开显示。正文采用“上方拼音、下方汉字”的注音排版，保留原段落、标点及诗词分行。日/英辅助译文放在对应句段下方，不逐个汉字塞入翻译。

需要一个可复用的 `RubyTextView` 或同类自定义注音控件，不要用“整行拼音 Label + 整行汉字 Label”依靠空格凑对齐。

布局必须把汉字及其注音作为同一排版单元；每单元宽度取汉字与拼音所需宽度的较大值，换行时不把拼音和对应汉字分到两行。不得假定所有汉字、拼音、数字、拉丁字母等宽。

### 7.2 点击片段的确定行为

默认点击某个正文小段时，执行三个动作：选中该段；打开或更新同一个放大阅读弹层；停止其他声音并朗读该段。**朗读到当前片段末尾即停止，不自动接着读下一段。**

再次点击同一正在朗读的片段，默认停止；点击另一段则切换并朗读新片段。放大弹层保留“上一段、下一段、朗读/停止、关闭”，其中上一段/下一段默认仅切换，避免用户翻阅时意外连续出声。

页面另外提供“全文朗读”按钮。只有用户主动选择全文朗读时，才按片段顺序继续播放，当前朗读片段有高亮。关闭放大弹层停止该弹层触发的片段朗读；退出阅读页面停止所有与该页面相关的播放。

### 7.3 标点分段规则

分段的目标是决定可点击与朗读的学习单元，不是把源文本破坏成互不关联的碎片。

| 情况 | 默认处理 |
|---|---|
| `，。！？；：` | 作为片段结束边界；标点保留在前一片段 |
| 普通文本中的 `, . ! ? ; :` | 在识别数字、网址等特殊串后再判断边界 |
| 换行/段落 | 保留原有分行，结束当前非空片段；空行是布局信息，不生成可播放空片段 |
| `……`、`...`、`？！` 等连续标点 | 作为一个结束标点组，不产生多个空片段 |
| 结束引号或括号 | 在紧随结束标点时，归入前一片段，例如 `你好！”` |
| 小数、版本号、时间、URL | 避免在 `3.14`、`10:30` 或网址中间误切 |
| `、` | 首版不单独形成可点击片段，可由自然朗读处理轻微停顿 |
| 没有标点的长文本 | 不静默截断；仍保留原文，按阅读布局换行；超过语音引擎单次限制时提示编辑或适配播放分块 |

分段后将全部片段与分隔信息按顺序连接，必须能还原保存的正文，包括原有换行和标点。纯标点输入不得造成空朗读循环。

示例：`今天天气很好，我们去公园。你要一起去吗？` 应形成三段：`今天天气很好，`、`我们去公园。`、`你要一起去吗？`。

全文播放中的额外片段间隔，可按“逗号短停、句末长停”设置默认值，但不能把固定延迟宣称为三平台一致的语音韵律。已有音频包含停顿时，不应重复添加明显多余的静音。

### 7.4 整篇音频与逐段音频

整篇录音只证明拥有“全文播放”音源，**不意味着自动拥有每段时间戳**。首版采取以下明确行为：

| 音源 | 全文播放 | 点击单段 |
|---|---|---|
| 每段独立录音 | 顺序播放各段 | 播放该段录音 |
| 只有整篇录音 | 播放整篇录音；不伪造逐段同步高亮 | 使用该段已绑定音频或普通话 TTS；不可用时明确提示 |
| 无录音、有可用普通话 TTS | 按片段合成朗读 | 合成当前片段 |
| 无可用音源 | 正常阅读，提示缺少音频 | 不播放错误语言或假音频 |

自动识别整篇录音并对齐时间轴不在首版范围内。后续可以扩展手工时间标记，但不能用按字数平均分配时间来冒充精确对齐。

### 7.5 阅读设置

首版提供正文大小、是否显示拼音。译文的语言与可见性始终受第 4 节约束。保存最后阅读位置作为可选增强，不是核心学习流程的前置条件。

## 8. 搜索页面：离线字典

### 8.1 布局与交互

搜索输入框固定在内容区底部、主导航之上；软键盘弹出时，输入框仍可见。结果列表在上方，点击词条进入词语详情，独立播放按钮不触发页面跳转。

支持即时搜索，默认输入防抖 250 ms；Windows 回车立即提交。新查询产生时取消旧查询或丢弃旧结果，避免输入已改变但列表被旧响应覆盖。

首版主要搜索已收录的词语，包括用户建立的词条。课文/诗词标题搜索可作为附加类型筛选；搜索整篇正文不是首版字典功能的前置条件。没有收录的词不应凭空显示“词典解释”。

### 8.2 查询输入与归一化

| 输入 | 预期行为 |
|---|---|
| `你好` | 查找对应汉字词条，精确匹配优先 |
| `ni hao` / `nihao` | 使用无调拼音查找对应词条 |
| `nǐ hǎo` | 使用带调拼音查找，匹配声调者排前 |
| `ni3 hao3` / `ni3hao3` | 解析数字声调，再按相同拼音模型查询 |
| `nǚ` / `nv` / `nu:` | 将 `v`、`u:` 作为 `ü` 的输入别名 |
| 大小写及多余空格 | 大小写不敏感，去除首尾空格并规范内部空格 |
| `xi'an` / `xi an` | 保留音节边界信息，优先匹配“西安”等对应分音节词条 |
| `xian` | 允许召回“先”以及连续无调拼音相同的多音节词，结果分开呈现 |

普通 `u` **不得**无条件转换成 `ü`，`nu` 和 `nü` 不能因去音标逻辑而被强制视为同一个拼音。去掉声调时须保留分音符，不能简单删除全部 Unicode 组合标记。

索引由已确认的词条读音生成。多音字按收录的词条/义项建立多条索引，不为一串汉字的所有候选读音生成指数级组合。

数字声调输入可接受 1—4，以及代表轻声的 0/5；内部轻声统一用 0，未知读音用 `null`，二者不能混淆。

### 8.3 搜索排序

默认按“汉字精确匹配 → 完整拼音且指定声调匹配 → 完整无调拼音匹配 → 前缀匹配 → 包含匹配”排序。同层使用稳定排序，例如词条常用度字段、长度和稳定 ID，避免相同查询每次顺序随机变化。

输入含明确声调时，可以显示无调候选作为次级结果，但必须与精确声调结果区分，不让错误声调命中冒充精确匹配。

先使用本地数据库索引/预计算拼音字段完成此功能，不引入向量数据库、RAG 或在线大模型。拼音首字母搜索及中英混输容错属于 P1/P2，不阻塞汉字和完整拼音搜索。

### 8.4 状态与隐私

空输入显示简短使用示例；无结果显示“未找到已收录词条”。搜索历史可选并可清除，默认不在内容分享包中携带，不上传查询内容。

## 9. 收藏页面

### 9.1 收藏对象

必须支持收藏词语；适当扩展为同时收藏课文、诗词与自己的内容，使用同一套收藏夹机制。点击收藏的词语进入词语详情；点击课文或诗词进入对应阅读器。

收藏引用内容 ID 和必要的读音/义项 ID，不复制出一套无法更新的独立词库。为离线备份和内容缺失提供快照，快照不是正常使用时的第二份主数据。

### 9.2 收藏夹管理

用户可以新增、重命名、修改说明、排序、删除收藏夹，并将内容添加到一个或多个收藏夹。同一内容在同一收藏夹内只能出现一次，但可出现在多个收藏夹。

默认提供“默认收藏夹”。该系统收藏夹保留，用户创建的收藏夹均可删除。收藏夹名称去除首尾空格后不能为空；同级名称比较规则统一，重名时明确提示。

删除收藏夹只删除该夹及关联关系，不删除原文、录音或其他收藏夹里的同一内容。移除收藏同样不等于删除个人内容。

### 9.3 收藏按钮语义

未收藏时点击收藏按钮，打开收藏夹选择界面，默认勾选最近使用的收藏夹；已有收藏时点击按钮，查看和调整所属收藏夹。全部取消勾选才表示取消收藏，避免在多收藏夹场景下“一点就全部移除”。

### 9.4 内容被删除或缺失

删除个人内容前显示其收藏引用数量，并说明相关收藏会移除；录音按引用计数清理，不能误删其他内容仍在使用的音频。

因应用版本或内置内容包变化导致引用失效时，优先通过稳定 ID 和备份快照恢复阅读；无法恢复则显示“内容暂不可用”，不要打开一个空白详情页或静默丢弃记录。

## 10. 设置页面

| 设置分组 | 首版项目 | 规则 |
|---|---|---|
| 语言 | 简体中文 / 日语 / 英语 | 即时刷新 UI；不改变教学内容 |
| 阅读 | 正文大小、显示拼音 | 跨页面一致；恢复备份后生效 |
| 音频 | 普通话语音选择、测试发音 | 不把日语/英语 UI 语音当作中文朗读语音 |
| 数据 | 导出完整备份、导入备份、导入内容包 | 恢复前预览，说明冲突策略 |
| 存储 | 用户资料及录音占用、清理临时缓存 | 清缓存不得删除用户正式录音和正文 |
| 关于 | 应用版本、内容版本、内容来源、开源许可、隐私说明 | 不伪造认证、教材覆盖或审核状态 |

主题切换、朗读速度、学习进度和搜索历史开关可作为 P1。启用速度设置前，应分别验证系统 TTS 与录音播放的实际支持；不允许 UI 上速度已变化，声音却完全不变且没有提示。[S04][S10]

应用在一个设备选定的语音标识，不保证存在于另一设备。恢复时按语言与可用声音重新匹配；找不到时提示重新选择，不让无效设备 ID 阻塞其他设置恢复。

## 11. 用户文本导入、自动注音与编辑

### 11.1 首版入口与格式

支持手工输入、粘贴文本、导入 `.txt` 和导入本应用内容包。普通 TXT 首版支持 UTF-8、带 BOM 的 UTF-8、带 BOM 的 UTF-16；未识别编码时提示用户选择/转换，不静默生成乱码。

PDF、Word、图片 OCR 不属于首版文本导入范围。用户输入的文本始终按数据处理，不执行 HTML、JavaScript、模板指令或外部程序。

导入文件时通过文件流读取，并把需要长期使用的正文与音频复制到应用数据目录。不能把系统临时授权的文件路径保存下来后假定永久有效。[S06]

### 11.2 导入流程

```text
输入/选择文件
→ 读取和大小检查
→ 预览原文
→ 选择类型、标题、场景、难度、学段等可选信息
→ 根据上下文和词语数据生成拼音
→ 展示可校对的注音正文
→ 修改读音与分段（按需）
→ 添加日/英译文（可选，不自动要求联网）
→ 添加或录制音频（可选）
→ 保存到“我的内容”
```

保存时为内容分配稳定唯一 ID。中途取消不得生成一半可见、一半缺文件的内容；已有草稿应明确标识。发生错误时保留用户输入，不能让用户重新输入整篇文章。

### 11.3 自动注音原则

优先使用词语/短语上下文确定读音，再使用单字候选作为回退。例如“银行”“行走”“音乐”“快乐”等，需要通过各自语境处理多音字，而不是把每个字的第一读音直接拼接。词组匹配和多音字候选是现有拼音工具可提供的能力，但本项目仍须用自己的样例验证效果。[S11][S12][S13]

优先级建议为：**当前内容中的人工校正 → 已审核的上下文注音 → 离线词语词典 → 单字候选 → 未知标记。**

不要求算法对任意古文、人名、地名、多音字百分之百正确。要求是可发现问题、可修改、修改可保存、可分享、可恢复。需要复核的状态来自“多候选、未命中、特殊文本”等可解释条件，不能伪造一个看似精确的 AI 置信度。

显示规范默认采用字词本调注音。自然朗读中可能出现连读变调；特殊教材如需显示教学变调，应显式标注其注音模式，不应让同一词条在不同页面随意变换注音规则。

### 11.4 人工修改拼音

在编辑模式点击某个注音单元，可以选择候选读音或输入拼音。支持 `lǜ` 和 `lv4` 等输入，保存后统一显示带声调形式；不能把 `lv4` 直接当作学习页面的显示结果。

编辑器应验证拼音格式与声调，并允许处理词典未收录的有效读音；特殊儿化、罕见字音有明确的高级编辑或待复核状态，不能强制改成错误的常用音。

人工修改应保存来源、修改时间和锁定状态。再次运行自动注音时，默认保留已锁定校正；“全部重新生成”必须先预览会覆盖的修改并确认。

修改后的拼音应立即影响当前显示及该个人词条的搜索索引，不得等重启后才生效。

### 11.5 拼音校正与录音不是同一件事

**修改显示拼音，不代表系统 TTS 会自动按这个拼音改读。** MAUI 的系统朗读接口以文本和语音选项为输入，不能据此假设已具备跨平台、逐字自定义发音控制能力。[S04]

对于需要严格遵循人工校正的词语或片段，优先绑定核对后的录音。用户修改了影响读音的拼音时，相关音频标记为“需确认读音一致”，保留旧文件但不声称已重新生成正确语音。不得把拼音拉丁字母直接交给 TTS 后当作可靠普通话音源。

### 11.6 修改原文后的关联处理

正文改变时增加内容版本，重新分析受影响范围。未改变的正文片段尽量保留其稳定 ID、人工注音和音频引用；改变的片段必须重新校验，不能仅按“第几个字”继续套用旧拼音与旧录音。

片段被拆分或合并时，不自动宣称旧录音可以正确对应新片段。提示重新绑定或重新录制。只改标题、分类或译文时，不应使正文录音无故失效。

### 11.7 默认容量边界

首版建议将单篇正文上限设为 20,000 个文本元素，TXT 文件上限为 1 MiB；任一达到限制即给出明确说明。此为可调整的产品保护阈值，需在实际设备测试后确认，不是 MAUI 的硬性上限。

不得超限后静默截断。普通注音与导入在后台任务执行，UI 保持可响应；用户可取消。对长文采用分段/可视区域渲染优化，但**不能为了 UI 性能改变原始语义分段或丢失全文上下文**。

## 12. 朗读、录音、音频导入与分享

### 12.1 音频服务职责

音频逻辑不得散落在每个页面里。统一服务协调本地音频、系统 TTS、录音权限和播放状态。建议状态为：`Idle / Loading / Playing / Recording / Error`，必要时增加已支持的暂停状态。

每次播放具有会话 ID 或取消令牌。新任务开始时取消旧任务；旧任务的迟到回调不能清掉新任务的高亮或误触发下一段。全文朗读通过顺序等待每段完成来实现，不并发发起全部 TTS 请求。[S04]

### 12.2 音源选择顺序

先使用用户为当前内容/片段**明确选择**的音轨；未选择时优先经过核对的内置对应音频，个人内容可使用其绑定录音；没有适用音频时，再使用可用的系统普通话 TTS。

录制自己的跟读音频，不应默认覆盖内置标准示范音源。保存时提供“设为该段默认音频”的明确选项，个人内容默认勾选，内置内容默认不勾选。

拼音教学条目的示范音频遵循第 5 节要求，不使用普通 TTS 盲目回退。

### 12.3 离线能力必须分层验收

| 能力 | 离线要求 |
|---|---|
| 内置拼音表、预置正文、搜索、收藏 | 必须离线可用 |
| 自动注音和手动校正 | 首版必须离线可用 |
| 已内置、已导入或已录制的本地音频 | 必须离线可播放 |
| 任意新输入文本的合成朗读 | 取决于设备是否具备可用普通话语音；必须检测并实测 |
| 缺少本地中文语音时 | 保留全部阅读/编辑功能，提示配置语音或导入/录制音频 |

不能仅因为 `GetLocalesAsync()` 返回了中文，就宣称所有设备在飞行模式下都能朗读任意文本。系统 TTS 是对设备语音引擎的调用，本项目应对离线可用性做独立验证。[S04]

首版不主动调用云 TTS、翻译或 LLM 服务；使用系统语音时应向用户说明其行为可能受系统语音提供方设置影响。需要严格不出网的场景优先使用本地录音，并按平台验证所选语音确实为离线语音。

### 12.4 用户录音

操作流程为“选择整篇或当前片段 → 请求麦克风权限 → 开始录音 → 停止 → 试听 → 重录或保存 → 选择是否作为默认音轨”。不要求首版支持录音中暂停、降噪、剪辑或自动评分。

必须显示录音状态与时长，开始录音前停止当前播放。首次实际使用时才申请麦克风权限；拒绝后可以继续学习，不循环弹出权限请求。

进入后台、系统来电、设备音频中断时，按可验证的平台能力结束或中断录音，并尽量保存可恢复草稿；恢复前台后不得在用户不知情的情况下继续录音。不能只写一个空的异常处理来掩盖录音丢失。

### 12.5 音频文件导入

首版目标支持 MP3、M4A/AAC、WAV/PCM 这组经过三平台实测的常见组合。文件扩展名不能保证实际编码可播放；导入时检查文件可解码、时长、容量，并试听确认。[S10]

为降低首版编码兼容风险，可优先验证单声道 PCM WAV 录音。是否改用 AAC 等压缩格式，由实际平台能力验证决定，不能把任意文件改扩展名伪装成可播放文件。[S10]

默认单个音频文件上限 100 MiB，连续录音上限 20 分钟；达到任一阈值前提示，并安全停止到草稿。这些阈值应配置集中管理。导入失败不留下无效音频索引。

导入后由用户选择绑定“整篇”或“指定片段”，首版不做自动识别与音文对齐。

### 12.6 分享边界

提供两种分享：

| 方式 | 内容 | 接收方体验 |
|---|---|---|
| 分享音频 | 一条用户选择的音频文件 | 可由系统支持的音频播放器打开 |
| 分享学习内容包 | 指定正文、注音、人工修改、可选译文、选中的音频与来源信息 | 安装本应用后导入并学习 |

内容分享不包含个人设置、搜索历史、未选择的收藏夹或其他录音。分享前预览包含的内容和文件大小，提醒录音可能包含个人声音信息。

首版“分享”指使用系统分享面板或另存文件，不指上传社区，也不需要后台、账户体系或好友关系。MAUI 的 Share 可调起系统分享能力，但接收目标由平台及已安装应用决定，不保证每台设备都有相同分享应用。[S07]

## 13. 备份、恢复与离线迁移

### 13.1 两种包，解决两种问题

| 类型 | 暂定扩展名 | 用途 | 默认内容 |
|---|---|---|---|
| 完整备份包 | `.hanbackup` | 自己换设备、重装恢复 | 设置、收藏夹、收藏关系、全部个人正文、注音校正、用户音频、必要内容快照 |
| 学习内容包 | `.hanpack` | 分享选中的学习材料 | 选定正文、拼音、译文、所选音频、来源信息；不含个人设置 |

扩展名随最终品牌可调整；内部 `packageType` 才是包类型判断依据，不只依靠文件名。无法选择自定义扩展名的平台可提供 `.zip` 保存/导入回退，仍必须读取清单校验类型。

原需求“设置和收藏夹导出到一个文件”已包含在完整备份中。因为增加了个人正文与录音，默认还必须备份这些关联数据，否则收藏迁移后可能无法使用。

### 13.2 备份内容边界

完整备份包含可迁移的用户设置、用户创建的全部收藏夹与关系、全部个人内容及其注音校正、用户导入/录制音频，以及已收藏内置内容的必要文本与注音快照。

内置公共内容和随应用分发的原始音频可按内容版本引用，不要求每份备份重复整个安装包。目标应用找不到所引用的内置内容时，利用快照恢复阅读；缺失内置音频则明确提示，不宣称快照本身包含不存在的音频。

用户音频默认完整携带。若以后增加“不含音频”的轻量备份选项，导出和导入界面均必须标明缺少哪些能力，不能仍然把它描述为完整迁移。

不备份缓存、临时文件、麦克风授权结果、设备绝对路径、设备专属硬件标识。搜索历史和阅读进度若实施，默认不含在内容分享包里；是否纳入完整备份应有明确设置。

### 13.3 推荐文件结构

```text
sample.hanbackup   # 实际为 ZIP 容器
├── manifest.json
├── settings.json
├── collections.json
├── contents.json
└── audio/
    ├── index.json
    ├── <audio-id-1>.wav
    └── <audio-id-2>.m4a
```

拼音与人工修改状态随正文注音结构保存在 `contents.json`，避免同时存在两套彼此冲突的拼音主数据。分享包不包含 `settings.json` 和 `collections.json`。

`manifest.json` 至少包含以下字段：

| 字段 | 说明 |
|---|---|
| packageType | `backup` 或 `content` |
| schemaVersion | 包结构版本，用于判断读取兼容性 |
| packageId | 本次导出的唯一标识 |
| createdAtUtc | UTC ISO 8601 时间 |
| producerAppVersion | 导出应用版本，仅作为来源信息 |
| contentCatalogVersion | 内置内容版本，可空 |
| counts | 内容、收藏夹、音频等数量 |
| files | 每个数据/音频文件的相对路径、实际字节数与 SHA-256 |
| warnings | 未包含音频、缺译文或其他已知不完整项 |

`files` 校验列表不包含 `manifest.json` 自身，避免清单自引用校验。

### 13.4 导出一致性

导出基于一致的数据库快照，读取不可变的正式音频文件；不能在录音仍写入文件时直接把它当完整音频打包。正在录音时提示先停止，或明确排除未完成草稿。

先写入临时导出文件，完成清单和校验后，再交给系统保存/分享。保存取消不是“导出成功”，不得提前显示成功提示。不得把正在写入的 SQLite 主文件直接复制到 ZIP 后声称已经可靠备份。

### 13.5 导入与恢复流程

```text
选择文件
→ 读取并验证清单、类型与版本
→ 检查文件规模、路径和校验值
→ 预览将导入的数量与警告
→ 选择合并或完整恢复
→ 处理内容/收藏夹冲突
→ 暂存并校验音频
→ 数据库事务写入
→ 提交后刷新设置、列表和搜索索引
→ 清理临时文件，显示结果与未恢复项
```

默认使用“合并导入”。“替换当前用户数据”只对完整备份开放，必须二次确认，并先生成可恢复的本地安全备份；预备份失败时不得继续破坏性恢复。导入分享包不得覆盖用户全局设置。

合并导入默认保留本机设置，预览页可明确勾选“应用备份中的设置”；尚未建立个人数据的新安装可默认勾选。完整替换恢复按备份还原可迁移设置，设备专属语音按第 10 节重新匹配。不能在合并收藏时悄悄改变用户已经选好的语言。

### 13.6 冲突策略

| 冲突 | 默认行为 |
|---|---|
| 同一包再次导入且内容完全相同 | 幂等处理，不制造重复条目 |
| 同一内容 ID、同一正文与注音版本 | 复用已有内容，合并必要引用 |
| 同一内容 ID 但正文/注音不同 | 保留双方，为导入版本创建新 ID，并同步重映射收藏与音频引用 |
| 收藏夹 ID 相同、内容相同 | 合并成员并去重 |
| 系统默认收藏夹 | 通过固定系统角色标识映射到本机唯一默认夹，不按不同语言的显示名称重复创建 |
| 名称相同但收藏夹 ID 不同 | 默认保留双方，导入夹附加“导入”等名称后缀；可让用户显式选择合并 |
| 音频文件哈希相同 | 可复用物理文件，但保留正确的逻辑关联 |
| 内置内容版本不同 | 按稳定来源 ID 对应，必要时采用快照；不把用户版本写回内置数据包 |

不得仅凭设备时间较新就覆盖人工校正，因为不同设备的时钟可能不同。包导入记录、原始 ID 与派生 ID 的映射应持久化，确保同一冲突包再次导入时不会重复派生。

### 13.7 安全与失败恢复

所有输入文件都按不可信数据处理。拒绝 `../`、绝对路径、逃逸目标目录的路径、重复歧义路径、符号链接及不允许的文件类型。路径校验必须考虑 Windows 大小写和路径分隔符差异。

建议初始保护阈值为：压缩包 512 MiB、解压后总量 1 GiB、最多 10,000 个条目，并对单文件、JSON 深度及字符串长度设置限制。这些是初版可调整阈值，必须在解压/读取流中累积计量，而不是完全相信 ZIP 头部声明。

校验缺失文件、哈希不符、未知的不兼容 `schemaVersion` 时，必须在修改用户数据之前停止。SHA-256 只用于检查一致性，不证明文件来自可信作者，也不等于数字签名。

数据库和文件系统不是一个共同事务。推荐先把已校验音频写为不可变新文件，再在数据库事务中提交引用；失败时旧引用不变，新产生孤立文件在回滚/启动恢复时清理。应有操作日志或恢复标记，处理进程意外退出。

首版导出包默认不加密，导出前明确告知它可能包含个人正文和声音；密码加密是独立后续需求，不能暗示 ZIP 后缀本身提供保密能力。

## 14. 数据模型与关键不变量

本节规定数据契约，不要求照着名字机械生成所有类。具体实现可以简化，但不能丢失字音对应、稳定引用、版本和备份能力。

### 14.1 核心实体

| 实体 | 主要字段与职责 |
|---|---|
| LearningContent | `id`、`kind`、标题、正文、来源、版本、难度、场景、学段/年级、创建/修改时间 |
| ContentSegment | 稳定 `id`、所属内容、正文范围、顺序、段落/诗行信息、译文、播放边界 |
| AnnotatedToken | 稳定 `id`、原文范围、文本、类型、拼音信息、修改来源与锁定状态 |
| PinyinSyllable | 无调拼写、声调、儿化标记、显示拼音、候选读音、审核状态 |
| WordSense / WordEntry | 词条/义项 ID、词语、读音、词义、例句关联；允许同字不同音义 |
| Translation | 内容或片段 ID、语言 `ja/en`、译文、来源与审核状态 |
| PinyinItem | 教学分组、显示拼写、示范音频引用、四声例词与高亮范围 |
| AudioAsset | 音频 ID、相对路径、文件哈希、编码、时长、来源、大小 |
| AudioBinding | 音频与内容/片段的关联、适用正文哈希、注音版本、默认音轨标记、需复核状态 |
| FavoriteFolder | 稳定 ID、名称、说明、排序、是否系统默认夹 |
| FavoriteItem | 收藏夹 ID、内容 ID、可选义项 ID、排序、加入时间 |
| UserSettings | UI 语言、阅读偏好、可迁移音频偏好等 |
| ImportRecord | 包 ID、导入结果、原 ID 到本地 ID 映射，用于幂等和冲突追踪 |

生产数据 ID 使用稳定 UUID 或等价的全局唯一标识。不能用标题、正文文本或数据库行号作为跨设备稳定身份。下面的样例为便于阅读使用缩写 ID，不作为生产 ID 生成方式。

### 14.2 注音不能只存一整串字符串

不采用以下结构作为唯一主数据：

```json
{
  "text": "你好！欢迎。",
  "pinyin": "nǐ hǎo huān yíng"
}
```

它没有说明标点、换行、人工修改、范围或片段音频如何关联。

推荐使用“正文 + 稳定片段 + 注音单元”的结构，例如以下最小测试样例：

```json
{
  "schemaVersion": 1,
  "id": "content-demo-001",
  "kind": "text",
  "title": "注音显示测试",
  "text": "你好！欢迎。",
  "contentRevision": 1,
  "annotationRevision": 1,
  "offsetUnit": "textElement",

    "type": "testFixture",

    },
    {
      "id": "segment-002",
      "start": 3,
      "length": 3,
      "text": "欢迎。",
      "translations": { "ja": "ようこそ。", "en": "Welcome." },
      "tokenIds": ["token-004", "token-005", "token-006"]
    }
  ],
  "tokens": [
    {
      "id": "token-001", "start": 0, "length": 1,
      "text": "你", "kind": "hanzi",
      "pinyin": { "base": "ni", "tone": 3, "erhua": false, "display": "nǐ" },
      "annotationSource": "phraseDictionary", "locked": false
    },
    {
      "id": "token-002", "start": 1, "length": 1,

    },
    {

      "text": "欢", "kind": "hanzi",
      "pinyin": { "base": "huan", "tone": 1, "erhua": false, "display": "huān" },

    {
      "id": "token-005", "start": 4, "length": 1,
```

本例只是验证数据结构、对齐、分段和译文选择，不代表正式收录课文或已审核翻译。

### 14.3 字符与范围约定

正文原样保存，保留标点与换行。范围统一使用保存正文的“文本元素”索引；UI、编辑、导出、恢复使用同一规则。在 .NET 中可使用 `StringInfo` 等文本元素处理能力，不能把 UTF-16 `char` 数量直接等同于可见字符数量。[S15]

特别注意：`StringInfo.ParseCombiningCharacters` 返回的是各文本元素起点的 UTF-16 偏移，不是“第几个文本元素”的序号。实现时维护序号与 UTF-16 偏移的映射，不能混用两套位置单位。[S15]

拼音显示字符串统一使用 NFC 规范化形式，无调 `base` 保留 `ü`，声调独立保存。转换测试至少包含 `ni3 → nǐ`、`liu2 → liú`、`gui4 → guì`、`lv4 → lǜ` 和轻声，不能统一把调号放在最后一个字符上。

为降低跨版本分段算法差异风险，序列化注音单元本身及其原文，并在导入时验证范围与原文一致；不能仅保存整数偏移后毫无验证地重新计算。标题修改不影响正文范围。

常规汉字按一字一注音单元排版；标点、空白、数字、英文、Emoji 不强行生成拼音。儿化等特殊情况允许一个注音单元覆盖相邻多个汉字，例如同一单元表示“花儿”并显示 `huār`，避免为满足一对一而造出错误发音。[S14]

生僻字无法识别时保留字形并标记“读音待确认”。用户导入繁体或其他文字时保留原文，不自动改成简体；支持保留不等于保证全部字形均能正确注音。

### 14.4 必须验证的不变量

| 不变量 | 检查方式 |
|---|---|
| 注音与正文对应 | token 的范围、保存文本与正文实际切片完全一致 |
| 分段不丢字符 | 片段及分隔信息连接后还原正文 |
| 显示拼音一致 | `base + tone + erhua` 与 `display` 对应；导入时校验 |
| 轻声与未知区分 | 轻声 `tone=0`，未知为 `null`，标点 `pinyin=null` |
| 收藏不重复 | `(folderId, contentId, senseId)` 唯一；空义项也须正确归一化 |
| 人工校正不丢失 | 自动重新注音不覆盖锁定项，导出恢复后保持一致 |
| 音频不串段 | 音频关联到稳定片段及适用正文版本，不只靠数组下标 |
| 备份可跨设备 | 所有文件使用相对路径；不依赖原设备数据库行号 |
| 内容与注音独立修订 | 原文变化与注音变化分别记录，触发适当复核 |
| 派生索引可重建 | 搜索字段和缓存不是唯一主数据，恢复后可安全重建 |

`display`、片段 `text` 等冗余字段用于校验或快速显示，必须由主数据推导/校验；出现不一致时不能随机挑一个当正确值。

### 14.5 本地数据持久化

推荐一份 SQLite 管理用户数据，内置资料按只读内容包或独立表管理，二者在仓储层合并查询。不要为了首版过早引入双数据库同步框架。[S09]

所有可迁移用户设置也以数据库为主数据源；如使用 Preferences 加速启动，它只是可重建缓存。恢复备份后重新加载设置，避免数据库恢复成功但 Preferences 仍保留旧值。

数据库迁移必须有版本号、测试与失败保护。升级不能直接删除旧数据库重建，以此“解决”数据结构变化。

## 15. 内容质量、来源与隐私

### 15.1 内容与代码分开治理

程序能显示一个词条，不代表词条的拼音、翻译、例句和音频已经正确。内置正式发布数据需要有清单、来源与审核状态，至少分别检查正文、拼音、翻译、音频一致性。

建议内置内容流程为：

```text
合法来源/原创草稿
→ 整理场景与级别
→ 注音与多音字校对
→ 日/英译文校对
→ 音频制作或授权导入
→ 文本与音频一致性检查
→ 发布内容包
```

AI 可以协助起草，但不能虚构“人工审核人”“真人录音”或“官方教材认证”。缺少素材时，保留草稿与缺失清单，不用空文件、静音文件或无关素材冒充完成。

### 15.2 来源字段

每个分发内容至少记录来源类型、作者/提供方、来源地址或内部来源编号、许可说明、使用范围与审核状态。文本、现代译文、注释、音频和字体分别管理来源，不因为其中一项可用，就推断其他部分也可任意分发。

选用开源字音/词语数据时，应核对具体文件的上游来源与许可，而不是只看到仓库许可证就忽略所合并的数据来源。[S11][S12]

本文不替代针对具体教材、录音和发行地区的授权审核。首版不以批量抓取商业教材和现成有声材料作为默认内容来源。

### 15.3 隐私基线

应用不主动把正文、收藏、搜索和录音上传至自己的服务器或第三方 AI 服务。录音仅在用户主动操作时申请权限、显示状态，分享必须由用户明确发起。

日志默认不包含全文、完整录音路径、录音数据和个人译文。诊断信息可记录错误代码、操作类型、耗时与不含隐私的统计。

“应用不主动上传”不等于可以忽略操作系统自身的备份、系统语音提供方或用户选用的分享应用。说明这些行为由对应系统/服务设置影响，不作无法验证的绝对承诺。

## 17. 推荐架构与开工验证

### 17.1 小而清晰的工程结构

```text
HanMate/
├── HanMate.sln
├── global.json
├── src/
│   ├── HanMate.App/                 # MAUI 页面、控件、ViewModel、平台适配
│   │   ├── Views/
│   │   ├── ViewModels/
│   │   ├── Controls/                # 注音排版、四声例词等复用控件
│   │   ├── Services/                # 本地化、音频、文件 UI 适配
│   │   ├── Resources/
│   │   │   ├── Localization/
│   │   │   └── Raw/                 # 有来源说明的内置内容与音频
│   │   └── Platforms/
│   ├── HanMate.Core/                # 纯 .NET：数据契约、拼音/搜索/分段规则
│   └── HanMate.Infrastructure/      # SQLite、内容读取、备份包与文件存储
├── tests/
│   ├── HanMate.Core.Tests/
│   └── HanMate.Infrastructure.Tests/
├── tools/                          # 可选：数据校验、离线内容包构建脚本
└── docs/
    ├── requirements.md            # 本文件
    ├── progress.md                # 当前阶段、真实进度、下一步
    ├── decisions.md               # 技术与产品决策及原因
    ├── test-matrix.md             # 平台与用例结果
    ├── data-format.md             # 固化后的数据/备份格式
    ├── content-sources.md         # 来源、许可、内容审核清单
    └── build-and-run.md           # 版本、环境、实际构建命令
```

依赖方向为 `App → Core / Infrastructure`、`Infrastructure → Core`，Core 不引用 MAUI，方便独立测试。与麦克风、TTS、系统文件窗口有关的实现放在 App/平台适配层，不让纯数据项目依赖平台 UI。

无需增加微服务、消息总线、插件市场或泛化到任何语言的复杂框架。现有代码规模较小时可以合并 Infrastructure，但核心规则仍须能脱离页面测试。

### 17.2 服务边界建议

| 服务 | 职责 | 不应承担 |
|---|---|---|
| IPinyinService | 注音、候选、人工覆盖、拼音格式转换 | UI 弹窗、直接播放声音 |
| IReadingSegmenter | 保留原文的句段划分与范围 | 把句段翻译或擅自改写 |
| IAudioService | 播放/TTS/录音协调、取消、状态 | 修改正文和收藏 |
| IContentRepository | 内容与版本读写、稳定引用 | 把教学内容切换成 UI 语言 |
| ISearchService | 汉字/拼音归一化、索引查询和排序 | 默认接入网络或向量数据库 |
| IFavoriteRepository | 收藏夹与关联关系维护 | 删除正文和原始录音 |
| IPackageTransferService | 包验证、导出、冲突映射、事务恢复 | 自行打开系统权限窗口 |
| ILocalizationService | UI 语言切换、译文选择、状态通知 | 修改正文的中文内容 |

以上名称为架构建议，实际签名由实现确定。AI 不应把它们误认为某个现成 NuGet 包已经提供的 API。

### 17.3 必须先验证的高风险点

| 验证项 | 最小验证内容 | 通过证据 |
|---|---|---|
| 三平台构建链 | 确认 SDK/依赖版本并构建最小应用 | 实际构建结果和运行环境 |
| 注音排版 | 中英文混排、标点、换行、长拼音、200% 字号、长文 | 三平台截图/交互记录 |
| 拼音引擎 | 词组、多音字、轻声、ü、人工锁定、离线 | 自动化样例结果 |
| 音频与录音 | 中文 TTS、本地播放、录音权限、实际录音文件、取消 | 真机试听与输出文件检查 |
| 文件与备份 | 选 TXT、保存 ZIP、自定义后缀回退、系统分享 | 至少一个完整保存→导入往返 |

先验证上述风险，再扩大页面和内容数量。某平台缺少构建机或真机时，将该项标为 `BLOCKED/NOT RUN`，继续能开展的独立开发；但不能因此在交付说明里写“三平台全部完成”。

## 18. AI 分阶段实施与交付要求

### 18.1 阶段划分

| 阶段 | 目标 | 交付物与通过条件 |
|---|---|---|
| M0 技术验证 | 完成第 17.3 节，选定版本与关键组件 | 可运行验证项目；环境清单；风险和未验证项；不先做整套精美空页面 |
| M1 基础与数据链 | 五入口、三语言、SQLite、内容契约、最小注音控件 | 至少 12 个真实测试词条、1 篇短课文、1 首来源明确的诗词；页面经真实仓储读取；基本重启持久化 |
| M2 完整学习闭环 | 拼音、四声例词、词语详情、课文/诗词阅读、搜索、收藏 | 点击朗读/分段停止正确；对应 A01—A20 用例有执行结果；不是占位按钮 |
| M3 个人资料与音频 | 文本输入/TXT 导入、自动注音、校正、录音与音频导入 | 导入→校正→保存→重启→播放完整走通；对应 A21—A30 用例执行 |
| M4 分享与迁移 | 内容包分享、完整备份、合并/替换恢复、故障保护 | 正文/拼音/收藏/用户音频完整往返；冲突、重复导入和失败恢复有测试 |
| M5 三平台交付整理 | 性能、访问性、权限、内容审核、发布构建说明 | 所有 P0 用例状态明确；三平台实测；完成内容清单；不存在被伪装成已完成的缺音频/缺功能 |

这些阶段是同一个首版的内部开发顺序。不能在 M2 后把用户导入、录音、分享和迁移自动改成“未来版本再做”。

### 18.2 每个阶段都要提供什么

阶段结束时提供可以运行的代码、实际构建/测试命令及结果、已完成需求 ID、未完成/阻塞项和复现信息。更新 `progress.md`、`test-matrix.md`，涉及数据格式或架构变化时同步更新对应文档。

“已实现”意味着正常路径和关键异常路径都有真实逻辑；“已测试”意味着实际执行并留下结果。只画出 UI、调用模拟服务或写一条 TODO，都不算完成对应功能。

```markdown

- 当前代码版本/提交：
- 本阶段目标：

|---|---|---|---|
```

### 18.4 禁止的开发方式

| 禁止行为 | 正确替代 |
|---|---|
| 一次性生成大量页面，全部绑定硬编码假数据 | 先做一条从持久化数据到 UI 的完整功能链 |
| 为了测试通过而删除失败用例或降低核心要求 | 修复实现，保留失败记录，必要时提出明确变更 |
| 把正文、拼音和 UI 翻译放在同一套语言资源里 | 分离 UI 与教学内容、译文数据 |
| 声称 TTS 自动尊重手工拼音 | 验证实际能力，必要时使用匹配录音 |
| 导出时只存收藏标题和原设备路径 | 存稳定引用、快照、相对音频文件及版本 |
| 未验证第三方 API 就编造调用代码 | 查对应版本的官方文档/源码并实际编译 |
| 吞掉所有异常，让用户看起来“成功了” | 返回真实错误，保持旧数据，说明可恢复步骤 |
| 没有 iOS 环境仍声称 iOS 测试通过 | 清晰标注未运行，提供构建步骤和所需环境 |
| 无授权删除用户资料、清库、强制恢复或重置仓库 | 做备份和确认，使用可回滚的小范围变更 |
| 自动接入收费云服务、上传用户文本和录音 | 首版按离线方案实现，新增服务需单独批准 |

应用内置内容默认只读。用户需要修改内置正文/拼音时，可复制为个人版本再编辑；个人录音和收藏作为用户层数据保存，不直接改动发布内容包。

### 18.5 完成定义

首版完成必须同时满足：原始 R01—R16 全部有落地实现；P0 功能没有空实现；关键逻辑有自动化测试；三个目标平台的验证状态真实清楚；备份恢复不丢失用户校正和录音；正式内置内容具有可追溯来源；构建说明可复现。

环境或素材仍有阻塞时，应交付已完成部分和明确缺口，但不能把未完成项隐藏为“已完成”。
