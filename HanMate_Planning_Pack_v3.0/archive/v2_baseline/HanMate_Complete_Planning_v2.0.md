## 00 · 项目总体规划

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 这个项目要做成什么

一个离线优先的中文学习与个人资料工具，使用 .NET MAUI，面向 iOS、Android、Windows。五个固定主入口为：**拼音、学习、搜索、收藏、设置**。学习内容包含词语、课文、诗词；用户可以导入自己的文本、校正拼音、录音或导入音频，再通过文件分享和迁移。

“离线优先”在本项目中的含义是：内容、索引、注音词典和用户资料保存在本地；核心学习与编辑不依赖应用服务器。系统 TTS 是否能离线合成新文本必须按设备验证，不把它当成无条件保证。

产品不要求用户登录，不以云 AI 作为自动注音的前置条件，不因 Windows 使用场景而取消移动端设计，也不因移动端优先而遗漏 Windows 鼠标和键盘操作。

### 2. 核心价值和完成标准

| 价值 | 必须能展示的实际行为 | 不能冒充完成的做法 |
|---|---|---|
| 学得清楚 | 汉字与带调拼音对齐；可选当前 UI 语言译文 | 两行文字靠空格对齐 |
| 听得可控 | 点击音源明确；课文只读所点片段；随时停止 | 快速点击叠音；长音频假装已逐段对齐 |
| 内容可改 | 多音字可改、可锁定；改原文后校正不串字 | 只改画面、不落盘 |
| 资料可留 | 收藏、个人文本、注音、录音重启后存在 | 数据只放在 ViewModel 内存里 |
| 换机可用 | 备份后在另一平台恢复关联数据 | 只导出收藏标题和原设备路径 |

软件完成与内容完成分开验收：程序工作不等于示范音频、拼音、翻译已审核；内容准备完毕也不等于程序能可靠恢复。

### 3. 三类决策

**U：用户明确要求。** R01—R16 全部属于首个完整版本的验收范围。文本导入、人工改音、录音、分享、迁移不能被开发 AI 自行降为第二版。

**D：本包提供的默认方案。** 包括五入口命名、TXT 格式、容量、100 个词条的初始内容目标、包协议、交互细节和技术分层。可以修改，但必须更新 ADR、关联文档和测试。

**V：需要实际验证的事项。** SDK 与依赖精确版本、最低系统版本、音频编码、语音离线可用性、20,000 文本元素的排版性能。不得把 V 写成已验证的事实。

完整决策登记见 [决策记录](#doc-26)。

### 4. 首版边界

| 范围 | 首版包含 | 不默认包含 |
|---|---|---|
| 学习 | 拼音表、四声例词、词语/例句、课文、诗词 | 考试题库、语音评分、智能导师 |
| 内容组织 | 场景、难度、学段/年级、来源 | 宣称某教材全覆盖 |
| 个人内容 | 输入/粘贴/TXT、注音、校正、译文手填 | PDF、Word、OCR、自动翻译 |
| 音频 | 播放、TTS 回退、录音、导入、整篇/片段绑定 | 自动音文对齐、剪辑台、后台连续播放 |
| 数据 | 搜索、收藏、备份、合并/替换恢复、内容包 | 登录、云同步、在线社区、支付 |

本地资料不是无限大。容量与性能阈值是保护性默认值，不是框架极限；见 [性能规划](#doc-20) 与 `specs/limits.json`。

### 5. 用户旅程与首版闭环

```text
第一次启动 → 选择/匹配界面语言 → 看拼音与试听
→ 按场景学习词语 → 查陌生词 → 收藏
→ 阅读课文/诗词并点段朗读
→ 导入自己的文本 → 修改读音 → 配上自己的录音
→ 分享选中资料 → 导出完整备份 → 在另一设备恢复
```

每个阶段都必须使用实际仓储数据；可以使用明确标为测试素材的小样本，但不得把随机生成的“知识”“真人录音”作为正式教学内容。

### 6. 六个实施阶段

| 阶段 | 工作重心 | 放行条件 |
|---|---|---|
| M0 技术验证 | 三平台环境、注音控件、离线注音、真实录音、文件往返 | 五项风险有证据；无法验证的平台明确 BLOCKED |
| M1 数据基础 | 工程、三语言、五入口、数据库、样例数据 | 数据贯通且重启持久；12 词、1 短文、1 诗词样例可访问 |
| M2 学习闭环 | 拼音、词句、阅读器、搜索、收藏 | 正常与关键异常流程通过对应测试 |
| M3 个人资料 | 文本导入、注音修改、录音、音频导入 | 保存—重启—再次编辑—播放闭环 |
| M4 分享迁移 | 协议、分享、备份、恢复、冲突和崩溃恢复 | 数据往返一致；错误包不破坏旧数据 |
| M5 发布准备 | 三平台 Release、性能、无障碍、内容审核 | 所有 P0 有结果；没有隐藏的占位能力 |

详细任务包见 [实施任务](#doc-21)。阶段不是日历承诺；先关闭实际风险，再安排人力和日期。

### 7. 资源和责任

开发 AI 负责实现、自动化测试、问题复现、文档更新；产品负责人决定范围变更与默认交互；中文教学校对者负责正文/读音；日英校对者负责译文；音频提供者负责素材及来源；设备验证者执行真实平台测试。同一个人可兼任，但不允许 AI 虚构某个角色已经完成审核。

开工所需资源包括可用 Windows 开发机、iOS 的 Mac/Xcode 构建环境、Android 与 iOS 测试设备或模拟器、Windows 测试环境，以及合法可用的内容与音频。iOS 构建要求以平台官方说明和所选发布版本为准。[S02，见来源文档](#doc-27)

### 8. 质量门禁

功能门：R01—R16 逐项有实现位置、测试、证据。数据门：用户校正与音频无损迁移，恢复失败不损坏旧数据。平台门：三个目标分别给出真实结果。内容门：正式发布项有来源和审核记录。安全门：未授权录音、隐性上传、路径逃逸、破坏性恢复等问题为发布阻断。

未做的事允许写 NOT RUN；有缺陷必须写 FAIL；只有实际执行达到期望才能写 PASS。没有做过用户调研、真机测试或许可证审核时，不使用“已验证”“完全兼容”“可直接商用”这些结论。

### 9. 文档使用与变更顺序

阅读顺序：本文件 → PRD → 相关模块 → 数据/包契约 → 测试 → 实施任务。AI 执行先读根目录 `AGENTS.md` 与 `tracking/STATUS.md`，不用每次把所有文档塞进一次模型上下文。

优先级：用户明确新指令 > R01—R16 > 已接受 ADR > 模块规则与契约 > 页面示例与样例数据。发现同级文档冲突时记录问题并选择不损坏用户数据的保守行为，不能通过静默改需求来消除冲突。

文档 v2.0、应用版本、数据库版本、内容包版本四者独立。当前仅交付规划、契约草案与验证样例，**没有交付或验证 MAUI 应用实现**。

### 3. 具体功能要求

#### F-PY 拼音学习

页面包含声母、拼写辅助项、韵母、整体认读音节等教学分组。分类清单是教学编排，不冒充完整音系清单。点击示范；长按显示四声例词弹层；Windows 支持右键或“示例”按钮和键盘路径。没有合适真实例词的某一声保留行位并说明缺失，不编造例词。

标红定位到例词注音 token 及其拼音范围；不是全局文字替换。声母通过包含该声母的真实音节示例讲解，不给孤立声母强加四种声调。

#### F-LEARN 学习内容

词语、课文、诗词三种类型与“内置/我的”来源独立。场景可多选；难度为入门/基础/进阶/高级/未标注；学段和年级可空。同维度 OR，跨维度 AND。列表保留筛选与滚动位置。

词语详情显示当前音义项；同样汉字但音义不同可为不同内容 ID，不使用汉字字符串当唯一主键。例句有独立文本单元和音源。课文与诗词保留分行，提供点段、放大阅读和全文朗读。

#### F-SEARCH 搜索

首版查已收录词语和个人词条，不声称是包含所有汉字词语的完整词典。支持汉字、空格/连续无调拼音、带调、数字声调、ü 别名和隔音符号。输入防抖 250 ms，回车立即提交，旧结果不能覆盖新查询。未收录不生成词义。

#### F-MINE 个人内容

支持输入、粘贴、UTF-8 和带 BOM 的 UTF-16 TXT。默认不支持自动翻译、文档 OCR、音文自动对齐。文本修改采用版本与差异预览；不按数组位置把旧校正/音频强套到新字上。内置正文需先复制为个人版本再改。

#### F-AUDIO 音频

播放/TTS/录音由统一协调器管理。页面退出、进入后台等按规则停止；不隐蔽录音。拼音表依赖专用教学示范，不用英语字母朗读顶替。普通正文没有录音时可尝试系统普通话 TTS；无法可靠离线时提示而不伪装可用。

只有整篇音频时，不自动拥有单段音频。用户修改拼音后，旧音频可能需要复核，不能宣称 TTS 已跟随改音。用户对内置内容录制的跟读音轨默认不覆盖标准示范。

#### F-DATA 收藏、分享与迁移

同一内容可属于多个收藏夹；同夹不可重复。收藏夹删除与内容删除分开。内容分享只导出选中内容与选中音轨，不带设置和私人收藏；完整备份包含所有已保存个人内容、录音和收藏依赖快照，不包含临时录音或未保存草稿，草稿存在时必须提示先保存。

导入先校验再预览再提交。合并默认保留本机设置和冲突双方；替换恢复二次确认并先生成安全备份。相同包重复导入不重复派生数据。协议和具体冲突规则以文档 14、15 为准。

### 4. 全局业务不变量

正文与教学拼音不受 UI 语言影响；原文范围、显示文字与注音必须一致；轻声不是未知音；所有跨设备引用使用稳定 ID；已保存人工校正优先于自动算法；同一时间一个音频任务；导入失败旧数据可用；任何未审核素材不得假装正式发布。

改变正文、读音、译文、分类对音频和搜索的影响不同。必须实施模块文档的失效矩阵，不以“一改就全清”“一改就全保留”代替。

### 5. 首版内容目标与非功能指标

默认发布目标：100 个词条、6 篇短文、6 首诗词，词条原则上两条例句；拼音表完整教学清单和示范音频另计。此数量是建议，可按内容校对资源调整，不等于用户已确认的收录数量。

搜索目标为 10,000 测试词条、引擎查询 P95 ≤ 200 ms，不含防抖；长文目标为 20,000 文本元素仍可打开、滚动与编辑。三平台 200% 字体缩放、键盘操作、权限拒绝、坏包和进程中断都要覆盖。所有数值是待测目标，不是已测成绩。

### 6. 明确不在首版

账户、服务器、收费服务、云同步、排行榜、社区、自动发音评分、语音识别、AI 聊天、自动机器翻译、PDF/Word/OCR、自动音文时间轴、背词算法、教学进度分析不默认实现。保留扩展点即可，不提前建立复杂平台。

### 7. 边界和变更

原需求中的“编译收藏夹”按“编辑收藏夹”理解。原有页面重复编号统一为五个主入口。学段不是成人学习难度的自动映射。“中文界面不显示译文”不隐藏必要中文 UI 说明、中文释义或作者信息。

新需求记录变更原因、影响需求 ID、数据兼容风险、需要新增的测试和阶段；未经同意不得将“全面优化”解释为扩大范围或自动接入联网服务。

## 02 · 用户流程与导航规则

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 页面和路由登记

路由字符串为项目约定，不代表 MAUI 已经提供这些页面。路由参数只传稳定 ID 和简单显示模式；内容对象从仓储重新获取。

| 页面 ID | 路由建议 | 入口 | 返回目标 |
|---|---|---|---|
| P01 | `//pinyin` | 主导航 | 主入口，无重复堆栈 |
| P02 | `//learn` | 主导航 | 保留类型、筛选与滚动 |
| P03 | `//search` | 主导航 | 保留查询和滚动 |
| P04 | `//favorites` | 主导航 | 保留所选收藏夹 |
| P05 | `//settings` | 主导航 | 保留当前设置位置 |
| P06 | `word?id={id}` | 学习、搜索、收藏 | 回到真实来源页面 |
| P07 | `reader?id={id}` | 学习、收藏 | 回到真实来源页面 |
| P08 | `editor?id={id?}` | 新建、导入、个人内容菜单 | 保存后详情；取消回原来源 |
| P09 | `audio?targetId={id}` | 详情或编辑器音频管理 | 原详情/编辑草稿 |
| P10 | `folder?id={id}` | 收藏夹列表 | 收藏主入口 |
| P11 | `transfer?kind={backup|content}` | 分享、设置 | 操作完成后原页面 |

四声、放大阅读、收藏选择、拼音修改是弹层，不产生新的主导航。弹层自身必须有标题、关闭路径、焦点恢复和取消语义。

### 2. 首次使用

首次启动依次完成数据库迁移、内置内容校验/安装和语言解析。失败时显示可恢复错误页，不让用户进入缺表页面。首次语言规则：系统 `zh-*` → `zh-Hans`，`ja-*` → `ja`，其他 → `en`；设置页可立即更改。

默认直接进入拼音页，可用一句提示介绍点击和长按，但不强制观看多页引导。没有网络、没有麦克风权限、没有中文 TTS 都不阻止进入阅读和搜索。默认收藏夹创建由数据库唯一系统角色保证，不由每次进入页面创建。

### 3. 学习和收藏流程

```text
学习列表 → 选择类型与分类 → 点击内容正文 → 详情
                                      ├→ 点击音频按钮：仅播放
                                      └→ 点击收藏：选择一个或多个收藏夹 → 保存
```

收藏弹层的选择是一次批量提交。关闭/取消不提交临时勾选。未收藏时默认选最近使用夹；已收藏时勾选真实现有集合。移除全部需要用户点击“保存”确认，不用单次星形按钮点击悄悄移除所有夹。

收藏夹名称失效、内容已删除、保存时数据库忙等均保留当前选择，显示原因，可重试。若内容在页面打开后被删除，提交返回 `CONTENT_NOT_FOUND`，不生成悬空引用。

### 4. 阅读流程

点击正文片段 → 标记选中 → 打开/更新同一个放大弹层 → 取消旧播放 → 朗读当前片段 → 到片段末尾停止。再次点击相同正在播放的片段停止；点击其他片段替换当前播放。

弹层上一段/下一段只切换内容和选中状态，默认不自动发声。全文朗读是独立按钮；用户点段、关闭关联弹层、退出页面、进入后台均按音频规则取消相应会话。不能因为旧音频晚到的“完成事件”自动跳到下一段。

只有整篇录音时，全文入口可播放整篇；点段入口必须查找该段自己的音源或 TTS。界面明确显示“整篇录音，暂无逐段定位”，不高亮推算出来的段落。

### 5. 个人资料流程

```text
新建/导入 → 正文预览 → 类型/标题 → 自动注音
→ 校正读音/边界 → 可选译文 → 可选录音或导入语音 → 保存
```

不强制每一步都完成：正文有效即可保存草稿；“保存为学习内容”允许有待复核读音，但详情显示待复核状态。录音和译文可后补。录音工作区引用草稿的稳定文本单元 ID，最终保存时一并提交，不提前把半成品加入正式收藏。

离开有修改的编辑器时显示“保存草稿 / 丢弃 / 继续编辑”。应用切后台不弹确认框，而是尽力持久化草稿；重新打开提供恢复入口。草稿不是正式内容，完整备份前列出未保存草稿并提示先保存，不能暗示它们已经被迁移。

### 6. 分享和迁移流程

分享：选择内容及音轨 → 权限/来源规则检查 → 预览文件内容 → 生成临时包 → 系统分享或另存。关闭系统分享面板，只能说明“已打开系统分享”，不能在无法确定接收结果时说“对方已收到”。

备份：读取一致性快照 → 导出校验 → 系统保存 → 根据保存 API 的真实结果给出状态。取消保存不是成功。

恢复：选包 → 校验 → 冲突预览 → 合并/替换选择 → 本机安全备份（替换必需） → 暂存 → 提交 → 汇总。提交前可取消；短暂提交区不可半途取消，界面说明“正在完成保存”，完成后展示真实结果。

### 7. 页面状态统一

| 状态 | 画面 | 可做的操作 |
|---|---|---|
| Loading | 局部加载状态，避免全屏闪白 | 返回；可取消的任务可取消 |
| Ready | 内容与可用操作 | 正常操作 |
| Empty | 说明原因和一个相关入口 | 清筛选/新增内容等 |
| Error | 稳定错误说明与错误码 | 重试、返回、保留输入 |
| Dirty | 未保存提示 | 保存/丢弃/继续编辑 |
| BusyCommit | 提交状态，无重复按钮 | 不启动第二次写入 |
| MissingAsset | 正文正常，音源缺失说明 | 选音源、录音、导入 |

页面状态与音频状态分开，不用 `IsBusy` 一个布尔值控制整个应用。一个页面加载失败不应清空其他主导航的已保存状态。

### 8. Windows 与移动端统一语义

Windows 支持 Tab 遍历、Enter 激活、Esc 关闭弹层、右键替代长按、Ctrl+F 进入搜索。Ctrl+S 只在编辑器保存，不覆盖系统保存窗口快捷键。移动端返回键/系统返回手势调用同一个未保存保护；软键盘遮挡测试必须覆盖搜索底部输入框和编辑器。

快速双击内容最多打开一个详情实例；操作使用命令执行锁或导航去重。文件导入菜单一次只打开一个系统选择器，不因连点叠加授权窗口。

## 03 · 页面与组件详细规格

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 共用页面规范

五入口名称不按不同页面随意变化；正文学习区域和页面操作栏视觉分层。列表使用真实数据源、稳定 item key 和分页/虚拟化，不嵌套两个争抢滚动的纵向容器。详情返回保留列表上下文。

每个按钮必须有实际行为、禁用原因与辅助语义。演示阶段没有能力的按钮明确标“未实现”且不可进入正式发行版本；不弹“成功”来代替真正操作。

### 2. P01 拼音页

顶部是页面名与一次性简短操作提示，下面按分组纵向排列可换行的拼音条目。分组允许快速定位，但不拆成多个必须反复返回的页面。条目至少有普通、按下、播放、不可用、键盘焦点五种状态。

点击条目播放专用示范音频；长按 500 ms 为默认触发阈值，拖动进入滚动后取消长按；长按完成不再补发 click。Windows 提供右键和可点击的“例词”入口。长按能力可评估 Toolkit TouchBehavior，但绑定和手势冲突仍须测试。[S08](#doc-27)

#### 四声弹层

标题是所选拼音项，下面固定一至四声四行。每行依次展示声调标签、上拼音下汉字的例词、日/英译文、播放状态。整行可点击朗读例词，不朗读“一声”等 UI 标签。缺例词行显示“暂无常用例词”，不可播放。

高亮来自 `pinyinItem.examples[].highlight`：定位到 `contentId / unitId / tokenId / pinyinElementStart / pinyinElementLength`，只标红目标拼音范围，并增加下划线或强调标记。四声缺失不使用轻声顶替。关闭弹层停止其触发的例词播放，焦点回到原条目。

### 3. P02 学习页

第一层切换词语、课文、诗词；第二层为筛选区域；右上角一个“新建/导入”入口。筛选维度为场景、难度、学段/年级、来源。可折叠筛选，不让所有标签占满首屏。当前生效条件有摘要和“清除”。

词语列表显示汉字、带调拼音、当前语言译文、收藏状态和独立朗读按钮。课文/诗词列表显示中文标题、作者、短摘要和必要标签；标题译文是辅助行，中文 UI 隐藏。点击空白正文区进入详情，音频按钮不冒泡到导航。

空列表区分“当前无此类内容”和“筛选后没有匹配”。前者可引导导入，后者优先清筛选。来源“我的”显示输入、TXT 导入与分享导入的个人资料；草稿单独有入口，不混作正式学习内容。

### 4. P06 词语详情

| 区域 | 内容 | 交互 |
|---|---|---|
| 顶部操作 | 返回、收藏、更多 | 更多含分享；个人内容另有编辑/音频 |
| 词语头部 | 逐字注音、大字词语、读音/义项说明 | 点击头部或播放按钮，播放当前词条 |
| 释义 | 中文教学释义及当前 ja/en 辅助译文 | 中文 UI 只隐藏辅助译文，不删中文释义 |
| 例句 | 每句上拼音下汉字，下方句译文 | 点击整条例句播放完整例句 |
| 来源 | 提供方、审核/个人状态 | 查看来源详情，不伪造认证 |

相同汉字的其他读音或义项仅在库中确有数据时提供切换。词条头部与每条例句都是独立 `TextUnit`，各自拥有音频目标。词语收藏收藏当前词条 ID；播放例句不自动收藏整篇句子。

默认内置词条至少两条审核例句，个人词条允许零例句；缺例句不生成占位“例句1”。正文或读音需复核时以轻量提示呈现，不让草稿审核标记被隐藏。

### 5. P07 阅读器

标题、作者与来源在正文上方；工具栏含拼音显示、字号、全文朗读、收藏、更多。正文按原段落和诗行展示；译文在相应片段下方，不按一个汉字一条译文排列。

点段行为按文档 09 执行。放大弹层只有一个实例，内容过长可以滚动；顶部显示段落位置，底部为上一段、播放/停止、下一段、关闭。上下段按钮到边界时禁用，不循环跳转。

全文播放有“按段朗读”与“整篇录音”两种真实模式，有整篇音源时可选择；只有段录音/TTS 时显示按段模式。没有可靠时间轴的整篇录音只显示整体播放状态，不假装逐段高亮。全文播放切换模式先停止旧会话。

### 6. P03 搜索页

结果区域占据上方，底部输入框位于主导航之上，安全区及软键盘弹出时保持可见。输入框包含清除按钮，提示“输入汉字或拼音”；空态提供 `你好 / nihao / nǐ hǎo` 示例。

有效输入防抖 250 ms；Windows Enter 立即提交。首次显示最多 50 条，继续分页；结果排序必须可重复。首版支持词条，不将课文正文检索冒充已实现。可以保留内容类型扩展位置，但未实现时不显示可选空筛选。

搜索输入为中文输入法组合态时不主动回写输入框，不打断候选选择；识别已提交文本。已发出的旧请求可取消，无法取消时通过 queryId 丢弃旧结果。

### 7. P04 收藏页与 P10 收藏夹详情

收藏主页面显示收藏夹名称、条目数与最后变动信息，可新建、重命名、修改说明、排序、删除。默认夹有明确系统角色，不因 UI 切换产生多个语言名称夹。用户排序可拖动，也要有“上移/下移”无障碍替代。

详情按内容类型显示一致的条目卡片，允许移除收藏或修改所属夹。删除收藏夹确认文案明确“不会删除原词语、课文或录音”。删除个人内容从内容菜单操作，并另行显示影响的收藏和音频引用数量。

### 8. P05 设置页

| 组 | 控件 | 保存和反馈 |
|---|---|---|
| 显示语言 | 简中/日本語/English 单选 | 即时持久化并刷新，不重启清导航 |
| 阅读 | 字号 18—40 默认 24；显示拼音 | 预览当前学习片段；数字为默认逻辑尺寸 |
| 音频 | 可用普通话语音、试听、本地音源说明 | 语音不存在时正常回退，不读成 UI 语言 |
| 数据迁移 | 导出完整备份、导入备份、导入内容包 | 进入预览和确认流程 |
| 存储 | 正式资料、录音、草稿、缓存分项容量 | 清缓存只删可重建缓存 |
| 关于 | 版本、内容版本、隐私、来源、许可 | 实际版本与真实文件清单 |

主题和变速不是首版必需；不放无效开关。选项写入失败时恢复旧值并解释，不让 UI 已改变而数据库仍旧。

### 9. P08 新建与文本编辑器

顶部显示类型、标题、保存；正文编辑区始终可恢复原文。注音编辑在预览模式中进行，用户点击 token 修改拼音；不要在一个自由文本框中同时编辑汉字和整行拼音位置。

提供“生成/补全拼音”“只处理未锁定项”“预览全部重生成”的不同语义。新建正文为空、类型不合法、标题空白不可保存正式内容。超限显示计数与上限，不截断。个人译文、标签、来源说明放在可折叠辅助区。

切换正文与注音预览之前完成输入法提交和草稿同步。正文变更后展示“哪些读音校正保留、哪些需要复核、哪些音频受影响”的结果。人工分段只影响边界，不插入或删除正文标点。

### 10. P09 音频管理

按当前目标列出音轨：名称、来源、时长、是否默认、是否待复核。操作为试听、录音、导入、设为默认、重命名、解除绑定/删除。明确“整篇”与“当前片段”，避免用户不知道声音配到哪里。

录音界面显示目标文字、录音状态、时长、停止按钮；停止后有试听、重录、保存与丢弃。录音默认名称由时间与目标摘要形成，可修改。权限拒绝仍保留内容编辑状态。

### 11. P11 迁移预览

显示包类型、导出时间、内容/收藏夹/音频数、大小、缺失音源、冲突数和权限范围。分享包不能选“替换所有用户数据”。备份合并默认不应用外来设置；替换模式说明删除当前用户数据并二次确认。

完成汇总必须区分新增、复用、派生、跳过、未恢复和警告，不只显示一个“成功”。存在未恢复项时可查看具体列表，错误详情不泄露源设备绝对路径。

## 04 · 视觉系统、注音组件与无障碍

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 设计目标

视觉以易读、安静、轻量为主。学习正文比装饰重要；不采用大量玻璃质感、复杂渐变和动态卡片来争夺注意力。此为本项目设计建议，不是要求模仿某个现有产品。

统一设计 token，避免每页独立决定边距、字号、按钮形状。颜色和尺寸为提案，发布前必须用真实页面和对比度工具验证；本包不声称已完成视觉验收。

### 2. 基础 token

| 类别 | 默认建议 | 使用原则 |
|---|---|---|
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 | 页面内边距手机 16，宽屏 24；不以空格排版 |
| 圆角 | 8 / 12 / 16 | 小控件、卡片、弹层三个级别 |
| 正文字号 | UI 16；阅读汉字 24；拼音约 14 | 由系统缩放叠加；拼音不小到难以阅读 |
| 词语大字 | 汉字 36；拼音 20 | 长词可换行，不缩到难辨认 |
| 放大阅读 | 汉字 32，拼音 18 | 与原文相同数据，不生成另一份注音 |
| 辅助译文 | 14—16 | “小字”是视觉层级，不是固定微小字体 |
| 交互区域 | 48×48 逻辑单位为统一设计目标 | 图标可小，命中区域不能同样小 |
| 颜色语义 | Background / Surface / Text / Secondary / Accent / Error | 拼音红色为 TeachingHighlight，不能与错误状态混淆 |
| 字体 | 优先系统字体与明确合法的回退 | 不把机器上的字体文件直接打包分发 |

拼音高亮使用明确红色（候选 `#C62828`），同时辅以强调或下划线，保证色觉差异用户可识别。其他颜色不在需求中固定，交由主题资源统一定义。

### 3. 核心复用组件

| 组件 | 输入 | 输出事件 | 禁止职责 |
|---|---|---|---|
| RubyTextView | AnnotatedText、样式、选中 segment、可交互模式 | SegmentTapped、TokenEditRequested | 不直接访问数据库/TTS |
| PinyinTile | 教学项、播放状态 | PlayRequested、ExamplesRequested | 不自建全局音频实例 |
| ContentListItem | 摘要、译文选择、收藏状态 | Open、Play、Favorite | 不自己拼接查询 SQL |
| AudioButton | 会话状态、可播放原因 | Play/Stop | 不假定所有状态支持暂停 |
| FolderPicker | 当前成员集合、文件夹集合 | Confirm/Cancel | 关闭时不偷偷保存 |
| ImportSummary | 经过验证的导入计划 | Confirm/Cancel | 不直接信任未验证 manifest |
| StatusPanel | 错误码、已本地化信息、操作 | Retry/OpenSettings | 不把原始异常完整显示给用户 |

控件属性必须可通知、可测试；点击字、点段和整句播放模式显式区分，不依赖某页临时绑定顺序。

### 4. 注音控件的可访问性

普通阅读按句段提供语义朗读文本，避免屏幕阅读器同时把上方拼音与下方汉字读两遍。拼音学习或编辑模式可单独暴露 token 的“汉字、拼音、是否待复核”信息。纯自绘不能无语义节点；必要时使用平台可访问性适配层。

朗读按钮描述如“朗读例句：今天我去学校”，停止按钮有停止语义。收藏按钮暴露已收藏/未收藏以及打开选择器的行为。录音状态除颜色外显示“正在录音”和实际时长。

### 5. 布局和响应式

手机保持五项底部导航。Windows 首版可保持同结构，宽屏在内容区使用最大阅读宽度或主从布局，而不是把一行正文无限拉长。窗口缩窄后退回单栏，不遮挡保存和返回按钮。

内容列表只使用一个主滚动容器。阅读器虚拟化单位是可测量的布局行/块，不要求语义句段必须很短。超长无标点片段可以拆成多个视觉块，共用同一 segment ID；详见文档 09。

200% 字体缩放要验证：四声四行可滚动、上下拼音不截顶、对话框能关闭、底部输入不被键盘挡住、日英长按钮可换行。不能为了保持截图整齐而关闭系统字体缩放。

### 6. 键盘、焦点与触摸

Tab 顺序与视觉顺序一致；打开弹层聚焦标题或首个有效操作；关闭后回到触发控件；Esc 可取消非破坏性弹层。删除确认默认焦点不放在危险按钮上。

拼音项有可聚焦“示例”入口，不能要求键盘用户模拟长按。收藏夹排序提供上下移动。拖动滚动超过阈值时取消点击/长按，不在用户滑动列表时突然朗读。

### 7. 视觉验收素材

必须覆盖最窄目标手机宽度、横屏、Windows 小窗口和宽屏；中文/日文/英文各一组；正文混合 `ā á ǎ à ǖ ǘ ǚ ǜ`、汉字、日文、Emoji 和组合字符。截图记录系统缩放、应用字号、构建号。

截图只是显示证据，不替代声音、焦点、滚动和保存验证。此包提供设计规则，不包含声称已通过验收的 UI 截图。

### 8. 实现参考

MAUI 自定义布局提供测量与排列的扩展点；项目仍需实现注音单元测量、行布局、命中映射和无障碍。[S21](#doc-27) 不能把框架“支持自定义布局”当成已经存在完整 Ruby 控件。

## 05 · 多语言、教学译文与界面文案

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 三层语言必须隔离

| 数据 | 是否随 UI 语言变化 | 存储位置 |
|---|---|---|
| 导航、按钮、错误、分类标签 | 是 | `.resx` 资源 |
| 汉字、词语、诗词、例句、拼音、中文释义 | 否 | 内容文档 |
| 日英词义与句段辅助译文 | 是；中文时不显示 | 内容文档 `translations` |
| 用户收藏夹名、录音名、个人标题 | 否 | 用户数据 |
| 系统默认收藏夹显示名 | 是 | 由固定 systemRole 和 UI 资源得出 |

语种为 `zh-Hans`、`ja`、`en`。语言切换不能改内容 ID、正文哈希、拼音来源、音频适用哈希。由语言决定的显示字段是投影，不是新的内容版本。

### 2. 语言解析与持久化

首次系统语言按 `zh-* / ja-* / 其他` 映射，之后使用明确设置。`UserSettings.uiLanguage` 是迁移主数据；CultureInfo 和启动 Preferences 仅为运行时状态/可重建缓存。

资源默认英文，中文与日文分别提供完整资源；不得依赖缺失资源的默认回退来通过三语言验收。UI 资源翻译缺失是发布缺陷；个人正文缺译文不是功能错误。

资源文件本地化是 MAUI 官方提供的能力，运行时通知、主导航即时刷新、平台语言声明仍由本应用实现。[S03](#doc-27)

### 3. 即时切换事务

1. 验证目标语言在允许集合。
2. 写入设置；失败不改变当前语言。
3. 通过 UI 线程切换资源服务并发出 `LanguageChanged`。
4. 刷新当前页、Shell 导航、弹层后续文案、分类、系统夹显示名。
5. 保留内容、滚动、搜索输入和未保存草稿；关闭并重开弹层不是丢弃草稿的理由。

绑定不能只在构造函数读取一次 `AppResources.X`。ViewModel 应订阅可释放的语言通知，或使用可更新资源索引器。具体技术选用需在 M0/M1 验证。

### 4. 辅助译文选择函数

```text
SelectTranslation(translations, uiLanguage):
    zh-Hans -> null（隐藏整个译文容器，包含其边距）
    ja      -> translations.ja 非空时返回，否则 null
    en      -> translations.en 非空时返回，否则 null
```

空字符串与全空白作为未提供处理。日语缺失不返回英语；正文仍可学习。编辑器可以显示“尚未填写日语译文”，普通学习页默认不重复制造“无译文”噪音。对正式内置内容，缺译文在内容审核环节拦截。

### 5. 中文朗读与 UI 语言无关

语音服务单独选普通话目标 locale，用户选择 ja/en 界面不能使汉字被日语或英语语音朗读。恢复另一设备的 voice ID 时必须重新解析，不把它当成跨平台稳定 ID。

UI 切换不重新生成音频，不改变已有录音。系统中文语音缺失使用可理解的 UI 提示；不将拼音字符串作为英语文本提交 TTS。

### 6. 文案键约定

键按 `Nav / Action / Label / Error / Dialog / Audio / Import / Settings / A11y` 分组，例如 `Nav.Pinyin`、`Error.PackageHashMismatch`。资源值不包含用于业务判断的编码。

含数值的文案用参数，如“将导入 {0} 个内容、{1} 个音频”；不拼接中文词序后再翻译。显示日期使用当前 UI 区域习惯；存储和 JSON 时间统一 UTC ISO 8601。排序、哈希和包数值序列化使用不受 UI 区域影响的确定规则。

初始文案表见 `examples/ui-copy.csv`，状态为草稿，需日英校对。不得虚构“母语审校已完成”。

### 7. 高风险文案规范

| 场景 | 建议中文表达 | 必须说明 |
|---|---|---|
| 删除收藏夹 | 删除此收藏夹？原内容和录音不会被删除。 | 删除对象 |
| 删除个人内容 | 将删除此内容，并移除其收藏关系。 | 引用与音频影响 |
| 替换恢复 | 将替换本机已保存的用户资料；继续前先创建安全备份。 | 破坏性与保护步骤 |
| 改读音 | 已修改显示拼音，请确认原音频读音是否一致。 | 拼音与音频不同步 |
| 系统语音缺失 | 当前没有可用的普通话语音，仍可阅读或导入录音。 | 不阻断阅读 |
| 包未加密 | 文件包含个人正文或声音，任何取得文件的人可能读取。 | 保密边界 |
| 系统分享 | 已打开系统分享，请在目标应用完成发送。 | 不宣称接收成功 |
| 取消保存 | 已取消，未保存到所选位置。 | 不伪报成功 |

### 8. 验收

测试三语言来回切换，包含主导航、四声弹层、错误提示、恢复预览、默认收藏夹和麦克风用途说明。测试正文在语言切换前后哈希完全相同；中文时布局无空译文行；个人缺译文不触发英语回退；将英文 UI 与普通话 TTS 组合试听。

## 06 · 技术架构与依赖选型

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 技术基线与已核查边界

2026-09-14 核查的 Microsoft 支持页列出 .NET MAUI 10 为受支持版本，页面列出的补丁为 10.0.101、支持结束日期为 2027-05-11。**MAUI 补丁号不是 .NET SDK 号或 workload-set 号**；开工必须分别锁定，不把它直接填入 global.json 的 sdk.version。[S01](#doc-27)

本项目默认采用当前受支持稳定 .NET/MAUI，不自动切到预览版。最低 OS、Xcode、Android SDK/JDK 和 Windows SDK 以选定发行版本的依赖表及 M0 实测确定；不承诺“所有 iOS/Android/Windows 版本”。iOS 开发需要适用的 Mac 构建环境。[S02](#doc-27)

本包没有检查用户实际开发机，没有执行 .NET MAUI 构建。`tracking/environment-lock.template.json` 的未选择字段必须由真实环境填充，不能拿空值直接当作构建配置。

### 2. 工程结构

```text
src/
  HanMate.App/                  MAUI、XAML、ViewModel、平台能力适配
    Views/ ViewModels/ Controls/ Resources/ Platforms/
    Services/                  语言、系统文件 UI、TTS/录音底层适配
  HanMate.Core/                 纯 .NET 模型、规则、接口、用例服务
    Domain/ Application/ Contracts/
  HanMate.Infrastructure/       SQLite、文件库、包协议、离线词典
    Persistence/ Packages/ AudioStorage/ PinyinData/
tests/
  HanMate.Core.Tests/
  HanMate.Infrastructure.Tests/
  HanMate.Platform.Tests/       可自动化的平台部分；真机记录另存
```

依赖方向：App → Core 与 Infrastructure；Infrastructure → Core；Core 不依赖 MAUI、文件选择器、麦克风或具体 SQLite 包。无需再拆微服务、事件总线服务器或十几个空程序集。项目小可以合并 Infrastructure，但不能让核心规则无法独立测试。

### 3. 单一数据链

```text
View/XAML → ViewModel 命令 → 应用用例服务 → 仓储/引擎接口
                                        ├→ SQLite 与本地文件
                                        ├→ 离线拼音词典
                                        └→ 平台音频/文件适配
```

ViewModel 不直接读取 raw JSON 后自行保存另一份；领域服务不显示弹窗。读取结果为不可变 DTO 或快照；所有编辑经 `expectedRevision` 检查提交，提交成功后发出局部内容变更通知。

首版采用**一个运行时 SQLite 数据库 + 应用包中的版本化内置数据源 + 不可变音频文件库**。安装/升级时将内置内容导入数据库受控区域，查询统一索引；普通编辑只能改 personal，内置只能复制后改。避免双数据库跨库搜索/备份复杂度；这是对上一版可选方案的明确收敛。

### 4. 依赖建议与门禁

| 能力 | 默认路线 | 采用前验证 |
|---|---|---|
| MVVM | CommunityToolkit.Mvvm 或轻量自实现 | 源生成、编译绑定、裁剪 |
| UI 辅助 | CommunityToolkit.Maui 按需使用 | MAUI 版本、TouchBehavior、FileSaver |
| SQLite | Microsoft.Data.Sqlite 或 sqlite-net-pcl 二选一，M0 锁定 | 原生 SQLite 打包、事务、迁移、三平台 Release |
| 自动注音 | .NET 离线词典引擎；构建期加工字/词数据 | 数据许可、词组命中、儿化、字素、AOT |
| 系统朗读 | MAUI ITextToSpeech | 普通话 locale、取消、离线、生命周期 |
| 播放录音 | Plugin.Maui.Audio 为候选；不合适时局部平台适配 | 真录音、编码、完成事件、释放 |
| 文件选择/分享 | MAUI FilePicker、Share；保存适配按版本验证 | URI/流、后缀、取消、受限分享目录 |
| 包 | System.IO.Compression + System.Text.Json + SHA-256 | 资源限制、重复键、路径、流式计量 |

Microsoft 文档给出 MAUI SQLite 使用路线；具体库选型与打包仍需验证。[S09](#doc-27) Plugin.Maui.Audio 项目包含播放与录音能力，但不代表任意版本/编码/平台组合都已经适用于本项目。[S10](#doc-27)

不为调用 Python 拼音库在手机中嵌入 Python；文档验证脚本和数据构建脚本可以使用 Python，但只在开发/构建阶段运行。

### 5. 生命周期与实例范围

应用级 singleton：数据会话协调器、音频协调器、语言服务、字典加载器、内容变更通知。页面与 ViewModel 按导航范围创建并释放订阅；禁止通过 singleton 持有整棵页面树。

长任务使用 CancellationToken 和 operationId；状态回到 UI 线程更新。除 UI 事件入口外不写 `async void`。取消不是失败；异常带稳定错误码，不吞掉异常后继续“成功”。

启动顺序：应用目录 → 数据库迁移 → 未完成操作恢复 → 内置目录更新 → 设置加载 → 搜索索引检查 → 主页面。数据库迁移失败时保留原库，不以清库重建恢复启动。

### 6. 并发边界

单进程、单主窗口是首版默认。Windows 第二次启动不允许绕过数据会话锁并发破坏性恢复；是否支持多实例由 M0 记录，可限制为单实例。运行中的数据库写入由单写队列或可控事务门限串行协调。

普通读可并发，编辑提交使用乐观版本检查；导入、目录升级、替换恢复使用排他的数据维护门。音频文件为内容寻址不可变文件，删除由引用/租约检查后的 GC 处理。导出获取快照与文件租约，不阻塞整个压缩期间的普通读取。

### 7. M0 五项技术试验

每项有最小程序、版本、输入、输出和证据：三平台最小构建；注音排版与长文；离线多音字校正；实际录音与播放中断；文件保存—重新选择—导入。接口模拟只能证明协调逻辑，不能证明真机音频。

若候选库失败，先隔离到适配器，不重写全部架构；记录失败平台、复现输入、替代实现成本与决策。受阻平台不能标记完成，但不阻止纯逻辑测试继续。

## 07 · 数据模型、持久化与版本策略

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 数据真源与派生数据

| 数据 | 唯一真源 | 可重建内容 |
|---|---|---|
| 词语/课文/诗词、注音、例句、译文 | ContentDocument 版本化 JSON | 列表摘要、搜索字段、播放目标投影 |
| 用户收藏和设置 | SQLite 关系表 | 页面显示状态、启动缓存 |
| 用户音频文件 | 不可变音频存储，按 SHA-256 定位 | 波形/试听缓存等 |
| 音轨绑定及默认选择 | audio_binding / audio_preference 表 | 当前播放策略缓存 |
| 内置内容源 | 应用随附的经过审核目录包 | 运行时 SQLite 内置投影 |

`content.body_json` 为完整内容文档；表中的 title/kind/revision 等是查询投影，由一次事务同步生成，不能独立更新。全文、拼音不再存进 `.resx`。音轨绑定只在音频关系表/包 `audio/index.json` 中维护，不同时以另一套可编辑字段嵌入 ContentDocument。

### 2. ContentDocument

关键字段：`schemaVersion=1`、UUID `id`、`kind=word|text|poem`、`origin=personal|builtin|builtinSnapshot`、`title`、`contentRevision`、`annotationRevision`、`metadataRevision`、`difficulty`、`schoolStage`、`grade`、`scenes`、`source`、`textUnits`、时间。

一条 word 内容表示一个明确读音/义项；同字不同音义为不同 contentId，不再使用可空 senseId 参与收藏唯一性。这是首版简化规则，不阻止将来增加词头聚合。

| TextUnit.role | 数量/要求 | 用途 |
|---|---|---|
| headword | word 恰好一个 | 词语头部发音与注音 |
| example | word 可零或多个，默认上限 20 | 例句，各自独立音源 |
| body | text/poem 恰好一个 | 正文和句段阅读 |

每个 TextUnit 都有 UUID `id`、原样保存的 `text`、`offsetUnit=textElement`、`elementBoundariesUtf16`、`tokens`、`segments`、`translations`。标题不混入正文范围；例句不冒充根正文的一段。

### 3. 范围与字素

主范围仍为文本元素序号：`start`、`length`。额外持久化从 0 到原文 UTF-16 总长度的边界表 `elementBoundariesUtf16`，含结尾 sentinel；从该表得到 token 与 segment 对应的 UTF-16 片段。范围不得负数、越界、重叠或丢字符。

.NET StringInfo 可用于创建文本元素映射；ParseCombiningCharacters 返回的是 UTF-16 起点，不是文本元素序号。[S15](#doc-27) **持久化边界表用于校验和跨版本保护，不能在恢复时丢掉它后用新算法静默重解释旧整数。**

导入检查：边界单调、首项 0、末项等于 UTF-16 长度、不拆代理项，token.text 与范围完全匹配；再与支持的文本元素实现核对。不一致返回 `TEXT_BOUNDARY_MISMATCH`，在修改数据库前停止并给出纯文本另存/显式迁移路径，不自动移动人工校正。

正文保留原来的组合字符、换行与繁体；不对原文做静默 NFC/简繁转换。拼音 display 则规范为 NFC。常规汉字一字一个 token，儿化可以一 token 覆盖“花儿”。非汉字 token 的拼音为 null。

### 4. token 与 segment

Token：稳定 id、start、length、text、kind、pinyin、annotationSource、locked、reviewState。拼音包含 base、tone、erhua、display；base 保留 ü；tone=0 表示轻声；未知读音用 pinyin=null 且 reviewState=unknown，不用 0 冒充未知。

Segment：稳定 id、start、length、text、kind=speech|layout、boundarySource=auto|manual、translations、tokenIds。speech 为可点击朗读范围；layout 承载纯空白/换行/非朗读标点。**全部 segment 顺序连接必须还原 text，全部 token 同样必须还原 text。** token 不跨 segment；分段变化必须重新校验 token 列表。

只有包含实际可朗读文字的范围才能是 speech。词语例句的整句朗读目标是 unit，不受课文标点切段入口影响。

### 5. 播放目标和音频模型

所有可播放目标投影进 `playback_target`：ID 等于 unit、speech segment 或 pinyinItem 的稳定 UUID；owner 指向一个 content 或一个 pinyinItem；含当前 textHash、pronunciationHash 和 role。目标投影可由真源重建，但其 ID 不重新随机生成。

AudioAsset：id、sha256、relativePath、byteLength、durationMs、container、codec、sampleRate、channels、origin=user|catalog。文件相对路径由应用生成，不能来自原设备绝对路径。

AudioBinding：id、targetId、assetId、boundTextHash、boundPronunciationHash、reviewState=confirmed|needsReview、sourceRole=standard|user|imported。AudioPreference 单独保存 targetId → bindingId。复合外键保证默认音轨确实属于同一 target，不以一个全局“默认录音”串到其他片段。

修改标题/标签/译文不影响声音；原文或有效读音变化使相关绑定 needsReview。仅锁定状态或审核备注变化不应让未变的音频失效。

### 6. 收藏、设置和导入记录

FavoriteFolder：id、name、nameKey、description、sortOrder、systemRole。只有一个 systemRole=default；其名称由 UI 资源显示。普通夹名经 trim + NFC + 不受文化区域影响的大小写归一化生成 nameKey；同名拒绝，导入冲突用确定后缀。

FavoriteItem 的主键为 `(folderId, contentId)`，没有可空 senseId 陷阱。SQLite 唯一索引对 NULL 的行为必须明确，不能以为可空三列会自动实现业务去重。[S12](#doc-27)

UserSettings 用单例行存可迁移 JSON；设备专属 voiceId 不作为跨设备设置真源。ImportReceipt 记录 packageId、archiveSha256、提交结果；ImportMapping 记录原实体 ID、源语义指纹与本地 ID，确保冲突派生幂等。

### 7. 版本和哈希

| 变化 | contentRevision | annotationRevision | metadataRevision | 音频处理 |
|---|---|---|---|---|
| 修改正文/例句文字 | +1 | 受影响后 +1 | 不强制 | 对受影响目标复核 |
| 修改有效拼音 | 不变 | +1 | 不变 | 读音哈希变化的目标复核 |
| 仅标题/分类/译文 | 不变 | 不变 | +1 | 保持 |
| 锁定/解锁、不变读音 | 不变 | +1 | 不变 | 哈希不变时保持 |
| 修改默认音轨 | 不变 | 不变 | 不变 | 单独音频关系事务 |

`textHash`：对应目标原文 UTF-8 字节的 SHA-256。`pronunciationHash`：按目标内 token 顺序，以 `start/length/base/tone/erhua` 的规范语义序列计算；不含 UI 语言、display 冗余、修改时间、锁定标记。具体规范化见文档 14。

同一文档保存采用数据库 rowRevision 乐观锁；旧编辑器提交返回 `REVISION_CONFLICT`，保留草稿并让用户比较，而不是按设备时间强制覆盖。

### 8. SQLite 草案和迁移

可执行 DDL 见 `specs/database.sql`；它是设计参考和文档校验对象，不是已集成到 MAUI 的数据库实现。外键须在每个连接启用并检查，不能只在创建表时启用一次。[S13](#doc-27)

迁移流程：检测版本 → 取得维护门 → 安全备份 → 事务执行逐版 migration → 检查外键/内容投影/用户数据计数 → 提交 → 更新版本。失败保留原库，禁止 `DROP DATABASE` 式重建用户资料。

内容目录更新与用户数据迁移分开。更新内置内容前检查用户收藏/音轨依赖：稳定 ID 保留；删除项保留必要快照；读音变化使用户音轨复核。内置资料不是让用户覆盖的共享可写文本。

### 9. 文件一致性与清理

数据库事务不能同时原子提交文件系统；音频先暂存验证，再写为不可变正式文件，最后在 SQLite 事务中引用。SQLite 事务只能保证其数据库操作边界，外部文件需要应用级恢复协议。[S11](#doc-27)

GC 只清理无数据库引用、无导出租约且超过保护期的文件；不能用“清缓存”删除用户音频。磁盘不足、进程终止和数据库忙都要保留旧数据，具体步骤见文档 15。

## 08 · 离线注音、标调与人工校正

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 能力边界

目标是离线生成可校对的拼音，而不是承诺理解任意人名、地名和古文。算法必须能够解释“词组命中、多候选、单字回退、未知”，不能伪造精确概率或“AI 已确认”。

内置教学资料通过人工审核提供确定注音；用户输入先自动生成，再允许修改。拼音源与语音源分离，显示校正不会自动驱动系统 TTS 的逐字发音控制。

### 2. 引擎路线

默认构建期加工合法可用的字音与词组数据，运行时由纯 .NET 引擎读取。字典使用 code point 访问汉字，文本范围使用文档规定的文本元素映射。词组数据和单字数据是候选来源，不自动等于准确教材。

pinyin-data 和 phrase-pinyin-data 分别提供字音与词语数据，词语库也可能包含多读音及上游合并数据；具体数据文件、版本、来源和许可须分别登记。[S14a / S14b](#doc-27) python-pinyin 可用作构建期参考/对照，不要求手机运行 Python。[S14c](#doc-27)

### 3. 确定性处理流程

```text
保存原文与文本元素映射
→ 识别可注音汉字段和非汉字范围
→ 读取当前内容中已锁定且锚点仍有效的校正
→ 在可处理区匹配已审核局部短语
→ 词组词典匹配（优先覆盖更完整的匹配）
→ 单字候选回退
→ 输出拼音、候选、来源、待复核状态
→ 合并有效人工校正
→ 生成带调 display 并做范围/词音数校验
```

词组候选选择首版采用可复现规则：人工覆盖 > 已审核短语 > 最长合法词组 > 显式词典优先级 > 单字。相同优先级仍有多个读音时保留候选并标待复核，不随机选一个并标 confirmed。最长匹配是基线，不宣称解决所有歧义；有实际错误样本再引入更复杂分词/消歧。

人工锁定范围是匹配边界，词典命中不可跨越并覆盖锁定项。词音数与汉字段元素数不一致（如儿化）需有显式映射，不能 `zip()` 截掉多出的字或音。

### 4. 拼音数据形式

标准保存形式是 base + tone + erhua。例：`base=lü,tone=4,erhua=false,display=lǜ`。轻声 tone=0；无可靠读音用 null。base 小写，保留 ü，不以 v 作为正式展示。

| 输入 | 规范结果 | 说明 |
|---|---|---|
| ni3 | nǐ | 数字声调 |
| liu2 | liú | iu 标调位置 |
| gui4 | guì | ui 标调位置 |
| lv4 / lu:4 / lǜ | lǜ | 输入别名统一 |
| ma5 / ma0 | ma，tone=0 | 轻声 |
| huar1 | huār，erhua=true | 只在合法儿化上下文使用 |
| nu | nu，无指定声调 | 搜索可用；编辑需用户确认 tone |
| ni6 / ni33 | 拒绝 | 不支持的/重复声调 |

无调输入在查询中表示“不限定声调”，在人工编辑中表示“尚未指定”，**不能无条件存成轻声**。用户编辑必须选 1—4、轻声或未知状态。

显示一般采用本调。连读变调的自然声音可能与本调显示不同，这是教学口径，不是每次 TTS 都错。若未来提供教学变调显示，需另设明确模式，不能混入首版默认数据。

### 5. 标调和 ü 规则

实现维护明确标调规则与合法音节表：先定位主要元音，处理 a、o/e 与 iu/ui 等情况；生成 NFC 带调拼音。不要把调号一律放在末字母上。`j/q/x/y` 相关拼写、缩写韵母和儿化以经审核音节规则处理，不以全局 `u→ü` 替换实现。

ü 的去调只去声调，不去两点。输入 `nǚ/nv/nu:` 可归一到 nü；`nu` 保持 nu。组合形式 `u + 分音符 + 声调` 和预组字符应得到相同 base/tone。`ê`、成音节 m/n/ng 等特殊输入可作为显式高级候选，未实现的形式标需复核，不能改成随便一个常用音。

教学规范来源和标调参考登记于文档 27；规则测试以 `examples/pinyin-cases.json` 为起点，发布前需教学校对扩展。

### 6. 人工校正与重生成

用户点击 token，可选择候选或输入新的合法拼音；保存记录 annotationSource=manual、locked=true、修改时间。校正默认只作用当前内容当前出现位置，不全局修改词典，不把整篇所有“行”改成同一读音。

“补全未确认读音”不碰锁定项；“重新自动注音”默认保留锁定项；“全部重新生成”先列出将覆盖的人工项并二次确认。确认后仍保留编辑前版本作为本次撤销/草稿恢复基础。

读音改变后同步刷新个人词条索引，增加 annotationRevision；对应目标的 pronunciationHash 变化时将绑定音轨标待复核。显示修改必须先进入草稿，正式提交失败时不谎称已保存。

### 7. 原文变化的锚点规则

每个 token 和 segment 拥有稳定 ID。编辑正文后，按未变区间和上下文做差异匹配；**只有唯一确定的原文范围映射才自动保留校正**。重复文本导致无法唯一判断时，宁可要求复核，也不能错误迁移读音。

改变片段复核：拆分/合并不按数组下标复用音轨；仅前面插入一段而后面原文唯一未变时保留后段 ID/校正/音频。正文完全重新替换时重新生成身份和绑定预览；标题变化不触发正文重建。

### 8. 本地字典覆盖

首版人工校正是内容级。开发侧可以维护审核后的短语覆盖文件，但每条须记录来源、原因、测试样本和版本。用户级“总是这样读”的全局个人词典属于 P1，不在本次编辑里暗中创建。

字典更新不覆盖已经确认的内置资料或人工锁定项；新算法结果以预览形式应用到未锁定范围。记录引擎版本和字典版本，便于复现不同版本的注音结果。

### 9. 必测样例与评估

最小样例含：银行/行走、音乐/快乐、重新/重量、长大/长度、得地的、轻声、ü、儿化、诗词多音字、姓氏、生僻字、Emoji、组合字符、拉丁字母和数字。词组正确与否以审核样例为基准，不用引擎自己的输出作为金标准。

分别报告字音准确率、词条全对率、多音字子集结果、未知率和人工锁定保留率。人工锁定保留率与范围一致性要求 100%；任意古文的自动注音准确率不承诺 100%。核心已审核样例必须全部正确或明确待复核，不允许安静误读后显示 confirmed。

## 09 · 注音排版、标点分段与阅读器

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 三种单位不要混用

**文本元素**是原文位置与编辑边界。**语义片段 segment**是点击/朗读边界。**视觉布局行/块**是屏幕测量与虚拟化单位。它们不是同一个概念：20,000 字无标点文本仍可保持一个语义片段，同时分成许多虚拟化视觉行。

TextUnit 的完整原文始终保留；不为性能丢掉前后文，不把每屏文字当成新的资料。词条例句播放以整个 example unit 为目标，课文点击才使用 speech segment。

### 2. 分段优先级

先识别数字、时间、网址等保护区，再处理人工边界与自动标点。人工边界必须位于文本元素边界，不在 token 中间；修改边界本身不修改原文。所有边界结果都带规则版本和来源。

| 输入情况 | 默认处理 |
|---|---|
| `，。！？；：` | 结束当前非空 speech，标点留在前段 |
| `, . ! ? ; :` | 不在保护区时才作边界 |
| `3.14`、`v1.2.3`、`10:30` | 作为保护串，不从内部拆开 |
| URL/邮箱 | 保护有效内部标点；尾随中文句末符号不吞进 URL |
| `……`、`...`、`？！` | 连续结束符为同一标点组 |
| 紧接结束符的 `”’」』）】` 等 | 归入前段；不吞掉后面的正文 |
| `、` | 不单独形成点击边界 |
| LF、CRLF、段落空行 | 保留原始字符为 layout，结束前段 |
| 纯空白/纯标点片段 | layout，不生成可播放空任务 |
| 无标点长文本 | 保留语义片段，视觉层分行；TTS 子请求另行处理 |

保护串识别是有边界的规则，不宣称完整解析所有自然语言网址。遇到不能确定的结构宁可少切，并允许用户手工调整；不能为了凑短句把数字切坏。

### 3. 还原性

输出的全部 segments（含 layout）按 start 顺序连续覆盖原文，无重叠、无缺口；每个保存的 segment.text 必须等于该范围实际文字。tokens 同样完整覆盖原文；一个 token 只属于一个 segment。

示例：`你好！\r\n欢迎。` 中间的实际 CRLF 是 layout，不能标准化为 LF 后仍沿用旧范围。序列化展示可以转义，保存的原文不能变。

参考测试见 `examples/segmentation-cases.json`。它是测试预期，不是已实现的分段引擎。

### 4. RubyTextView 测量算法

每个 token 生成原文字形和可选拼音字形。单元宽度为 `max(原文测量宽度, 拼音测量宽度)+左右内边距`；单元高度包含拼音 ascent/descent、行间距和原文行高。基线统一，声调不得被控件顶部裁掉。

逐单元排入剩余行宽；汉字和其拼音作为不可拆整体换行。标点避免出现在行首的规则在视觉层处理，不移动原文索引；遇到极窄容器允许整组换行，不以缩小到不可读来隐藏问题。

无拼音的拉丁串/数字允许按合法视觉机会换行；词语、儿化 token 保持其既定注音对应。当前首版不实现复杂拼音跨字悬挂排版，优先保证“不错位、不裁切、可缩放”。

布局输出包含每一行、每一 token 的矩形与 segmentId，用于点击命中、选中、高亮和无障碍。不要通过像素颜色或 Label 文本反推命中对象。

### 5. 渲染与虚拟化策略

M0 先用小范围可测量布局验证正确性，再验证 20,000 文本元素。主阅读器采用可虚拟化的视觉块，保持 `block → segment → token` 映射。不要让一个巨大无标点段生成几十万个原生控件；必要时采用自绘块，但必须实现可访问性语义节点和编辑命中。

缓存键包括 unitId、内容/注音版本、可用宽度、字体及缩放、拼音可见性、布局算法版本。译文和正文布局可分缓存；UI 语言切换只更新译文影响的区域，不能触发自动注音。

后台完成布局数据计算，实际平台文字测量按被选 API 的线程要求执行；不能假定任意字体 API 都可放后台。每次尺寸变化取消过期布局任务，新结果通过 generationId 验证后才应用。

### 6. 点段与放大阅读状态

阅读器维护 selectedSegmentId、expandedSegmentId、playbackSessionId；三者不要合并成一个“当前索引”。点击新段更新选择与放大，并请求播放；同段正在播放时只停止。结束后保留选中，不自动跳下一段。

全文按段模式顺序等待每段播放完成；用户交互导致取消后旧完成事件不得推进队列。上一段/下一段默认不播放；关闭弹层停止由此弹层拥有的单段会话；退出页面停止该页所有会话。

### 7. 整篇音轨与 TTS 子分块

整篇音轨没有明确时间轴时，只能全文播放，不能伪造逐段进度。全文录音播放后点段先停止整篇，再请求段音源/TTS。

单个语义片段超过系统语音单次限制时，允许在**播放适配层**按安全词语/标点位置产生子请求：保留同一个 segmentId、按序播放、取消共同生效、不在 UI 伪装成更多语义片段。不确定引擎限制时在 M0 测量并记录；禁止静默截断朗读后声称全文完成。

### 8. 编辑后的身份映射

未改的唯一原文片段可保留 ID；更改或拆并后的片段须重新核对 token、译文和音频。分段编辑导致原先逐段译文失去准确边界时转入待复核，不把前后译文简单拼接当作正确翻译。

只改标题、作者展示或分类不重建 unit/segment。自动重排版不改变任何领域 ID；Windows 窗口拉伸不能造成收藏、音频或人工拼音变化。

### 9. 验收与失败回退

验证长拼音、轻声、儿化、Emoji、组合调号、CRLF、连引号、混排数字、200% 字号、长无标点段、诗行。若特殊字体无法显示某字，保留原文并给出缺字提示；不可替换为看起来相似的别字。

普通纯文本可读是异常回退，不等于注音功能已通过。若正式目标设备存在严重错位/裁调号，视为核心功能缺陷，而不是降级宣布 Ruby 已完成。

## 10 · 离线搜索、拼音查询与索引

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 搜索范围

首版检索已收录的 word 内容，包含个人词条。同字不同音义通过不同 contentId 分开返回。课文/诗词标题搜索是独立扩展，不能用查到标题来冒充词典结果；默认没有全文向量检索、RAG 或在线补词。

索引从已保存的 headword unit 与已确认读音派生，不从当前 TTS 结果或 UI 译文反推。多个确认读音可建立显式 alias 行，但不得为每个多音字的全部候选做笛卡尔组合。

### 2. 索引字段

| 字段 | 示例 | 规则 |
|---|---|---|
| hanzi_key | 你好 | 搜索副本 NFC，原文不改 |
| pinyin_joined | nihao | 无调、连续、索引用 v 代表 ü |
| pinyin_separated | ni hao | 保留已知音节边界 |
| tone_separated | ni3 hao3 | 轻声为 0 |
| tone_joined | ni3hao3 | 数字声调输入快速精确匹配 |
| syllables_json | ni/3, hao/3 | 对显式声调和边界细粒度排序 |
| frequency_rank | 100 | 可空；不可随机生成声称真实频率 |
| index_version | 1 | 升级可重建 |

base 正式数据保存 ü；索引中 v 是内部查询编码。文档、UI 和导出内容的学习拼音不能因此显示 `nv`。

索引行身份为 contentId + aliasOrdinal，唯一性与 word 音义项一致。修改个人注音后在同一写事务中刷新相应索引；索引失败则不提交内容半成品。恢复/目录更新可批量重建，重建中不返回不完整结果冒充全量。

### 3. 查询归一化

保留原输入供显示。查询副本 trim、NFC、小写；合并多空格，将直/弯隔音符统一为音节边界；先识别 `u:`、v、带调 ü，再解析声调。不能“一口气删除所有组合标记”，否则会把 ü 错变成 u。

数字声调允许 1—4、0/5；归一后 5 为 0。输入中的普通数字不当声调，除非它位于合法拼音音节尾。未知字符、仅符号输入返回明确空态，不执行动态 SQL。

| 输入 | 查询语义 |
|---|---|
| 你好 | 汉字完整或前缀/包含 |
| nihao | 连续无调，允许多个已知音节划分候选 |
| ni hao / ni'hao | 有音节边界证据 |
| nǐ hǎo / ni3 hao3 / ni3hao3 | 指定相应位置声调 |
| nǚ / nv / nu: | 同一 nü 查询 |
| nu | nu，不等于 nü |
| xi'an / xi an | 优先 xi + an |
| xian | 可召回 xian 与 xi + an，明确列为不同词条 |

连续带调输入如 `nǐhǎo`：先取得无调连续键候选，再按候选已有音节切分核对调号位置；不强制只选择一种猜测切分。空格/隔音符是边界约束，带调字符或数字是声调约束；不要把不完整声调查询补成全部轻声。

### 4. 排序和近似结果

排序层级：汉字精确 → 音节边界和指定声调均匹配的完整拼音 → 完整无调拼音 → 前缀 → 包含。若用户未指定边界/声调，对该条件不惩罚。用户指定声调但无完全命中时可以列无调近似项，必须显示“近似拼音结果”，不能伪装精确声调匹配。

同层使用稳定元组：显式 commonRank（存在时）→ 词条元素数 → contentId 的 ordinal 顺序。不得用随机排序，也不根据 UI 语言的字符串比较改变核心匹配。

每个 contentId 只显示一次，多个 alias 命中取最佳层级。相同汉字不同内容 ID 必须保留，不误以标题相同为重复。

### 5. 查询实现基线

SQLite 建立汉字、连续拼音、分音节拼音、数字调键的普通索引。精确和前缀分层查询，后续包含查询作为最后一层；`%包含%` 不假设能有效使用普通 B-tree 索引，必须实测。

参数化传值，并对 LIKE 的 `%`、`_` 与转义字符做字面处理；用户输入不拼接进 SQL。可以采用确定的 prefix 上下界查询，或核对排序规则后的 LIKE；是否使用索引由 EXPLAIN QUERY PLAN 和目标设备计时确认，不靠口头保证。

先完整计算较高层级的可用结果，再补较低层级，避免提前截取低质量候选导致精确声调结果丢失。初页 50 条，用稳定游标继续；不直接把“返回 50 条”当全库只命中 50 条。

10,000 条词语是首版性能基准，超过基准仍不能截断数据。出现性能问题可增加结构化索引或经过验证的 FTS，但不默认换成服务器。

### 6. UI 和取消

输入防抖 250 ms，Enter 立即执行，清空取消请求并清空结果。每个请求有 queryId；只有最新 queryId 的结果可以更新列表。取消数据库查询做不到立即生效时，至少丢弃过期结果并释放资源。

不回写正在组合的中文输入法文本；回车如果用于确认输入法候选，不应意外同时打开第一条结果。点击朗读不影响查询；详情返回恢复 query、筛选和 scroll anchor。

### 7. 一致性和升级

启动发现 index_version 不匹配时从 ContentDocument 重建，不删除个人主数据。修改读音、导入冲突派生、删除词条、目录升级都必须更新索引；没有保存的草稿不进入正式词典查询。

重建采用维护门与事务/影子索引切换，外部读者看到旧完整索引或新完整索引。记录重建数量、版本和错误码，不记录用户的搜索全文。

### 8. 性能与正确性验收

基准包含汉字精确、单字多音义、连续拼音、数字声调、ü、隔音符、短前缀、无结果和包含查询。P95 ≤ 200 ms 是查询引擎目标，不含 250 ms 防抖；另记录输入提交到列表显示的端到端延迟。

`examples/search-cases.json` 给出具体输入与应有/不应有结果。单元测试可模拟仓储；查询计划与耗时必须使用真实 SQLite 和真实数据。未测试 Windows 输入法、iOS/Android 软键盘时不能把桌面单元测试当三平台通过。

## 11 · 朗读、录音、音轨与音频生命周期

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 音频目标和音源

目标为拼音教学项、词语 headword、例句 unit、课文 body unit 或正文 speech segment。调用时传 targetId，不传“第几行”作为永久身份。音源类型为 catalog 标准录音、user 录音/导入音频、系统普通话 TTS。

默认顺序：用户明确选择且仍适用的音轨 → 对应的审核标准音轨 → 个人内容已确认绑定音轨 → 允许时的系统 TTS。拼音教学项只接受审核的教学示范，不用普通 TTS 盲目读拉丁字母。

用户跟读内置内容后，默认不覆盖标准音源。保存时可明确勾选“设为该目标的默认音轨”；个人内容默认勾选，内置内容默认不勾选。

### 2. 状态机

| 当前状态 | 请求 | 结果 |
|---|---|---|
| Idle | Play | Loading，找到音源后 Playing |
| Loading/Playing | Play 新目标 | 取消旧会话，确认停止后开始新会话 |
| Playing | Stop 或再次点同目标 | Stopping → Idle |
| Idle/Playing | StartRecording | 先停止播放 → RequestingPermission → Recording |
| Recording | Play | 返回 RECORDING_BUSY；要求先停止，不隐藏丢弃录音 |
| Recording | StopRecording | Finalizing → 生成可试听草稿 → Idle |
| Recording | 页面退出/后台/中断 | 尽力安全停止为草稿，不自动续录 |
| 任意活动状态 | 不可恢复失败 | 释放资源，返回 Idle，并附稳定错误结果 |

“有录音草稿”是编辑器状态，不意味着麦克风仍在 Recording。状态仅允许协调器修改，页面不能自行把 IsPlaying 设为 false 后不停止真正播放器。

每个请求有 sessionId 和 ownerScopeId。旧完成回调先检查 sessionId，再更新高亮或推进全文队列；跨页面停止按 ownerScopeId 定位，不误停新页面已开始的音频。

### 3. 完成和取消语义

PlayAsync 表示本次播放到自然结束、取消或失败后的结果，不是“已经调用 Play 方法”。底层播放器使用完成事件转换为 Task，并保证事件/流/播放器释放。停止正在加载的文件同样必须取消后续开始动作。

全文朗读用顺序 await，不并行提交全部片段。系统 TTS 官方说明可用文本、语音选项与取消令牌，并提示跨线程排队和后台播放的限制；应用仍自行管理队列和生命周期。[S04](#doc-27)

如果停止后底层仍短暂回调，忽略过期事件；如果设备停止 API 失败，返回真实失败并禁止继续叠加，而不是假装 Idle。长播放过程中保持文件租约，GC 不得删除正在读的音频。

### 4. 整篇与逐段

body unit 音轨用于整篇播放，segment 音轨用于单段播放。只有整篇录音不具备 segment 时间轴；全文模式可直接播放它，段模式按段音轨/TTS 回退。

按段全文模式可混用已确认段录音和 TTS，但播放开始前告知缺失项；无法播放某段默认停止并提示，用户可以明确选择跳过，不静默略过后宣称全篇完成。整篇模式没有精确段时间轴就不做同步段高亮。

句段停顿优先来自音源本身；额外延迟是可调整播放体验，不声称三平台语音韵律完全一致。首版不包含自动强制对齐、按字数估算时间轴、波形编辑或自动语音评分。

### 5. TTS 与离线策略

系统语音选择与 UI 语言分离。枚举普通话候选并提供试听；语音 ID 为设备专属，不直接迁移。仅发现中文 locale 不能证明飞行模式可用，M0/M5 需实际验证。

设置默认允许“本地音频优先，必要时尝试系统语音”；增加可调整默认项“仅使用本地音频”用于不希望调用系统合成的场景。系统提供方可能受自身设置影响，应用不声称绝对无网络行为。

人工改拼音只改教学注音；对必须精确遵守校正的段，优先使用确认匹配的录音。不得将拼音拉丁字符串提交 TTS 后当成可靠普通话。

### 6. 录音工作流

选择目标 → 说明用途并请求麦克风 → 显示录音计时 → 停止 → 关闭/修复音频容器 → 试听 → 保存/重录/丢弃 → 可选设为默认。未停止时不让草稿成为正式资产；保存需要非空、可解码、时长有效的音频。

麦克风权限只在实际录音时申请；拒绝返回编辑页，不能循环弹请求。永久拒绝提供系统设置入口。进入后台、音频焦点丢失、来电等尽力结束并保留草稿；突然被系统终止可能来不及修复容器，启动时检查并明确说明草稿是否可恢复，不能承诺任何中断都零损失。

窗口短暂失焦和应用真正进入后台不是同一事件，Windows 文件对话框不应被误判为长时间后台。平台生命周期回调按实测接入。[S20](#doc-27)

### 7. 编码与容量

| 类型 | 首版验证目标 | 说明 |
|---|---|---|
| WAV | PCM 16-bit little-endian，常用采样率/声道 | 优先作为跨平台录音基线 |
| MP3 | 常见 MP3 音频流 | 需实际探测和播放 |
| M4A | AAC-LC 音轨的 M4A 容器 | 不等于支持所有 AAC 变体或裸 .aac |

具体录音采样率和编码按候选库及平台实测确定；请求参数不等于实际输出参数，必须探测文件头。Plugin.Maui.Audio 的录音文档是能力参考，不是本项目三平台录音已通过的证据。[S10r](#doc-27)

导入单文件 ≤100 MiB；连续录音 ≤20 分钟，同时受 100 MiB 限制，两者先达到者先安全停止。录音前做剩余空间检查，录制中实时统计字节；容量来自实际文件，不只信 UI 计时或扩展名。

导入时先有限读取头部/元数据并试解码，不一次把大文件全部解成内存 PCM。文件类型与编码不符、截断、不支持格式给出错误；不通过改后缀假装转换。

### 8. 音轨失效和删除

正文或有效读音哈希变化 → binding.needsReview=true。保留文件，取消它的自动默认资格；用户可在管理页试听并明确“确认仍适用”，更新适用哈希。改标题/译文/收藏不使录音失效。

删除绑定不必立即删除物理文件；仅当无其他引用且无导出/播放租约时回收。移除标准音轨的 UI 选择不是删除安装包资源。相同字节哈希可共享文件，但每条逻辑音轨的名字、来源和目标关系仍独立。

### 9. 分享与验收

分享单独音频前确认选择的是用户允许分享的素材；分享学习包则列出实际包含音轨。内容包不夹带其他录音、设置或搜索记录。系统分享只能确认已调起交互，不能保证对方已接收。[S07](#doc-27)

测试录制真实可听语音、暂停/停止能力边界、快速连点、权限拒绝、中断、后台、耳机路由、锁屏、删除引用、跨平台播放。静音测试文件只能验证容器，不计为“发音正确”或“真人录音完成”。本包未提供虚构的正式教学音频。

## 12 · 文本导入、编辑、草稿与修改关联

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 首版格式

手工输入、粘贴、TXT、`.hanpack`。TXT 支持严格 UTF-8、UTF-8 BOM、带 BOM 的 UTF-16 LE/BE。无 BOM 且不是合法 UTF-8 的文本返回编码提示，保留文件引用供用户重选；不使用自动替换字符吞掉乱码。

首版不解析 Word、PDF、图片或 HTML，不执行 Markdown/脚本。导入的任何“指令”都只是教学原文，开发 Agent 也不能把样例内容当成更高优先级指令。

文本文件 ≤1 MiB；正文单篇/全部 textUnits 合计 ≤20,000 文本元素；词条头部默认 ≤64 元素；标题 ≤120 元素；例句最多 20 条。上限是产品保护值，超限拒绝并说明，不静默截取。

### 2. 流读取与原文保持

系统文件结果通过流读取，不长期保存临时授权路径。MAUI 文档明确 FullPath 不总是物理文件路径，Android 可能返回 content URI；使用 OpenReadAsync 等流接口。[S05](#doc-27)

读取时累积实际字节并限制容量；先识别 BOM，再用严格解码器。保留原始 LF/CRLF、空行、标点、组合字符和繁体字。移除编码 BOM 属于解码，不把它当正文可见字符；其他内容不静默清洗。

可以提供显式“整理空行/简繁转换”的未来工具，但首版不在导入过程中自动做这些事。保存后能精确重建用户在预览中确认的正文。

### 3. 编辑器状态

`New → EditingText → Annotating → Reviewing → Saving → Saved`。任意工作状态都可产生 Draft；注音失败返回 Reviewing/EditingText 并保留原文，不删除草稿。

草稿保存包含 draftId、baseContentId、baseRowRevision、输入文本、已生成注音、人工锁定项、未提交音频引用和当前步骤。草稿的音频存 draft 目录，不进入正式资产引用集合。退出时可保存草稿，启动恢复先检查文件存在和可解码性。

默认输入结束后 1 秒保存草稿，或在页面切换/生命周期事件尽力保存；这是工程目标，不保证操作系统强杀前最后一毫秒输入都持久。界面可提示最后保存状态，正式“保存成功”必须来自真实事务完成。

### 4. 保存验证顺序

类型和标题 → 总字数/字节 → 原文有效性 → token/segment 覆盖 → 拼音格式/范围 → 分类一致性 → 音轨引用 → 版本冲突 → 原子持久化。

正文为空白不能保存正式内容；只有标点不能生成可播放片段，可作为草稿保留。未确认的字音允许保存个人学习内容，但保留显著待复核状态；不能自动设置 confirmed。

内置数据编辑：先复制为 personal，生成新 contentId/内部 unit/segment/token ID，保留来源引用。个人录音不自动复制全部内置资产，先按授权与绑定规则确认。

### 5. 自动注音与人工改音

生成前保留全文上下文及字典版本。分段用于布局和播放，不能先丢弃上下文再假装词组消歧完整。性能处理可按安全区块执行，但要保持正确短语跨边界匹配窗口和原文位置。

每次改音更新草稿状态，正式保存后刷新搜索与读音哈希。选候选与手工输入同等可保存；数字调输入转换成带调 display。再次自动注音只处理未锁定内容，全部覆盖必须独立确认。

### 6. 修改影响矩阵

| 修改 | 校正保留 | 分段/译文 | 音频 |
|---|---|---|---|
| 只改标题/标签 | 全保留 | 不动 | 不失效 |
| 只改译文 | 全保留 | 仅该译文 | 不失效 |
| 只改一个音 | 保留其他 | 不改边界 | 对应 unit 和包含该 token 的 segment 复核 |
| 前方插字，后文唯一不变 | 映射成功的保留 | 未变片段保留 ID | 不受影响目标保留 |
| 替换某一句 | 改动范围重新处理 | 该段译文需复核 | 该段及整篇音轨复核 |
| 拆段/并段 | 未变 token 可保留 | 片段关系和译文需复核 | 原段音轨不自动套入新段 |
| 重复文本无法唯一匹配 | 不自动搬移有歧义校正 | 展示差异预览 | 有歧义绑定需复核 |

整篇音轨适用整个 body unit，因此正文任一部分变动都会影响它；单段音轨只随相关 segment 变化。只改某例句不影响词语头部音轨。

### 7. 差异匹配算法建议

以文本元素数组做有界 diff，先确认未改前后缀，再处理改动窗口。对于重复文本，使用上下文及稳定编辑操作记录判断；无法唯一映射就返回需要用户复核，不能按“第一个同样文本”硬匹配。

大型替换不要运行不可控的 O(n²) diff；达到算法资源上限则回退为“该范围重新注音并复核绑定”的透明结果，保留旧版本草稿以便比较。性能回退不能悄悄丢掉旧人工校正。

### 8. 保存与并发

提交传 expectedRowRevision；仓储内验证后同时写 canonical JSON、投影、搜索索引、音轨失效和草稿完成标志。若其他流程已更新资料，返回 REVISION_CONFLICT，保留草稿并提供比较/另存新内容路径。

开始保存后防重复提交；成功后导航到相应详情，并可从“我的内容”查到；失败不关闭编辑器。没有音频的内容可成功保存，不强制用户授权麦克风。

### 9. 取消、恢复和备份

取消文件选择不产生空内容。取消自动注音保留输入与已有人工修改。丢弃草稿只删除草稿及其独占临时文件，不删除旧正式版本。

完整备份覆盖所有正式保存的用户内容和音频；未保存草稿不悄悄混入。导出前检测草稿与正在录音，提示先保存或明确排除；“完整”仅指已保存正式数据，预览中必须说明这一边界。

## 13 · 收藏夹、设置与本地数据管理

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 收藏对象与唯一性

word/text/poem 都可收藏；每个 word ID 已对应明确音义项。收藏存稳定内容引用，不复制一份日后无法同步的正文。快照只用于备份与缺失内容恢复。

一个内容可出现在多个夹，同一 `(folderId,contentId)` 只能出现一次。收藏选择器一次提交最终所属夹集合：新加入的插入，取消的删除，未变的不动；事务失败整体保持旧集合。

### 2. 收藏夹规则

名称 trim 后 1—40 文本元素；说明默认 ≤300 元素。普通夹名称使用统一 nameKey，大小写和 Unicode 规范化后的同名不允许。系统默认夹以 `systemRole=default` 标识，唯一、不可删除，显示名按 UI 语言生成；不能把中文显示名当身份。

普通夹可新建、重命名、改说明、排序、删除。排序持久化为整数并定期事务内重排，不依赖创建时间或操作系统文件顺序。支持拖动和上移/下移两种路径。

### 3. 删除语义

删除收藏夹只删除夹与关系。移除收藏只删除关系。删除个人内容才影响正文及相关收藏，并在确认前列出受影响数量。音频物理文件按全库引用和租约回收，不能直接递归删除以正文标题命名的文件夹。

内置内容正常不可由普通删除入口删除；不喜欢的内容取消收藏或用来源/分类筛选。未来增加隐藏功能需独立字段，不能删除 catalog 主数据。

### 4. 缺失内容处理

先用稳定 ID 解析本地内容；目录版本变化时按快照/映射恢复可读数据。无法恢复显示“内容暂不可用”和来源，不出现空白详情，不悄悄删收藏。

有用户音轨绑定的内置内容即使未收藏，也属于备份依赖集合。备份不能只遍历收藏夹而漏掉“没收藏但录了跟读音频”的目标。

### 5. 可迁移设置

| 设置键 | 默认值 | 恢复规则 |
|---|---|---|
| uiLanguage | 首次系统映射 | 合并默认保留本机；替换应用备份值 |
| reading.showPinyin | true | 即时刷新 |
| reading.fontSize | 24，允许 18—40 | 非法值拒绝/兼容迁移，不静默溢出 |
| audio.policy | localWithSystemFallback | 可改 localOnly，不启用云服务 |
| audio.preferredLocale | 普通话偏好，如 zh-CN | 目标设备重新查找可用声音 |
| favorites.lastFolderId | 默认夹 | 恢复后按 ID 映射；不存在回默认夹 |

设备 voiceId、临时路径、麦克风权限结果、缓存大小、窗口句柄不能作为可迁移设置。UI 的字号是应用偏好，仍需叠加系统字体缩放。

### 6. 设置保存一致性

数据库为主，Preferences 若使用只是启动缓存。修改成功后发通知更新 UI，失败回滚控件值并说明。恢复后重新从数据库加载，不让旧 Preferences 覆盖新备份设置。

切换语言不触发正文版本、音频哈希或索引重建。lastFolderId 的失效不能让收藏弹层无法打开；只回默认夹并记录非敏感诊断。

### 7. 存储页

分别统计：正式个人内容、用户音频、内置目录/音频、草稿、可清缓存、临时导出包。异步计算可取消，不通过 UI 线程遍历大量文件。

“清理缓存”仅清可重建的布局/索引临时副本和过期分享临时文件；不清正式用户录音、草稿或安全备份。删除草稿和删除本地安全备份用单独明确入口。

首版不提供一键“清空全部数据”作为解决问题的默认方法。若以后增加重置必须二次确认、先备份、说明卸载与系统备份边界。

### 8. 备份偏好边界

完整备份默认带全部已保存用户录音，不设置容易误点的默认排除音频。可显示“不含安装包自带音频；这些在相应应用版本中提供”，缺失版本时明确告知。

内容分享不带设置。合并完整备份默认不改本机语言/字号；新安装可在预览页推荐勾选“应用设置”，但仍显示选择。替换恢复使用备份可迁移设置并重映射文件夹和声音偏好。

### 9. 测试

重复添加、同名不同 Unicode 组合名、三语言默认夹、重启排序、删除夹不删音频、多夹移除、删除个人内容关联清理、失效 lastFolderId、设置写入失败与合并/替换差异都要覆盖。数据库去重与 UI 防连点同时存在，不能只靠前端按钮禁用实现唯一性。

## 14 · 内容包、备份包与格式协议

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 版本与包类型

文档包 v2.0 不等于协议 v2。当前定义的是首份可执行草案 `schemaVersion=1`；旧文档示意 JSON 不是已经发行的互通协议，不直接作为合法导入样例。若实际已有发布数据，必须先调查真实格式再制定迁移，不能按本草案覆盖它。

`.hanpack`：packageType=content，分享选中学习内容。`.hanbackup`：packageType=backup，迁移已保存个人资料。二者都是 ZIP 容器；扩展名仅帮助系统识别，真实类型由校验后的 manifest 决定。选择器不支持自定义后缀时允许 .zip 回退。

### 2. 目录和文件白名单

```text
manifest.json               必需
contents.json               必需，ContentDocument 数组封装
collections.json            仅 backup 必需
settings.json               仅 backup 必需
audio/index.json            必需，可为空资产与绑定集合
audio/<sha256>.<wav|mp3|m4a>  按实际打包音频出现
```

不写显式目录 entry，不带 SQLite 原库、缓存、日志、原设备路径、可执行文件或隐藏控制文件。content 包出现 settings/collections 必须拒绝，而不是自动应用其中数据。所有实际文件（除 manifest）必须恰好在 files 清单出现一次；清单之外的文件也拒绝。

UTF-8 JSON，禁止重复属性名、NaN、Infinity、注释和尾逗号；整数限制到字段约定范围。属性名为协议定义的 ASCII 键。样例与 JSON Schema 见 `specs/*.schema.json` 与 `examples/`。

### 3. manifest 字段

| 字段 | 规则 |
|---|---|
| schemaVersion | 整数 1；不认识的版本在写入前拒绝 |
| packageType | content / backup |
| packageId | UUID，本次导出身份 |
| createdAtUtc | UTC ISO 8601 |
| producerAppVersion | 来源说明，不作为兼容版本比较的唯一依据 |
| contentCatalogVersion | 可空，记录目录来源 |
| counts | contents / folders / favorites / audioAssets / audioBindings |
| files | path、byteLength、sha256；不包含 manifest 自身 |
| warnings | 结构化 code 与 message；导出前已知不完整说明 |

manifest 自身最大 1 MiB。files.byteLength 和哈希用实际内容验证，不只相信 ZIP header。计数与解析实体实际数量不符为错误，不能只显示 header 上好看的数字。

### 4. contents.json

外层 `{schemaVersion:1, contents:[...]}`。每篇内容按文档 07；unit/segment/token ID 在包内全局唯一，所有 tokenIds 指向同一 unit 中已有 token。body/headword 数量与 kind 匹配，原文范围与注音冗余字段一致。

打包内置收藏依赖时用 builtinSnapshot，保留来源目录 ID/版本和原始稳定 ID；接收端不得把它当成可覆盖本机 catalog 的授权。未收藏但有用户录音绑定的内置目标，也必须提供可恢复文本与注音依赖。

用户分享 selected 内容以它们的完整必要文本/注音单元为闭包；首版不做任意字符片段包，避免丢掉上下文和音频目标。只分享某段音频可使用单音频文件入口。

### 5. audio/index.json

外层包含 `schemaVersion`、`assets`、`bindings`、`preferences`。资产至少有 id、origin、storage、sha256、byteLength、durationMs、container、codec、sampleRate、channels、path、catalogRef。

| storage | path | 含义 |
|---|---|---|
| package | `audio/<sha256>.<ext>` | 字节确实包含在包中，必须完整校验 |
| catalogRef | null | 只引用某版本内置音频；catalogRef 必须非空 |

用户资产在完整备份中必须 storage=package；不允许只有旧设备路径或“以后下载”的占位。内容包可不包含未选音轨，但必须删除其 binding/preference 并在预览说明，不留下悬空引用。

Binding 包含 id、targetId、assetId、boundTextHash、boundPronunciationHash、reviewState、sourceRole、label。Preference 为 targetId→bindingId；引用必须属于相同目标。目标可在 contents 或明确目录引用中解析；需要目录快照的关系不可只留下裸 ID。

相同 SHA-256 可被多个逻辑关系使用，物理文件只打包一次。asset.byteLength/path 与 manifest 同一文件记录一致。catalogRef 未在目标设备找到时属于已声明的可用性警告，不当作丢失“本来应有的包内音频”；声称 package 的文件缺失则致命拒绝。

### 6. collections 与 settings

collections 封装 folders 和 items；folder 包含 id/name/description/sortOrder/systemRole；item 包含 folderId/contentId/sortOrder/addedAtUtc。默认夹使用 systemRole，不依赖显示语言。重复关系不算两个收藏；导出器应去重，验证器拒绝歧义重复记录。

settings 只包含可迁移设置，字段以文档 13 和 schema 为准。合并时是否应用设置是导入计划选项，不由外来包强制决定。权限、设备 voiceId、绝对路径不在 schema 内。

### 7. 哈希与规范化 H1

文件哈希为文件原始字节 SHA-256。正文哈希为 target 原文的 UTF-8 字节 SHA-256。它们不先做简繁、换行或 Unicode 正规化。

语义比较使用项目规范 JSON `H1`：对象 ASCII 属性按 ordinal 排序；数组保留领域顺序（集合字段 scenes 在输出前按 ordinal 排序并去重）；无无效 Unicode、无浮点；整数十进制无多余前导零；UTF-8 无 BOM、无空白分隔；字符串仅转义引号、反斜杠、控制字符，常用控制符用 `\b\t\n\f\r`，其他 U+0000—001F 用小写十六进制 `\u00xx`，非 ASCII 字符原样编码。

contentFingerprint 对 ContentDocument 去除根 createdAtUtc/updatedAtUtc、三个 revision 计数，以及 token 的修改时间后计算；保留正文、拼音、锁定状态、译文、分类、稳定 ID 与来源信息。相同 ID 但标题/译文等语义不同也按冲突保留双方，避免合并时丢修改。

pronunciationHash 对目标相对位置的 `[start,length,base,tone,erhua]` 数组计算；未知项使用 null；标点没有虚构音节。锁定状态、注音来源和时间不进入读音哈希。

packageFingerprint 对规范化 manifest（files 按 path 排序）计算。重新压缩但 manifest/有效载荷一致可视为同一包；archiveSha256 另作诊断。哈希证明一致性，**不证明作者身份、版权授权或文件可信来源**。

### 8. 校验顺序

文件实际大小 → ZIP 结构/entry 数/路径 → 唯一且限长 manifest → 类型与版本 → 严格 JSON 与 schema → 流式累计解压字节/单文件哈希 → 实体数量 → 字音范围 → 所有外键 → 权限边界 → 构造只读导入计划。

JSON Schema 只校验结构和部分约束，不能代替跨引用、哈希、范围还原、文件流配额和音频解码检查。使用 Draft 2020-12；日期/UUID format 需验证器明确开启，不以注解存在就认为已验证。[S22](#doc-27)

### 9. 不可信包安全规则

路径只接受规定固定文件和应用生成的 ASCII 音频路径。拒绝绝对路径、盘符、`..`、反斜杠、空路径段、冒号、符号链接、重复路径、大小写碰撞、NUL、路径尾随点空格和非白名单文件。先查 entry 再解压，不能解压到正式目录后才发现穿越。

容量集中在 `specs/limits.json`：包 ≤512 MiB、展开 ≤1 GiB、≤10,000 entries、单 JSON ≤64 MiB、深度≤32、单音频≤100 MiB。解压流实时计量，ZIP 头部的大小可能不可信。超过上限停止并删除本次暂存，不影响正式数据。

全库大于当前备份保护上限时，不允许静默排除音频或分成多个文件后仍称单文件完整备份；预检报告容量冲突，由产品选择经验证提高上限或减少资料。上限是需要容量规划的默认方案。

### 10. 兼容和样例地位

未知 schemaVersion 默认拒绝并说明需要更高兼容版本；不尝试“能 parse 几个字段就导入”。将来增加兼容迁移时以 fixtures + 迁移函数逐版测试。

本包的示例 `.hanpack/.hanbackup` 仅验证协议容器、数据结构和哈希，不含正式教学音频，也不证明尚未实现的应用已经能导入。样例 source.reviewStatus 为 draft，不是教材授权或人工审核记录。

## 15 · 备份、恢复、冲突与崩溃一致性

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 完整备份集合

包含：所有已保存个人内容及其人工校正；全部用户音频与音轨选择；全部收藏夹和收藏；可迁移设置；收藏或用户音轨依赖的内置正文/注音快照；当前关联仍需复核的用户音轨。未保存草稿、正在录制的流、临时缓存不悄悄算作已备份，预览必须显示排除项。

安装包自带音频可作为 catalogRef，不重复整套应用资源。目标设备缺少对应音频版本时保留可读快照并提示，不声称全文音频无损恢复。需要“完全不依赖目标安装包的所有内置音频备份”是额外授权/容量需求，不冒充首版已覆盖。

### 2. 导出一致性步骤

1. 检查无正在写入的录音，提醒保存草稿；估算大小与剩余空间。
2. 获取数据快照和对应音频文件租约；抓取关系闭包和设置版本。
3. 读取不可变正式文件生成导出临时包；可进度/取消，逐文件计算哈希。
4. 写 manifest，关闭 ZIP，重新执行包校验。
5. 调用系统保存或分享；根据真实结果反馈。用户取消保存不是成功。
6. 释放租约；临时分享文件保留到安全期限或可确认不再使用，再清理。

不能直接复制正在使用的 SQLite 主文件作为可靠备份，尤其不能漏掉 WAL 相关状态。首版采用逻辑导出，SQLite 快照与文件租约由仓储协调。

### 3. 导入计划不等于执行

预检输出不可变 ImportPlan：包指纹、所有 ID 映射、新增/复用/派生统计、缺失目录音频、设置应用选项、目标数据 rowRevision/epoch、将删除项（替换）、需要写入的文件及空间需求。

计划预览后数据如果变化，执行前重新检查 epoch，必要时返回 PLAN_STALE 重算，不能使用旧冲突计数直接覆盖新资料。用户更换包或模式必须重新生成计划。

### 4. 合并规则

| 情况 | 默认处理 |
|---|---|
| 同 packageId + 同 packageFingerprint | 幂等复用；允许 ZIP 重压缩而语义清单不变 |
| 同 packageId + 不同 fingerprint | 拒绝 PACKAGE_ID_COLLISION，不把改过的包当旧包 |
| 同 contentId + 相同语义指纹 | 复用本机数据与内部目标 ID |
| 同 contentId + 不同语义指纹 | 保留本机，导入为新 ID 的个人/快照版本 |
| 新 contentId | 新建；内部 ID 同样检查冲突 |
| 同 folderId | 合并成员去重，保留本机名称/说明/排序并列出警告 |
| 不同 folderId + 同 nameKey | 保留双方；导入名加 `(导入)`、`(导入 2)` 等稳定后缀 |
| systemRole=default | 映射到本机唯一默认夹 |
| 音频 SHA-256 相同 | 复用物理文件；逻辑关系按映射保留 |
| 默认音轨冲突 | 已有本机选择优先，导入音轨仍可在管理页选择 |
| 设置冲突 | 合并默认保留本机；用户明确勾选才应用 |

不根据设备时间较新就自动覆盖。不同 contentId 即使汉字相同也不自动合并，它们可能是不同读音/义项。内容标题/分类/译文不同同样保留双方，避免只比较正文而丢掉用户编辑。

### 5. 全图 ID 重映射

冲突派生内容必须生成新的 content、unit、segment、token ID，不能只换根 ID 后让播放目标冲突。完整映射覆盖：tokenIds、音轨 targetId、音轨默认选择、收藏 contentId、内部例句关系和必要来源链接。

ImportMapping 记录源实体类型、源 ID、源语义指纹、目标本地 ID，并与提交结果同时入库。重复导入同一冲突包先查映射，不再新建第二个“导入副本”。导入中断但没提交时不留下“已导入”的 receipt。

多个包携带同一源 ID/同一语义数据可复用既有映射；同源 ID 数据变了则产生新的派生版本。外部包的“审核通过/内置”标记仅作来源声明，不赋予覆盖本机 catalog 权限。

### 6. 内置目录版本差异

本机内置内容 ID 与快照语义一致可复用；不一致默认保留快照为只读历史版本，记录源 catalog ID/版本并映射收藏/音频到该版本，避免把旧录音直接套到新正文。用户可主动切换到新目录版本，但不能在恢复中静默替换文字。

若用户想修改快照，复制为 personal。目录后续升级不删除仍被用户引用的快照。目录音频不存在时显示缺失；用户 package 音频缺失是包损坏，提交前拒绝。

### 7. 替换恢复

仅 backup 支持。含义是**替换已保存用户资料**，不是卸载应用、删除内置目录或改系统权限。先列出被替换的个人内容、收藏和音轨数量；二次确认后生成且校验本机安全备份，失败禁止继续。

取得维护门后将“删除现有用户关系/资料、写入恢复资料、映射设置、建立 receipt”放入同一数据库事务。数据文件先准备好，旧不可变音频在提交前不删除。新的默认夹与关联一次提交，避免短暂暴露无默认夹状态。

存在未保存草稿时先让用户保存/丢弃/取消恢复；不在后台清掉草稿。正在播放/录音时先按明确规则停止，不能与替换操作并发引用将被删除的目标。

### 8. 数据库与文件系统协议

| 阶段 | 已做的事 | 中断后的恢复 |
|---|---|---|
| Preparing | 私有 staging，解析/校验/计划 | 删除无正式引用的暂存 |
| FilesReady | 已校验新音频安装为不可变文件，持有操作标记 | 旧数据库仍有效；新孤立文件待 GC |
| Committing | 单个 SQLite 事务写关系与 receipt | 由数据库提交/回滚结果决定 |
| Committed | receipt 与正式数据同事务可见 | 数据已成功，不能按外部旧日志误回滚 |
| Cleaning | 清暂存、释放租约、排队 GC | 幂等重复清理 |

外部操作日志只帮助恢复，不作为“是否已提交”的唯一证据。启动时先查数据库 receipt/operationId：有 committed 记录就完成清理；没有且事务已回滚则保持旧数据并清孤立新文件。不能因写日志失败而删除已成功导入的内容。

每次操作使用唯一 staging 目录，文件拷贝采用临时名→关闭/校验→同文件系统改名；跨卷移动不假定原子。正式文件不覆盖同名不同哈希文件，已有哈希相同文件先核对再复用。

### 9. 取消与空间

校验、复制、压缩阶段可取消。进入短暂数据库提交阶段后停止接收取消，完成一个完整提交或回滚，并在 UI 说明正在完成保存。用户误点多次不启动并发恢复。

剩余空间预算至少覆盖暂存包/展开内容、新音频、安全备份、数据库/WAL 增长和余量；数值由实际文件估算。恢复过程中空间不足，旧数据仍可用；不得先删旧音频腾空间再发现新包损坏。

### 10. GC 与安全备份保留

GC 查数据库实际引用、草稿引用、播放/导出租约与操作保护标记；只有无引用且超过保护期才删除。首版保留最近 3 份本地安全备份为默认，但删除前展示体积，受磁盘压力时先通知；不能以后台清理误删唯一可回滚副本。

安全备份仍含私人文本与声音，默认未加密且只在应用私有区保存。系统是否备份该目录需发行阶段核查，不把私有路径等同于跨设备绝对保密。

### 11. 必测故障注入

在解压前、音频复制中、文件安装后/数据库前、事务中、事务提交后/日志前、清理阶段分别模拟进程终止与磁盘满。检查旧/新数据完整性、receipt、孤立文件、收藏引用、人工校正、默认音轨和索引。

跨平台执行 Android↔iOS、Android↔Windows、iOS↔Windows 六个方向。只有 JSON 相同不够，还要实际试听用户音频、检查语音偏好重匹配和平台保存/选择流程。

## 16 · 教学内容、音频素材与来源治理

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 内容不是程序占位数据

正式内容和开发样例分开目录/版本。页面能显示不等于拼音、译文与录音已经审核。AI 可以起草词条、例句、翻译和元数据，但不能写入虚构审校人、授权号、真人音频或“官方教材认证”。

本包所有语言样例均为开发草稿；除明确说明的容器验证外，没有人工教学审核结果，也没有正式教学录音。程序在正式构建中不能把 testFixture 自动提升为 published。

### 2. 初始内容计划

| 资源 | M1 技术样例目标 | 首版正式目标（可调整） |
|---|---|---|
| 词条 | 12 个，包含不同字数、轻声、多音字、ü | 100 个；每条原则上两条例句 |
| 课文 | 1 篇原创短文 | 6 篇短文，场景/难度明确 |
| 诗词 | 1 个来源明确的分行样例 | 6 首，正文与读音逐项校对 |
| 拼音表 | 完整条目结构、重点交互样例 | 完整教学清单、示范音频、四声例词可用性矩阵 |
| 日英译文 | 足够覆盖语言规则 | 正式发布词条/句段满足预期译文覆盖 |
| 音频 | 验证真实播放与录音的小样本 | 拼音专用示范必须齐全；正文音轨按实际音源清单说明 |

以上数量不是已经完成的内容资产。正文可按已确认标准录音/TTS 回退规则播放；如果宣传“全套真人离线朗读”，必须另外准备并审核完整对应音频，不能用系统 TTS 顶替宣传。

### 3. 分类体系

场景初始建议为问候、日常、家庭、学校、饮食、交通、购物、工作。难度为入门、基础、进阶、高级；学段/年级为另一套标签，空值表示未标注。不依据字数自动断言某词属于小学或某套教材。

分类 ID 使用稳定 ASCII code；标签由 UI 资源翻译。内容可以多个场景，难度默认单值，学段/年级按一致性规则校验。后续更名不改分类 ID。

### 4. 拼音教学目录

声母、y/w 拼写辅助项、单韵母、复韵母/特殊韵母、前后鼻韵母、整体认读音节按上一版建议编排，正式发布前统一教学口径。不要混合多套教材分类后仍宣称完全标准。

每项需要：稳定 ID、分组、拼写、说明、示范音频、四声例词列表、每个例词的目标 token 与高亮范围、缺例词原因。声母示范采用已选教学读法录制，不能用英语字母名替代。

例词必须真实且适合学习。四声不完整的项保留缺失说明；声母本身不是能直接加四调的完整音节。轻声解释单独放置，不占四声行位。

### 5. 审核流水线

来源/原创登记 → 中文正文与释义 → 拼音和多音字 → 日译 → 英译 → 音频 → 音文一致性 → 格式/交互校验 → 发布。

各维度独立状态：draft / needsReview / approved / rejected / missing。发布要求由内容类型决定，例如拼音教学项必须音频 approved；个人导入内容允许 draft，但不能带官方认证标志。

审核记录保存资源 ID、版本、审核维度、真实审核者、日期、问题和结论。表单见 `templates/CONTENT_REVIEW.md`。没有审核者就留待审状态，不填 AI 伪造的人名。

### 6. 文本与音频对应

录音脚本使用明确 contentId/unitId/segmentId 和正文/读音哈希。音频录制时记录读法、语言、说话者或提供方、实际格式、来源与可使用范围。音频替换不改变正文身份，但更新资产哈希和绑定。

耳化、轻声和自然连读需用同一教学口径核对；本调显示与自然变调发音的差异可以说明，但不能用该理由掩盖真正多音字读错。只对已有事实标“真人录音”，合成音标明合成来源。

### 7. 许可和分发边界

文本、现代译文、注释、音频、字体、字音词典数据分别登记来源与许可。仓库许可证与其合并的上游数据并不自动构成所有具体分发用途的结论；须核对具体文件与来源。[S14a / S14b](#doc-27)

产品策略默认只有明确允许的资源可出现在分享包；私有备份所需文字快照也应在内置内容选型时纳入授权范围。不要先收录不能满足迁移要求的素材，再在备份时静默丢掉依赖。

来源表保存 `sourceId / assetKind / title / authorProvider / sourceReference / licenseIdentifier / permissionNotes / canDistribute / canShare / backupPolicy / reviewStatus`。本包是工程治理建议，不代替具体发行地区和资料的授权判断。

### 8. 目录打包与升级

内容源在版本控制中维护，构建脚本输出只读 catalog 及索引种子，附文件哈希、schema 和目录版本。正式构建拦截缺源、缺审批、坏范围、错拼音格式和拼音示范缺音频。

升级保持稳定内容 ID；纠错更新 revision；用户复制版本不被覆盖。目录删除已被收藏/用户音频依赖的内容时保留必要快照。对新增字典或修音规则建立回归样例，避免一次修正另一批词条变错。

### 9. 发布统计

分别统计：已审核词条数、已审核例句数、课文/诗词数、ja/en 译文覆盖、拼音项示范音频覆盖、四声例词缺口、正文录音覆盖、来源待核项。不得把草稿计入“已完成资源”。

建议用 `tracking/content-inventory.csv` 管理素材。当前文件是待填清单结构与真实样例状态，不代表正式内容生产完成。

## 17 · 隐私、安全与错误处理

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 隐私设计基线

应用首版不主动上传正文、搜索词、收藏、拼音校正、个人译文或录音到开发者服务器、云 TTS 或 LLM。没有账户不代表没有需要保护的数据：用户声音、个人文本和备份同样需要明确操作边界。

系统 TTS 由设备语音提供方实现，系统备份和用户选择的分享应用有各自行为。隐私说明必须区分“本应用没有上传接口”和“整个设备绝对不联网”。严格不调用系统合成时使用 localOnly 音频策略。

麦克风仅在用户发起录音时开启，界面显示状态与时长；进入后台不静默继续录音。使用文件选择器只读取用户明确选定的文件，不遍历无关私人目录。

### 2. 数据流和边界

| 输入/输出 | 信任级别 | 处理 |
|---|---|---|
| 用户输入/TXT | 不可信文本 | 限额、严格解码、按纯文本展示 |
| 外部 hanpack/backup | 不可信结构和文件 | 路径、schema、引用、哈希、容量与权限校验 |
| 导入音频 | 不可信二进制 | 有界探测、实际解码、隔离暂存 |
| 自带审核目录 | 应用发行源 | 版本/哈希验证；普通导入不能冒充 |
| 系统 TTS | 外部平台能力 | 用户可关闭；不承诺所有语音离线 |
| 系统分享 | 用户主动外发 | 预览范围，私有数据不默认夹带 |
| 导出备份 | 含私人数据的普通文件 | 明确未加密，不作保密保证 |

自带资源可信只指来源渠道；内容本身仍需教学质量校对，不能以“在安装包中”代替读音审核。

### 3. 文件和权限最小化

只用应用私有目录存正式资料；系统文件交互通过选定文件的流。Android 文档选择框可基于 Storage Access Framework 授予用户选中文件访问，不默认索取全盘权限；具体 MAUI 包与系统版本仍按 M0 验证。[S16](#doc-27)

系统分享目录与数据库/完整缓存目录分开，Android FileProvider 只暴露专用导出子目录。MAUI 分享文档提醒不当的路径配置可能暴露更大范围文件；不可直接共享整个 AppData/Cache。[S07](#doc-27)

不申请摄像头、通讯录、定位或照片权限来完成本项目不需要的功能。平台用途说明按实际麦克风/文件能力填写，不照抄无关示例。

### 4. 日志规则

允许记录 operationId、错误码、阶段、耗时、字节数、实体数量、匿名化的本地诊断标识和版本。不记录完整正文、搜索输入、录音字节、绝对私人文件路径或导出包内容。

异常堆栈存开发/诊断通道并做路径脱敏；普通用户看到简明原因与恢复操作。用户主动导出诊断信息前先预览，默认不含个人内容与媒体。

日志自身按大小轮换，不能磁盘无限增长。哈希也可能用于识别内容，不默认把内容 SHA 上报服务器；首版无诊断上传接口。

### 5. 错误结果约定

正常成功：Success(data)。用户取消：Cancelled，无红色失败提示和错误日志。业务/平台失败：Failure(code, safeMessageKey, retryable, context)。UI 根据 code 本地化，不把 Exception.Message 直接当跨语言文案。

| 错误码 | 用户可见含义 | 数据保护 |
|---|---|---|
| CONTENT_NOT_FOUND | 内容已不存在或暂不可用 | 不建悬空收藏 |
| REVISION_CONFLICT | 内容已被其他操作更新 | 保留草稿，不覆盖 |
| TEXT_ENCODING_UNSUPPORTED | 当前编码不支持 | 原文件不动 |
| TEXT_INVALID_ENCODING | 文本解码失败 | 不替换成乱码后保存 |
| TEXT_LIMIT_EXCEEDED | 文字或文件超过当前上限 | 不截断 |
| TEXT_BOUNDARY_MISMATCH | 字符边界与保存注音不一致 | 不移动校正后强行导入 |
| PINYIN_INVALID | 拼音/声调格式不合法 | 保留输入待修改 |
| AUDIO_PERMISSION_DENIED | 未获麦克风权限 | 仍可阅读编辑 |
| RECORDING_BUSY | 录音中，需先停止 | 不丢弃正在录制的内容 |
| AUDIO_UNAVAILABLE | 当前没有适用音源 | 不读成错误语言 |
| AUDIO_STALE | 音频与修改后的文字/读音待核对 | 保留文件，禁止静默默认使用 |
| AUDIO_FORMAT_UNSUPPORTED | 此编码不能播放 | 不改后缀伪装转换 |
| AUDIO_DECODE_FAILED | 音频损坏或解码失败 | 暂存清理，正式资产不提交 |
| PACKAGE_VERSION_UNSUPPORTED | 包版本不支持 | 写入前停止 |
| PACKAGE_TYPE_MISMATCH | 文件内容与所选导入操作不符 | 不应用分享包的设置 |
| PACKAGE_PATH_UNSAFE | 包含不安全路径 | 不解压到正式目录 |
| PACKAGE_DUPLICATE_ENTRY | 包内有重复/歧义文件名 | 拒绝 |
| PACKAGE_JSON_DUPLICATE_KEY | JSON 字段重复 | 拒绝不同解析器歧义 |
| PACKAGE_HASH_MISMATCH | 包内文件校验失败 | 旧数据不变 |
| PACKAGE_REFERENCE_MISSING | 目标/音频引用缺失 | 不提交悬空关系 |
| PACKAGE_LIMIT_EXCEEDED | 包容量/深度/条目超限 | 流式停止 |
| PACKAGE_ID_COLLISION | 同包 ID 对应不同清单 | 不覆盖旧 receipt |
| PLAN_STALE | 预览后本机数据已变化 | 重新规划 |
| STORAGE_FULL | 空间不足 | 先保留旧数据与草稿 |
| DB_MIGRATION_FAILED | 数据升级未完成 | 不清库重建 |
| DB_WRITE_FAILED | 保存失败 | 事务回滚，保留输入 |

更底层未知异常映射为 UNEXPECTED_ERROR 并提供 operationId；不对未知情况自动重试破坏性动作。

### 6. 威胁用例

恶意 ZIP 路径、大小写重名、压缩炸弹、超深 JSON、重复属性、伪装 MIME、异常 WAV/MP3、包 ID 欺骗、内置身份伪造、半恢复、默认音轨跨目标引用、共享目录泄露均需要负例测试。

SHA-256 不是数字签名。首版不声称验证作者身份；外部内容自称 approved 不授予官方标志。备份默认无密码加密，不能将后缀隐藏视作加密。

### 7. 发布隐私材料

`templates/PRIVACY_NOTICE_DRAFT.md` 为可填写的应用隐私说明草案，必须按最终依赖、发行主体、联系方式和系统备份策略核对后发布。Apple App Privacy 和 Google Play Data safety 均需根据实际应用及第三方组件行为填写；不因“离线优先”就自动选择所有“不收集”。[S17 / S18](#doc-27)

首版目标包含低龄学习材料，但不自动声明适用于特定儿童专区或满足所有儿童隐私法规。实际目标年龄、发行地区和商店分类由发布前审核决定，不能让 AI 根据“小学标签”自行承诺合规。

## 18 · 服务接口、用例契约与事件

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 说明

以下均为**项目自定义接口设计**，不是 MAUI 或某个 NuGet 现成 API。可以调整类名，但输入、取消、版本、错误和副作用语义不能缺失。实现前先让 Core 中的 DTO 与 schema 一致，再生成页面。

### 2. 通用值与结果

ID 统一 UUID；OperationId/SessionId/QueryId 为操作身份而非内容身份。范围使用 TextRange(start,length) 与所在 TextUnit 的持久化 UTF-16 边界映射。所有时间持久化为 UTC；排序 code 使用 ordinal。

`Result<T>` 为 Success / Cancelled / Failure；Failure 包含稳定 Code、MessageKey、Retryable 和安全诊断上下文。长任务必须接收 CancellationToken；进度用阶段、已处理量、总量可空表达，不伪造百分比。

编辑提交携带 expectedRowRevision；数据维护计划携带 expectedDataEpoch。取消不抛给 UI 当成崩溃；领域验证失败不改变正式数据。

### 3. 内容用例

| 方法建议 | 输入 → 输出 | 关键约束 |
|---|---|---|
| QueryContentsAsync | ContentFilter + PageCursor → Page<ContentSummary> | 同维度 OR、跨维度 AND、稳定分页 |
| GetContentAsync | contentId → ContentSnapshot | 包括 rowRevision，不返回可直接写的仓储对象 |
| CreateDraftAsync | kind + 可选原文 → DraftSnapshot | 分配草稿稳定 ID；不进正式索引 |
| SaveDraftAsync | draftId + expectedDraftRevision + draft → DraftSnapshot | 保留原文/校正/音频临时引用 |
| CommitContentAsync | draftId + expectedRowRevision → ContentSnapshot | 原文、投影、索引、音频复核一次事务 |
| CopyBuiltinToPersonalAsync | contentId → DraftSnapshot | 全图新 ID，保留来源，不改内置 |
| PreviewDeleteContentAsync | contentId → DeleteImpact | 列收藏、音轨、草稿影响 |
| DeletePersonalContentAsync | contentId + expectedRowRevision + confirmationToken → Result | 非内置；安全事务；GC 延后 |

DeleteImpact 不是持续有效授权；数据变化后必须重算，确认 token 绑定实体与版本，避免确认甲却删除乙。

### 4. 拼音与分段

| 方法建议 | 契约 |
|---|---|
| AnnotateAsync(AnnotatedInput, options, token) | 返回完整原文映射、候选与来源；保留有效锁定项 |
| ParsePinyin(input, mode) | 区分 search/edit；无调不是轻声；返回合法性和规范值 |
| FormatSyllable(syllable) | 确定性输出 NFC 带调拼音 |
| ApplyManualCorrection(draft, tokenId, syllable) | 只改当前出现位置；更新锁定和复核关系 |
| SegmentText(text, boundaries, manualOverrides) | 全覆盖、可还原，保留 layout |
| ReconcileTextEdit(old,newText,editOperations) | 返回保留/新建/歧义 ID 映射与受影响音轨，不直接播放 |

注音服务不弹窗、不获取网络、不直接写数据库。校正能否自动映射由 ReconcileReport 明确决定，ViewModel 不能自行绕过“需复核”结果。

### 5. 搜索与收藏

SearchAsync(query, queryId, cursor, token) 返回匹配层级、是否近似、contentId 和当前版本摘要。旧 queryId 由调用者丢弃。RebuildIndexAsync 只从主数据重建，绝不删除主数据。

GetFolderMembershipAsync(contentId) 返回真实所属集合。SetFolderMembershipAsync(contentId, finalFolderIds, expectedMembershipRevision) 一次提交，不逐次网络式模拟增删。Create/Rename/Reorder/DeleteFolder 均验证 systemRole 与名称规范；内容删除不是 FolderRepository 职责。

Settings.UpdateAsync(patch, expectedRevision) 验证允许字段并持久化；触发通知后 UI 再刷新。设备语音枚举不写进可迁移设置 JSON。

### 6. 音频接口

| 方法建议 | 完成语义 |
|---|---|
| ResolveSourceAsync(targetId, mode, policy) | 返回具体适用音源或缺失原因，不启动播放 |
| PlayAsync(targetId, ownerScopeId, mode, token) | 等待自然结束/取消/失败，不只是“已调用播放器” |
| StopAsync(ownerScopeId?) | 确认取消并释放相应活动会话 |
| BeginRecordingAsync(targetId, ownerScopeId) | 权限通过且实际开始录音后返回 sessionId |
| StopRecordingAsync(sessionId) | 完成容器写入，返回 AudioDraft 或失败 |
| SaveRecordingAsync(audioDraftId, targetId, setDefault) | 安装不可变文件并提交绑定 |
| ImportAudioAsync(streamProvider, metadata, targetId, token) | 限额/解码/复制/试听前态；不保存外部绝对路径 |
| ConfirmBindingAsync(bindingId, expectedTargetHashes) | 确认读音仍适用，原子更新哈希和复核状态 |
| SelectBindingAsync(targetId,bindingId) | 必须属于同目标且适用；不自动覆盖标准源 |

平台底层 IAudioPlayerAdapter、IRecorderAdapter、ISystemSpeechAdapter 负责真实设备；协调器拥有业务状态机。平台事件回调携带 sessionId 或由适配器绑定当前会话，防止迟到回调更新新任务。

### 7. 包和文件接口

| 方法建议 | 契约 |
|---|---|
| ValidatePackageAsync(streamProvider, limits, token) | 仅 staging，只读验证结果，正式库不动 |
| PlanImportAsync(validatedPackage, options, token) | 返回 ID 映射、依赖闭包、冲突和 expectedDataEpoch |
| ExecuteImportAsync(planId, token) | 重验包指纹与 epoch；文件/事务协议；提交 receipt |
| ExportBackupAsync(options, token) | 一致快照与租约，返回已校验私有临时文件 |
| ExportContentAsync(selection, options, token) | 白名单选择，不含设置/未选资料 |
| SaveExportToUserLocationAsync(exportHandle) | 返回 Saved / Cancelled / Failed |
| ShareExportAsync(exportHandle) | 仅表示系统交互状态，不保证对方收到 |

Core/Infrastructure 不弹系统窗口：streamProvider 由 App 平台层提供。文件句柄/导出 handle 有生命周期与租约，不在 Share 返回后立即删除仍可能被系统读取的文件。

### 8. 领域通知

ContentChanged(contentId, revisions, changeKind)、ContentDeleted(contentId)、FoldersChanged、SettingsChanged(keys)、LanguageChanged、AudioSessionChanged(sessionSnapshot)、CatalogUpdated、DataRestored(epoch)。通知为进程内轻量机制，不引入远程消息总线。

提交前不广播正式变更；失败不发“成功更新”。接收者依据 ID 局部刷新，取消过期加载；页面释放时取消订阅。DataRestored 使旧详情快照和缓存失效，但必须先处理未保存草稿。

### 9. 示例调用顺序

改拼音：Editor → ApplyManualCorrection → DraftSaved → CommitContent(expectedRevision) → 内容/索引/绑定复核事务 → ContentChanged → 详情刷新。

分享导入：FilePicker → ValidatePackage → PlanImport → 用户确认 → ExecuteImport → 文件安装 → SQLite 提交 receipt → DataRestored/ContentChanged → 结果摘要。

点课文：RubyTextView.SegmentTapped → ReaderVM 更新选中与弹层 → AudioCoordinator.PlayAsync(segmentId) → ResolveSource → 实际播放 → 当前 session 完成状态。禁止 View 直接 new 播放器绕过协调器。

## 19 · 测试策略与验收标准

### 1. 验收层次

测试分为纯逻辑、持久化集成、平台适配、端到端、内容质量五层。Mock 播放器只证明调度正确，不能证明真机发声；JSON Schema 通过只证明部分数据结构，不证明恢复功能已实现；代码编译通过不能替代三平台实际运行。

所有应用用例初始状态为 **NOT RUN**。允许 PASS、FAIL、NOT RUN、BLOCKED 四种结果。BLOCKED 必须写明缺少什么环境/素材，不能当作通过。文档包自检单独记录，不混进应用完成率。

### 2. 测试输入和基准

版本化保留：示例 ContentDocument、文本元素范围、拼音转换表、分段预期、搜索候选、故障包、数据库旧版本快照。测试基准变更要记录原因和审查，不得把实现输出自动写成正确答案。

基础语料覆盖银行/行走、音乐/快乐、轻声、ü、隔音符、长无标点文本、诗行、CRLF、Emoji、组合字符与未知字。词典语料的准确率报告必须说明样本量与人工标注来源；没有基准时不写“准确率 99%”。

### 3. 各层必须验证什么

| 层次 | 核心验证 | 证据 |
|---|---|---|
| 单元 | 标调、规范化、分段守恒、注音锁定、语言选择、状态机 | 测试名称、断言、运行日志 |
| 集成 | SQLite 约束、迁移、索引重建、导入映射、文件回滚 | 临时库、前后快照、测试日志 |
| 平台 | 录音、中文 TTS、文件选择保存、权限、输入法、生命周期 | 设备/系统/构建号、实际操作结果 |
| 端到端 | 导入→改音→录音→收藏→导出→另一平台恢复 | 内容及文件哈希、录屏/试听记录 |
| 内容 | 拼音/例句/译文/示范音频一致性、来源 | 审核表和真实审核者 |

### 4. 跨平台矩阵

iOS→Android、Android→iOS、iOS→Windows、Windows→iOS、Android→Windows、Windows→Android 六个方向分别执行完整备份恢复。另测各平台自身恢复、不同应用版本的支持范围以及相同包重复导入。

每次恢复至少包含：两个收藏夹、一个词条、一个课文、一个人工锁定读音、一条整篇录音和一条片段录音。同一音频多引用、没有内置目录音频、名称冲突、内容 ID 冲突另建测试包。

### 5. 故障注入点

在暂存文件写到一半、哈希验证后、正式音频安装后、数据库事务开始前、事务进行中、COMMIT 后但清理前、收据已提交但外部操作日志未更新时分别终止进程。检查旧数据完整或新数据完整，不能出现“数据库有引用但正式音频不存在”的半成功。

磁盘不足、权限拒绝、系统取消、录音中断、数据库忙、损坏 JSON、过大 ZIP 分别测试。测试失败不得自动清库“修好环境”；先保留失败样本。

### 6. 通过门槛

所有 R01—R16 有对应实现与用例。所有 P0 用例 PASS 后才能声明首版完成；未执行平台验证可以交付阶段成果，但不能声明该平台正式完成。数据丢失、错误覆盖、路径逃逸、静默上传、隐藏录音、错误音源冒充示范均阻断发布。

默认把功能完成率、用例执行率、执行通过率分别展示：未执行不计入通过；一条用例在 Windows PASS 不代表 iOS PASS。性能目标的调整需附设备实测，不通过删除核心内容来达标。

### 7. 用例与原版映射

可执行用例清单见 [29 · 验收用例](#doc-29) 和 `tracking/acceptance-cases.csv`。沿用原版 R01—R16 需求身份，新用例 HM-Txxx 细化旧 A01—A42 的场景；旧编号留在 archive，不要求机械保留一个大用例对应所有异常。

## 20 · 性能、容量与可靠性设计

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 目标的性质

以下为首轮工程目标，不是本次文档生成时的实测成绩。M0 记录参考 Android 手机、iPhone 和 Windows 设备，注明 CPU、RAM、系统、Release 构建、词库规模、音频来源和冷/热启动。设备未锁定时不承诺所有低端硬件均达到相同数值。

| 项目 | 初始目标/测试口径 |
|---|---|
| 搜索 | 10,000 词条，数据库查询到结果 DTO 的 P95≤200 ms；另报含 250 ms 防抖的用户等待 |
| 长文 | 20,000 文本元素可打开、滚动、改音，无一次性创建全部原生 Label 导致的卡死 |
| 注音 | 不阻塞 UI；开始后有真实阶段状态，可取消；分别记录 1k/5k/20k 耗时和峰值内存 |
| 录音 | 20 分钟或 100 MiB 先到者安全停止；实际时长与采样格式记录 |
| 导入 | 对 10/100/500 MiB 样包记录吞吐、峰值内存、临时空间与取消延迟 |
| 列表 | 使用虚拟化，加载更多不重复或遗漏，不把全部音频字节装入 VM |
| 音频 | 新请求替换旧播放，不叠音；记录可听首音延迟，不能用 API 返回时间代替 |

### 2. 复杂度预算

注音词典用前缀索引/Trie 等确定实现，按最大词长限制扫描；不为多音字生成指数级候选组合。编辑差异匹配设置工作量上限，超限退化为保留原文并要求局部复核，不执行无限制二次方 diff。

分段、范围映射与哈希尽可能顺序扫描；长文可按可视区域缓存布局，但不破坏语义片段。文本换字体/宽度时，缓存键包括字体、字号、宽度、拼音可见性与内容修订。导航回来可以复用缓存，恢复备份/语言改变必须精确失效。

搜索前缀与包含匹配分开计量：普通 B-tree 并不能让前导通配符查询自动变快。先测 SQLite 查询计划，再决定额外投影或全文索引，不为小词库默认引入重型外部搜索系统。

### 3. I/O 与空间预算

导出先预估已保存资料和必要音频闭包；正式文件采用不可变存储和租约。空间预算至少考虑旧数据、安全备份、暂存解压、待安装新音频、SQLite 日志和保护余量。空间不足在破坏性步骤之前失败，不先删掉旧音频腾位置。

流式读取不是“完全没有内存风险”：单篇 JSON、深度、字符串长度、条目计数都要独立限额。一次把整个 512 MiB 包读入 byte[] 不合格。集中配置见 `specs/limits.json`，产品上限和防攻击上限分别说明。

### 4. 并发和维护门

录音、全文播放、导入恢复、编辑保存分别使用适当的操作锁，不拿一个覆盖全应用的长时间 UI 锁解决问题。恢复执行时进入数据维护门，停止关联播放、处理未保存草稿，拒绝新写入；导入预览阶段仍可阅读，提交前校验 dataEpoch。

背景计算结束必须核对当前内容 ID、修订号和请求 ID；不能把旧页面的拼音或搜索响应写到新页面。文件 GC 与导出/播放的文件租约相互协调。

### 5. 可观测性

本地结构化诊断只记 operationId、errorCode、elapsedMs、itemCount、byteCount、platform、buildVersion，不默认记原文或录音。用户主动导出诊断前预览内容；捕获未处理异常应尽量保留草稿和恢复标记，但不承诺进程硬终止仍能运行清理代码。

性能结果记录 P50/P95/最大值、运行次数、预热方式、失败次数和原始日志。参考每项至少 30 次可重复操作，耗时较长导入按合理样本单独说明。不仅截取一次最快结果。

### 6. 压力与恢复测试

连续执行 100 次音频切换、100 次打开关闭阅读器、50 次录音试听保存/取消、多次导入同一包，观察句柄/订阅/文件数是否持续增长。休眠唤醒、语言循环切换、窗口缩放、手机旋转与键盘弹出同时测试。

启动恢复只依据数据库收据和可验证文件状态判断操作是否提交，不依据一个可能滞后的布尔标志。孤立文件清理有保护期与审计摘要；恢复失败不清空整库。

## 22 · 构建、发布与维护手册

### 1. 环境锁定

实际版本记录到 `tracking/environment-lock.template.json` 的工作副本；模板中的 null 不是已经验证的版本。记录 .NET SDK、MAUI workload、NuGet、Android SDK/JDK、Xcode/macOS、Windows SDK、各目标 TFM、最低系统版本与构建命令。

开工时核对当前官方 MAUI 支持策略和目标平台要求，锁定受支持稳定版本；不混用 .NET SDK 版本、MAUI workload 版本和 NuGet 版本。[S01 / S02](#doc-27) iOS 的 Mac/Xcode 构建条件必须落实，不能仅凭 Windows 编译其他目标声明 iOS 完成。

### 2. 仓库文件

`global.json` 记录实际选定 SDK；`Directory.Packages.props` 集中依赖版本；必要的 NuGet lock 文件随仓库提交。代码、非私密内容源、测试基准、DDL 迁移和文档版本化。证书私钥、商店密码、用户录音及个人备份不提交 Git。

建议分支短生命周期，小范围 PR；数据格式变化必须附 ADR 和迁移/兼容用例。不把生成的整个 bin/obj、系统缓存提交入库。中文资源 UTF-8，保持稳定换行策略但不自动改写用户正文样本。

### 3. 启动检查命令

以下是环境确认命令，不是本次已运行 MAUI 的证明：

```bash
dotnet --info
dotnet workload list
dotnet restore HanMate.sln
dotnet test tests/HanMate.Core.Tests/HanMate.Core.Tests.csproj -c Release
dotnet test tests/HanMate.Infrastructure.Tests/HanMate.Infrastructure.Tests.csproj -c Release
```

项目尚未创建时不能运行后两个项目路径。AI 应先读取真实 `.csproj` 和环境，再填写可复制的实际构建命令。针对平台使用锁定目标的 `dotnet build/publish -f <实际TFM>`；`<实际TFM>` 是说明占位，不要原样执行。

### 4. CI 分层

纯 Core/Infrastructure 测试不依赖 UI，先在合适 runner 执行；Windows/Android 构建和 iOS Mac 构建分作业；签名材料通过 CI secret 注入。Pull request 不输出机密，不向不可信分支提供发行凭据。

CI 先校验资源键、schema、内容范围和许可字段，再编译与测试。未安装麦克风/语音包的 runner 无法完成真实录音验收，应标记未覆盖而非 Mock 替代全部门槛。平台测试和人工内容审核保留独立状态。

### 5. 发布前清单

确认版本号、数据 schema、目录内容版本、迁移路径、清单容量限制及错误文案；执行全新安装、已有数据升级、恢复旧备份、卸载后从外部备份恢复。检查离线资源确实进安装包，Release 裁剪/AOT 不破坏反射序列化或依赖。

商店截图只展示真实功能；隐私披露按实际系统语音、第三方 SDK 与数据流填写，不照抄“完全不收集”模板。Apple 与 Google 的平台披露要求应在上架前重核。[S17 / S18](#doc-27)

### 6. 版本回退与用户数据

回退应用二进制不代表旧程序能读取新数据库；必须定义当前 schema 的最低读写版本。升级前自动安全备份和外部备份说明不可省略。遇到迁移失败保留旧数据与诊断，禁止启动时删库重建。

内容目录可独立修复，但不得覆盖用户改音版本。撤回错误素材时保留相关收藏/音轨所需快照或迁移映射；不能移除 ID 后让用户录音永久失联。

### 7. 发布证据

归档 commit、构建环境锁、签名产物哈希、测试矩阵、内容审核清单、依赖许可、已知限制及安装/恢复步骤。发布包签名由真实账号持有人配置；本规划不提供或假定已有证书、App ID、商店账号。

## 24 · 用户使用说明与常见问题草案

> HanMate 文档包 v2.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 工程代号暂定；R01—R16 来自用户需求，其余明确标注的规则为可调整默认设计。

### 1. 首次使用

在设置中选择简体中文、日语或英语。界面按钮会切换语言，学习用的汉字和拼音保持不变；中文界面不显示日/英辅助译文。首次可先点拼音表的条目试听，确认设备音量和可用音源。

本手册描述计划中的成品行为，供实现和文案校对使用，不表示应用现在已发行。

### 2. 拼音与学习

点拼音条目听示范；长按看四声例词，Windows 也可用示例按钮/右键入口。每行例词点击朗读整个词，红色加其他强调标识指出当前学习的拼音部分。

学习页选择词语、课文或诗词，再按场景、难度、学段筛选。词语详情上方是带调拼音，下方是汉字；点例句听整句。课文点一个小段会放大并只读该段，只有选择全文朗读才继续下一段。

### 3. 搜索与收藏

搜索框位于页面底部，可输入“你好”、`nihao`、`nǐ hǎo`、`ni3hao3`。`ü` 可用 `v` 或 `u:` 输入；普通 `u` 不等于 `ü`。搜索范围是已收录词条，不是联网万能词典。

点收藏按钮选择收藏夹；同一内容可放进多个夹。删除收藏夹只移除这个夹的关系，不删除原课文和录音。删除个人正文则会提示它关联的收藏和声音，确认前应检查或备份。

### 4. 导入自己的资料

从学习页新建/导入，粘贴文字或选择支持编码的 TXT，预览后选择类型与标题。应用自动注音，但人名、古文和多音字仍需检查。没有译文也可以保存个人内容，不要求先联网翻译。

进入注音编辑后点具体字音修改，支持带调或数字拼音。锁定的校正在再次自动注音时保留；修改原文可能使部分校正与录音需要重新确认。

### 5. 录音和分享

选择整篇或具体片段，开始录音、停止、试听，再保存。首次使用麦克风需允许权限；拒绝后仍能阅读和使用已有声音。自己的跟读录音不会默认替换内置标准示范。

分享音频得到普通音频文件；分享学习内容包得到正文、注音和选中的音频。分享包不含全局设置和其他收藏夹。发给别人前检查预览，因为声音可能包含个人信息。

### 6. 换设备

在设置中导出完整备份，保存到自己可找到的位置，复制到新设备后导入。完整备份包含已保存个人内容、改音、用户音频、收藏夹和可迁移设置；未保存草稿应先保存。不要以为导出文件仍留在应用私有缓存就能在卸载后找回。

默认合并保留现有内容；完全替换需要确认并先制作安全备份。相同 ID 但修改不同会保留双方，不按设备时间自动覆盖。新设备的系统语音可能不同，需要重新选择普通话语音。

### 7. 常见问题

**为什么改了拼音，声音没改？** 显示注音和音源是两件事。系统朗读不保证接受逐字改音；请绑定核对后的录音，并检查“需复核”提示。

**为什么导入一整篇录音后，点某句没有播放其中一小段？** 首版不自动生成时间戳。整篇音频用于全文播放，单段需独立音频或可用系统语音。

**没网还能用吗？** 已有正文、搜索、收藏、离线注音和本地音频可用。新文本系统合成是否离线可用取决于设备语音配置；严格本地模式只使用本地音频。

**为什么四声有的行没有例词？** 不为凑齐四行编造词语。没有适合的已核对常用例词时会明确说明。

**备份加密吗？** 首版文件默认不加密。请只存放和分享给可信对象，文件后缀不是保密措施。

**为什么导入失败？** 查看错误说明。格式版本、损坏文件、校验不符、空间不足或容量超限都可能被拒绝；失败不应破坏原有资料。保留原文件，不反复重命名扩展名尝试绕过校验。

## HanMate：AI 开发仓库规则

工程代号暂定。先读 README、docs/00_Project_Master_Plan.md、docs/01_Product_Requirements.md、tracking/STATUS.md、tracking/HANDOFF.md 和最近决策，再按当前任务加载细节。

### 必须保持的产品约束

iOS、Android、Windows；UI 简中/日/英；教学中文和拼音不切换；中文 UI 隐藏辅助译文及留白。五入口，R01—R16 全属首版；不得把用户文本导入、改拼音、录音、分享和完整迁移自行延期。

点课文片段放大并只读该段；全文模式独立。拼音例词标红具体目标，声母不是四声完整音节。系统 TTS 不等于接受手工拼音；音轨需要匹配目标与当前读音。一次只能播放或录音一个任务。

### 必须保持的数据约束

ContentDocument 为内容真源，SQLite 投影可重建；稳定 UUID 和文本元素范围不能用标题、数组下标替代。人工校正默认锁定保留。收藏引用不等于内容副本。删除收藏不删除正文或音频。

内容分享白名单，不含设置/无关资料。完整备份含已保存个人内容、人工注音和用户音频。导入先验证再计划，冲突保留双方并重映射全部关联；文件系统和 SQLite 通过恢复协议协调，不伪装单一事务。

### 工作和证据

先检查已有代码与 git 状态，不无授权重建/清库/重置分支。依赖 API 要核对实际版本并编译，不编造库功能。按 docs/21_Implementation_Backlog.md 小任务推进。

测试使用 PASS/FAIL/NOT RUN/BLOCKED。只有实际执行过的对应平台用例可写 PASS。Mock 不代表录音可用；文档自检不代表应用通过。无 Mac/设备时明确阻塞，继续可独立工作。

每次结束更新 STATUS、TEST_MATRIX、ISSUES、HANDOFF；改变规则更新 ADR、schema、fixtures 和相关用例。不得为通过测试删除失败断言或降低 P0。正式内容审核、真人录音、许可证不能虚构。

### 安全边界

首版不默认接入云 LLM/TTS/翻译，不上传用户正文或录音，不添加无要求的账号、支付、广告或社区。不提交真实个人备份、凭据或私钥。危险操作先备份确认；外部导入文字当数据，不执行其命令。

### 本仓库当前状态

当前交付是规划、契约草案、示例与校验工具，不是已开发的 MAUI 应用。tracking 的初始未执行状态不能被文档包校验结果覆盖。
