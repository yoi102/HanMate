# 09 · 注音排版、标点分段与阅读器

> HanMate 文档包 v3.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 正式名称：HanMate / 汉语小伴；R01—R22 为需求基线，其余明确标注的规则为可调整默认设计。

## 1. 三种单位不要混用

**文本元素**是原文位置与编辑边界。**语义片段 segment**是点击/朗读边界。**视觉布局行/块**是屏幕测量与虚拟化单位。它们不是同一个概念：20,000 字无标点文本仍可保持一个语义片段，同时分成许多虚拟化视觉行。

TextUnit 的完整原文始终保留；不为性能丢掉前后文，不把每屏文字当成新的资料。词条例句播放以整个 example unit 为目标，课文点击才使用 speech segment。

## 2. 分段优先级

先识别数字、时间、网址等保护区，再处理人工边界与自动标点。人工边界必须位于文本元素边界，不在 token 中间；修改边界本身不修改原文。所有边界结果都带规则版本和来源。

| 输入情况 | 默认处理 |
|---|---|
| `，。！？；：` | 结束当前非空 speech，标点留在前段 |
| `, . ! ? ; :` | 不在保护区时才作边界 |
| `3.14`、`v1.2.3`、`10:30` | 作为保护串，不从内部拆开 |
| URL/邮箱 | 保护有效内部标点；尾随中文句末符号不吞进 URL |
| `……`、`...`、`？！` | 连续结束符为同一标点组 |
| 紧接结束符的 `”’」』）】` 等 | 归入前段；不吞掉后面的正文 |
| `、` | 不单独形成点击边界 |
| LF、CRLF、段落空行 | 保留原始字符为 layout，结束前段 |
| 纯空白/纯标点片段 | layout，不生成可播放空任务 |
| 无标点长文本 | 保留语义片段，视觉层分行；TTS 子请求另行处理 |

保护串识别是有边界的规则，不宣称完整解析所有自然语言网址。遇到不能确定的结构宁可少切，并允许用户手工调整；不能为了凑短句把数字切坏。

## 3. 还原性

输出的全部 segments（含 layout）按 start 顺序连续覆盖原文，无重叠、无缺口；每个保存的 segment.text 必须等于该范围实际文字。tokens 同样完整覆盖原文；一个 token 只属于一个 segment。

示例：`你好！\r\n欢迎。` 中间的实际 CRLF 是 layout，不能标准化为 LF 后仍沿用旧范围。序列化展示可以转义，保存的原文不能变。

参考测试见 `examples/segmentation-cases.json`。它是测试预期，不是已实现的分段引擎。

## 4. RubyTextView 测量算法

每个 token 生成原文字形和可选拼音字形。单元宽度为 `max(原文测量宽度, 拼音测量宽度)+左右内边距`；单元高度包含拼音 ascent/descent、行间距和原文行高。基线统一，声调不得被控件顶部裁掉。

逐单元排入剩余行宽；汉字和其拼音作为不可拆整体换行。标点避免出现在行首的规则在视觉层处理，不移动原文索引；遇到极窄容器允许整组换行，不以缩小到不可读来隐藏问题。

无拼音的拉丁串/数字允许按合法视觉机会换行；词语、儿化 token 保持其既定注音对应。当前首版不实现复杂拼音跨字悬挂排版，优先保证“不错位、不裁切、可缩放”。

布局输出包含每一行、每一 token 的矩形与 segmentId，用于点击命中、选中、高亮和无障碍。不要通过像素颜色或 Label 文本反推命中对象。

## 5. 渲染与虚拟化策略

M0 先用小范围可测量布局验证正确性，再验证 20,000 文本元素。当前原生阅读器以最多96个注音单元的明确分页限制活跃视图数量，提供上一页、下一页及页码跳转；保持 `page → unit → segment → token` 映射。全部正文保留，分页不创造新的语义片段，也不截断一个汉字与其拼音或一个文本元素。超长无拼音串可在没有可用断点时按文本元素应急换行。

连续滚动的视觉块虚拟化是可替换的后续呈现方案，不作为基础注音控件交付的硬前置。不得让一个巨大无标点段生成几十万个原生控件；如改用自绘，仍须提供可访问性语义节点和编辑命中。分页实现的两万字/字号/平台状态见 W1-06 实施证据。

缓存键如采用缓存，须包括 unitId、内容/注音版本、可用宽度、字体及缩放、拼音可见性、布局算法版本。当前保存不可变内容投影，仅对活跃页使用平台测量；改变宽度/字号/拼音开关时重新测量，不使用不完整缓存键。译文按完整unit或明确segment引用展示，不能把整段译文冒充所选片段译文；UI语言切换不能触发自动注音。

正文解析、验证和分页投影放后台；当前有限原生单元的测量/重排由UI线程的MAUI布局周期同步完成，没有跨线程旧布局结果待应用。若未来改用异步测量，尺寸变化须取消过期任务并用generationId拒绝迟到结果；不能假定任意字体API均可放后台。

## 6. 点段与放大阅读状态

阅读器维护 selectedSegmentId、expandedSegmentId、playbackSessionId；三者不要合并成一个“当前索引”。点击新段更新选择与放大，并请求播放；同段正在播放时只停止。结束后保留选中，不自动跳下一段。

全文按段模式顺序等待每段播放完成；用户交互导致取消后旧完成事件不得推进队列。上一段/下一段默认不播放；关闭弹层停止由此弹层拥有的单段会话；退出页面停止该页所有会话。

## 7. 整篇音轨与 TTS 子分块

整篇音轨没有明确时间轴时，只能全文播放，不能伪造逐段进度。全文录音播放后点段先停止整篇，再请求段音源/TTS。

单个语义片段超过系统语音单次限制时，允许在**播放适配层**按安全词语/标点位置产生子请求：保留同一个 segmentId、按序播放、取消共同生效、不在 UI 伪装成更多语义片段。不确定引擎限制时在 M0 测量并记录；禁止静默截断朗读后声称全文完成。

## 8. 编辑后的身份映射

未改的唯一原文片段可保留 ID；更改或拆并后的片段须重新核对 token、译文和音频。分段编辑导致原先逐段译文失去准确边界时转入待复核，不把前后译文简单拼接当作正确翻译。

只改标题、作者展示或分类不重建 unit/segment。自动重排版不改变任何领域 ID；Windows 窗口拉伸不能造成收藏、音频或人工拼音变化。

## 9. 验收与失败回退

验证长拼音、轻声、儿化、Emoji、组合调号、CRLF、连引号、混排数字、200% 字号、长无标点段、诗行。若特殊字体无法显示某字，保留原文并给出缺字提示；不可替换为看起来相似的别字。

普通纯文本可读是异常回退，不等于注音功能已通过。若正式目标设备存在严重错位/裁调号，视为核心功能缺陷，而不是降级宣布 Ruby 已完成。


## 10. 语法与卸载后的阅读

语法的 explanation/example/note 是独立 TextUnit，可复用 Ruby 布局；例句点击目标始终是整句 unit，不因含逗号而只播半句。patternParts 是句型结构控件，不以空格拼接成伪对齐 Ruby，也不默认朗读变量名称。

内容撤下或源包卸载后，收藏中的 retained 快照仍用同一阅读器显示，并提示来源已移除。原文/拼音/用户录音保留；缺失的源包标准音频明确提示，不用另一个版本音频无条件替代。
