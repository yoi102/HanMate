# 10 · 离线搜索、拼音查询与索引

> HanMate 文档包 v3.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 正式名称：HanMate / 汉语小伴；R01—R22 为需求基线，其余明确标注的规则为可调整默认设计。

## 1. 搜索范围

### 2026-09-19 用户追加：单字手写入口

搜索页顶部切换文字搜索与手写搜索。手写页上半部分显示候选汉字及相关例词，下半部分为单字田字格；每次抬笔重新识别，提供撤销一笔、清空重写。切换模式与进入释义后返回保留本页笔迹，离开页面取消未完成识别；笔迹不保存、不上传。

当前使用离线笔顺模板匹配，覆盖9,574个字形，要求常规笔顺，不声明任意连笔或任意笔顺准确率。数据来自固定版本 Make Me a Hanzi，包内附原版 Arphic Public License、来源及修改说明；只提取笔画中线，不包含上游词典释义。

点击字或词进入现有字典阅读页；例词取当前启用且未撤下的词条，允许只读展示当前可见的拼音教学例词。按内容ID去重，保留同字词不同音义条目。识别出的字尚无本地释义时显示该字的缺失状态页，不编造释义或自动写入字典。识别字形数量不等于已有词典条目数量。验证见 tracking/evidence/HANDWRITING-20260919.md。

首版检索个人 word、已启用学习资源 word、已启用查词字典 word，并排除撤下/缺失/retained 来源。同字不同音义通过不同 contentId 分开返回。课文/诗词标题搜索是独立扩展，不能用查到标题来冒充词典结果；默认没有全文向量检索、RAG 或在线补词。

索引从已保存的 headword unit 与已确认读音派生，不从当前 TTS 结果或 UI 译文反推。多个确认读音可建立显式 alias 行，但不得为每个多音字的全部候选做笛卡尔组合。

## 2. 索引字段

| 字段 | 示例 | 规则 |
|---|---|---|
| hanzi_key | 你好 | 搜索副本 NFC，原文不改 |
| pinyin_joined | nihao | 无调、连续、索引用 v 代表 ü |
| pinyin_separated | ni hao | 保留已知音节边界 |
| tone_separated | ni3 hao3 | 轻声为 0 |
| tone_joined | ni3hao3 | 数字声调输入快速精确匹配 |
| syllables_json | ni/3, hao/3 | 对显式声调和边界细粒度排序 |
| frequency_rank | 100 | 可空；不可随机生成声称真实频率 |
| index_version | 1 | 升级可重建 |

base 正式数据保存 ü；索引中 v 是内部查询编码。文档、UI 和导出内容的学习拼音不能因此显示 `nv`。

索引行身份为 contentId + aliasOrdinal，唯一性与 word 音义项一致。修改个人注音后在同一写事务中刷新相应索引；索引失败则不提交内容半成品。恢复/目录更新可批量重建，重建中不返回不完整结果冒充全量。

## 3. 查询归一化

保留原输入供显示。查询副本 trim、NFC、小写；合并多空格，将直/弯隔音符统一为音节边界；先识别 `u:`、v、带调 ü，再解析声调。不能“一口气删除所有组合标记”，否则会把 ü 错变成 u。

数字声调允许 1—4、0/5；归一后 5 为 0。输入中的普通数字不当声调，除非它位于合法拼音音节尾。未知字符、仅符号输入返回明确空态，不执行动态 SQL。

| 输入 | 查询语义 |
|---|---|
| 你好 | 汉字完整或前缀/包含 |
| nihao | 连续无调，允许多个已知音节划分候选 |
| ni hao / ni'hao | 有音节边界证据 |
| nǐ hǎo / ni3 hao3 / ni3hao3 | 指定相应位置声调 |
| nǚ / nv / nu: | 同一 nü 查询 |
| nu | nu，不等于 nü |
| xi'an / xi an | 优先 xi + an |
| xian | 可召回 xian 与 xi + an，明确列为不同词条 |

连续带调输入如 `nǐhǎo`：先取得无调连续键候选，再按候选已有音节切分核对调号位置；不强制只选择一种猜测切分。空格/隔音符是边界约束，带调字符或数字是声调约束；不要把不完整声调查询补成全部轻声。

## 4. 排序和近似结果

排序层级：汉字精确 → 音节边界和指定声调均匹配的完整拼音 → 完整无调拼音 → 前缀 → 包含。若用户未指定边界/声调，对该条件不惩罚。用户指定声调但无完全命中时可以列无调近似项，必须显示“近似拼音结果”，不能伪装精确声调匹配。

同层使用稳定元组：来源优先级 sourcePriority → 显式 commonRank（存在时）→ 词条元素数 → 来源与 contentId 的 ordinal 顺序。不得用随机排序，也不根据 UI 语言的字符串比较改变核心匹配。

每个 contentId 只显示一次，多个 alias 命中取最佳层级。相同汉字不同内容 ID 必须保留，不误以标题相同为重复。

## 5. 查询实现基线

SQLite 建立汉字、连续拼音、分音节拼音、数字调键的普通索引。精确和前缀分层查询，后续包含查询作为最后一层；`%包含%` 不假设能有效使用普通 B-tree 索引，必须实测。

参数化传值，并对 LIKE 的 `%`、`_` 与转义字符做字面处理；用户输入不拼接进 SQL。可以采用确定的 prefix 上下界查询，或核对排序规则后的 LIKE；是否使用索引由 EXPLAIN QUERY PLAN 和目标设备计时确认，不靠口头保证。

先完整计算较高层级的可用结果，再补较低层级，避免提前截取低质量候选导致精确声调结果丢失。初页 50 条，用稳定游标继续；不直接把“返回 50 条”当全库只命中 50 条。

10,000 条词语是首版性能基准，超过基准仍不能截断数据。出现性能问题可增加结构化索引或经过验证的 FTS，但不默认换成服务器。

## 6. UI 和取消

2026-09-19实现更新：文字搜索不显示分页按钮；首批50条，接近末尾用稳定游标追加并按contentId去重，保留滚动位置。关键词/来源变化重置，切换手写再返回保留结果，epoch变化重查。手写候选每行左字与拼音、右例词换行无拼音。实测见tracking/evidence/SEARCH-COMPACT-20260919.md。

输入防抖 250 ms，Enter 立即执行，清空取消请求并清空结果。每个请求有 queryId；只有最新 queryId 的结果可以更新列表。取消数据库查询做不到立即生效时，至少丢弃过期结果并释放资源。

不回写正在组合的中文输入法文本；回车如果用于确认输入法候选，不应意外同时打开第一条结果。点击朗读不影响查询；详情返回恢复 query、筛选和 scroll anchor。

## 7. 一致性和升级

启动发现 index_version 不匹配时从 ContentDocument 重建，不删除个人主数据。修改读音、导入冲突派生、删除词条、目录升级都必须更新索引；没有保存的草稿不进入正式词典查询。

重建采用维护门与事务/影子索引切换，外部读者看到旧完整索引或新完整索引。记录重建数量、版本和错误码，不记录用户的搜索全文。

## 8. 性能与正确性验收

基准包含汉字精确、单字多音义、连续拼音、数字声调、ü、隔音符、短前缀、无结果和包含查询。P95 ≤ 200 ms 是查询引擎目标，不含 250 ms 防抖；另记录输入提交到列表显示的端到端延迟。

`examples/search-cases.json` 给出具体输入与应有/不应有结果。单元测试可模拟仓储；查询计划与耗时必须使用真实 SQLite 和真实数据。未测试 Windows 输入法、iOS/Android 软键盘时不能把桌面单元测试当三平台通过。


## 9. 字典来源过滤与游标

来源规则以 [字典管理](32_Dictionary_Management.md) 为准。SQL 查询必须加入 installed_resource 的 is_present/enabled 与 resource_entry_override 条件；不能让已禁用字典通过旧索引漏回结果。词条语义排序优先于来源优先级。

启停、更新或卸载后更新 dataEpoch，旧查询结果和旧分页游标失效。个人 word 和独立注音引擎不因查询字典删除而删除。搜索页词典入口显示来源，grammar 不是词典主结果；可在未来标题检索中另分类型。

## 11. 手写候选延迟优化（2026-09-20）

以下为首轮优化背景；当前运行时预处理、笔顺/连笔和越界规则以§13为准。

进入手写页即后台预热9,574字模板；抬笔后先显示六个识别候选，不等待字典查询、释义构造和课程内容解析。随后逐行补齐拼音及例词；100 ms的笔间停顿只用于延迟查词补全，不延迟候选字。点击尚未补齐的候选会直接启动该字的共享查词任务，不排在其余候选后面。

模板加载时缓存各笔画前缀的包围范围，识别时直接计算距离并只保留所需前12名以内的候选；保留原归一化、前缀惩罚与相同距离时按字符排序的规则。新一笔、撤销、清空、离页取消旧任务；过期结果不得更新候选或打开详情，词典epoch变化仍重查。数据库和资源格式未变。

桌面CPU基准、288组候选/距离对照及自动测试见[手写性能证据](../tracking/evidence/HANDWRITING-LATENCY-20260920.md)。桌面耗时不代表手机端到端延迟；真机/UI调试仍依用户要求暂停。

## 12. 手写例词在不同宽度/字号下的换行（2026-09-20）

用户真机截图显示短例词被拆成两行且第二行截断。旧实现为允许shrink=1的FlexLayout原生多行Button，存在压缩宽度后文字换行但行高未同步的问题。本轮将例词文字交给Label测量，保留透明原生按钮承载点击和读屏；整词使用自然宽度排布，空间不足时整个词移到下一行。单个词比全部可用宽度更长时，按该宽度重新测量多行高度，再决定行高。分数尺寸向上取整，避免像素密度换算舍入裁切。

布局按平台实际测量的逻辑尺寸工作，不硬编码某台手机的像素分辨率；保留系统字体缩放及原有文字样式。先显示候选/逐行补例词、原词条点击跳转均保留。自动布局几何验证不等于真机原生控件显示通过，见[换行修复证据](../tracking/evidence/HANDWRITING-WRAP-20260920.md)。

## 13. 首次预处理、连笔容错及越界保留（2026-09-20）

运行时直接读取已随包预计算的HMI4点数组、前缀范围及笔画组合，不在首次书写时解析JSON/重采样9,574字。进入搜索页即后台准备字典和模板，手写激活不等待目录初始化；先出六个候选，再补拼音/最多五个例词。查过的行最多缓存64个，使用数据库及默认字典epoch判定有效，不因缓存显示已禁用来源。词条/课程内容及许可不因性能优化改变。

标准笔顺与未完成前缀仍参与排名；完整字形增加与笔顺无关的一对一笔画匹配，并比较相反落笔方向。先用匹配下界取48个候选，再运行精确分配。临近端点的断笔最多尝试两种合并；用户追加生/金后，连笔对12画以内模板扩大为最多少六次抬笔，一条轨迹可匹配连续2—3笔并包含笔间连接线。连笔惩罚按比例计算，累计误差已无法进入候选的路径提前结束。不是任意删笔、草书或多字连写模型，见[追加证据](../tracking/evidence/HANDWRITING-GENERAL-20260920.md)。

笔尖越出田字格时保留笔迹，采样限制到边缘；在外侧松手或原生控件因此报告Cancel时提交已有轨迹。显式离页取消当前未提交笔，撤销/清空保持。不会因越界而删除已绘制的整笔。独立手绘和模板扰动验证分开记录，实际手机范围见[本轮证据](../tracking/evidence/HANDWRITING-TOLERANCE-20260920.md)。

用户要求移除手写区“数据来源”按钮，底部仅保留居中的撤销/清空图标。数据来源NOTICE和Arphic许可继续随应用资源保留。
