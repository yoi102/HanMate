# 11 · 朗读、录音、音轨与音频生命周期

> HanMate 文档包 v3.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 正式名称：HanMate / 汉语小伴；R01—R22 为需求基线，其余明确标注的规则为可调整默认设计。

## 1. 音频目标和音源

当前实现以本章§18—19和ADR-111/112为准：默认MeloTTS，另内置Kokoro中文男女声，可显式选择系统文字转语音。前文/历史段落中的AISHELL-3、下载方式和逐次系统确认规则由该更新覆盖。

2026-09-19用户新增：提供内置目录的可下载AI中文语音包。设置中下载、校验、试听任意短文字并明确选择音色后，自己保存的内容与学习内容缺少匹配录音时可本机合成；普通点读与全文队列复用该选择。已有匹配录音优先，系统TTS保持原独立确认规则；拼音教学示范继续使用专用录音。模型不接受手工拼音作为语音控制，多音字/生僻字仍需检查。

当前AI引擎sherpa-onnx 1.13.8，模型AISHELL-3 VITS，固定源版本、逐文件大小与SHA256，只在用户请求时下载到私有voices目录。网络取消/坏哈希/超长响应不安装；完整校验后改名发布，不解压外部档案、不执行模型携带脚本。合成持有模型读租约，移除等待读取完成；播放、取消、导航共用PlaybackCoordinator。下载模型及本机音色选择不进入内容包/应用备份，换设备明确重新下载选择。Android/Windows本轮接入，Apple原生仍暂缓。

2026-09-19补齐边界：原生引擎会忽略并记录OOV输入，因此先对AI队列逐段按固定模型词典检查；英文/表情/不支持汉字在整队列开始前明确拒绝，不漏读后报成功。支持中文与数字、全角数字规范化；括号/引号/空白只归为停顿，原文不改。长语音块在180文本元素/500 UTF-16上限内优先句读切分，无分隔符才硬分块。界面离页/取消后忽略旧回调，损坏模型仍可删除。

Android长数字压力验证后，AI原生调用进一步限制为最多48文本元素，预览与阅读统一逐块生成/播放；这是为数字展开后的合成开销留余量，系统语音仍保留180元素上限。取消必须等当前原生调用返回，不能承诺在任意ONNX算子执行中立即停止；实际设备证据见W5本机补齐记录。

目标为拼音教学项、词语 headword、例句 unit、课文 body unit 或正文 speech segment。调用时传 targetId，不传“第几行”作为永久身份。音源类型为 catalog 标准录音、user 录音/导入音频、系统普通话 TTS。

默认顺序：用户明确选择且仍适用的音轨 → 对应的审核标准音轨 → 个人内容已确认绑定音轨 → 允许时的系统 TTS。拼音教学项只接受审核的教学示范，不用普通 TTS 盲目读拉丁字母。

用户跟读内置内容后，默认不覆盖标准音源。保存时可明确勾选“设为该目标的默认音轨”；个人内容默认勾选，内置内容默认不勾选。

## 2. 状态机

| 当前状态 | 请求 | 结果 |
|---|---|---|
| Idle | Play | Loading，找到音源后 Playing |
| Loading/Playing | Play 新目标 | 取消旧会话，确认停止后开始新会话 |
| Playing | Stop 或再次点同目标 | Stopping → Idle |
| Idle/Playing | StartRecording | 先停止播放 → RequestingPermission → Recording |
| Recording | Play | 返回 RECORDING_BUSY；要求先停止，不隐藏丢弃录音 |
| Recording | StopRecording | Finalizing → 生成可试听草稿 → Idle |
| Recording | 页面退出/后台/中断 | 尽力安全停止为草稿，不自动续录 |
| 任意活动状态 | 不可恢复失败 | 释放资源，返回 Idle，并附稳定错误结果 |

“有录音草稿”是编辑器状态，不意味着麦克风仍在 Recording。状态仅允许协调器修改，页面不能自行把 IsPlaying 设为 false 后不停止真正播放器。

每个请求有 sessionId 和 ownerScopeId。旧完成回调先检查 sessionId，再更新高亮或推进全文队列；跨页面停止按 ownerScopeId 定位，不误停新页面已开始的音频。

## 3. 完成和取消语义

PlayAsync 表示本次播放到自然结束、取消或失败后的结果，不是“已经调用 Play 方法”。底层播放器使用完成事件转换为 Task，并保证事件/流/播放器释放。停止正在加载的文件同样必须取消后续开始动作。

全文朗读用顺序 await，不并行提交全部片段。系统 TTS 官方说明可用文本、语音选项与取消令牌，并提示跨线程排队和后台播放的限制；应用仍自行管理队列和生命周期。[S04](27_References.md)

如果停止后底层仍短暂回调，忽略过期事件；如果设备停止 API 失败，返回真实失败并禁止继续叠加，而不是假装 Idle。长播放过程中保持文件租约，GC 不得删除正在读的音频。

## 4. 整篇与逐段

body unit 音轨用于整篇播放，segment 音轨用于单段播放。只有整篇录音不具备 segment 时间轴；全文模式可直接播放它，段模式按段音轨/TTS 回退。

按段全文模式可混用已确认段录音和 TTS，但播放开始前告知缺失项；无法播放某段默认停止并提示，用户可以明确选择跳过，不静默略过后宣称全篇完成。整篇模式没有精确段时间轴就不做同步段高亮。

句段停顿优先来自音源本身；额外延迟是可调整播放体验，不声称三平台语音韵律完全一致。首版不包含自动强制对齐、按字数估算时间轴、波形编辑或自动语音评分。

## 5. TTS 与离线策略

系统语音选择与 UI 语言分离。枚举普通话候选并提供试听；语音 ID 为设备专属，不直接迁移。仅发现中文 locale 不能证明飞行模式可用，M0/M5 需实际验证。

设置默认允许“本地音频优先，必要时尝试系统语音”；增加可调整默认项“仅使用本地音频”用于不希望调用系统合成的场景。系统提供方可能受自身设置影响，应用不声称绝对无网络行为。

人工改拼音只改教学注音；对必须精确遵守校正的段，优先使用确认匹配的录音。不得将拼音拉丁字符串提交 TTS 后当成可靠普通话。

## 6. 录音工作流

选择目标 → 说明用途并请求麦克风 → 显示录音计时 → 停止 → 关闭/修复音频容器 → 试听 → 保存/重录/丢弃 → 可选设为默认。未停止时不让草稿成为正式资产；保存需要非空、可解码、时长有效的音频。

麦克风权限只在实际录音时申请；拒绝返回编辑页，不能循环弹请求。永久拒绝提供系统设置入口。进入后台、音频焦点丢失、来电等尽力结束并保留草稿；突然被系统终止可能来不及修复容器，启动时检查并明确说明草稿是否可恢复，不能承诺任何中断都零损失。

窗口短暂失焦和应用真正进入后台不是同一事件，Windows 文件对话框不应被误判为长时间后台。平台生命周期回调按实测接入。[S20](27_References.md)

## 7. 编码与容量

| 类型 | 首版验证目标 | 说明 |
|---|---|---|
| WAV | PCM 16-bit little-endian，常用采样率/声道 | 优先作为跨平台录音基线 |
| MP3 | 常见 MP3 音频流 | 需实际探测和播放 |
| M4A | AAC-LC 音轨的 M4A 容器 | 不等于支持所有 AAC 变体或裸 .aac |

具体录音采样率和编码按候选库及平台实测确定；请求参数不等于实际输出参数，必须探测文件头。Plugin.Maui.Audio 的录音文档是能力参考，不是本项目三平台录音已通过的证据。[S10r](27_References.md)

导入单文件 ≤100 MiB；连续录音 ≤20 分钟，同时受 100 MiB 限制，两者先达到者先安全停止。录音前做剩余空间检查，录制中实时统计字节；容量来自实际文件，不只信 UI 计时或扩展名。

导入时先有限读取头部/元数据并试解码，不一次把大文件全部解成内存 PCM。文件类型与编码不符、截断、不支持格式给出错误；不通过改后缀假装转换。

## 8. 音轨失效和删除

正文或有效读音哈希变化 → binding.needsReview=true。保留文件，取消它的自动默认资格；用户可在管理页试听并明确“确认仍适用”，更新适用哈希。改标题/译文/收藏不使录音失效。

删除绑定不必立即删除物理文件；仅当无其他引用且无导出/播放租约时回收。移除标准音轨的 UI 选择不是删除安装包资源。相同字节哈希可共享文件，但每条逻辑音轨的名字、来源和目标关系仍独立。

## 9. 分享与验收

分享单独音频前确认选择的是用户允许分享的素材；分享学习包则列出实际包含音轨。内容包不夹带其他录音、设置或搜索记录。系统分享只能确认已调起交互，不能保证对方已接收。[S07](27_References.md)

测试录制真实可听语音、暂停/停止能力边界、快速连点、权限拒绝、中断、后台、耳机路由、锁屏、删除引用、跨平台播放。静音测试文件只能验证容器，不计为“发音正确”或“真人录音完成”。本包未提供虚构的正式教学音频。


## 10. 语法与资源卸载音频规则

语法例句/说明使用 unit target，结构槽位不生成播放目标。用户为某资源条目录音后，该录音归用户层，不被源包更新覆盖或卸载误删；依赖预览默认保留所需内容/目标快照。

资源标准音频 origin 仍为 catalog，catalogRef 的 catalogId/version 可指明确资源；不凭名称寻找相似音源。外部资源卸载时保留用户音轨，标准文件只有无其他引用/租约时才 GC。更新改了实际读音时保留旧快照或标记需复核，不强行套用旧音轨。

分享当前录音先完成容器写入再选声音文件；分享内容时只包含用户勾选的音轨，未勾选的 preference 也须剔除。详见 31、33。

## 11. 分阶段实现约定 · 2026-09-17

本轮先交付PCM16 WAV的导入、录音草稿和音轨绑定链路，MP3/M4A继续保留在首版需求中。实际完成及平台验证以tracking/STATUS.md与W3-04-W3-06证据为准，不能将本章目标表当作已支持格式列表。

本地内部草稿使用localAudio.v1：持久化pending意图后写临时文件，严格验证完整容器、哈希并重命名，再变为ready。重启后在同目标管理页显式尝试恢复，无法恢复的草稿明确提示并可丢弃。保存将asset/binding/preference/epoch及草稿完成放进同一SQLite事务；不可恢复的进程强杀窗口不承诺零损失。

所有打开的本地音频先建立播放租约并核对实际文件，再交给播放器。移除绑定/丢弃草稿暂不回收物理文件；后续GC必须识别正式资产、所有草稿状态、播放/导出/导入租约。录音草稿也保护对应内容不被资源卸载，不自行绕过依赖保护。

## 12. 阅读页面与单会话队列 · 2026-09-18

ReadingPage直接接入本地音频：词头与词语/语法例句使用完整unit目标，逗号不缩短播放范围；课文/诗词点击speech段进入放大页并只播放该段，上下一段停止旧声音、只改显示。语法PatternParts不是播放目标。管理操作放到正文后面，词头优先展示。

ReadingAudioStore在同一个读事务核对屏幕内容与保存内容，再预检整组自动适用音轨。全文按正文顺序：有完整unit录音时播放一次，不推定段时间轴；没有时按speech segment排队，layout换行仍显示但不发声。缺任何目标时本次整组不启动，显示缺失数；不静默跳过。单项失败也停止后续。

自动音源顺序沿用显式默认→standard→个人内容的confirmed绑定，needsReview或正文/读音hash不匹配不能自动播放。每一步打开文件时在同一数据库事务重验contentId、targetId与两种hash，再选择音轨、建立租约并验证实际WAV；过期阅读页面和旧队列不能播放已更换的正文。

PlaySequenceAsync将计划读取、全部播放项及项间切换放在同一owner会话内；准备/停止/后台/导航都取消同一令牌。只能顺序await原生完成，迟到进度不能恢复旧高亮。同队列重复点击停止；录音可抢占播放，播放不能抢占录音。取消可能同步完成，因此停止/切换必须先保存会话引用和toggle判定，再触发取消回调。

本地录音是本轮阅读工作包的已实现播放路径。系统TTS选择、设备离线可用性及localOnly/系统语音设置仍由W0-04和后续音频验收负责，本轮不自动调用TTS、不声称手工拼音影响系统语音；§5仍为首版未完成目标。正式音频生产/教学终审属于W5-02，当前开发录音缺失时保留明确不可播放状态。


## 13. 本机系统语音检查 · 2026-09-18

设置页新增系统语音检测与固定中文句试听，仅由明确点击触发。Windows枚举系统已安装普通话SpeechSynthesizer音色；Android枚举TTS引擎候选，排除network-required/notInstalled；Apple枚举普通话语音。实际离线能力和教学发音须另行验收，枚举不等于通过。

试听经PlaybackCoordinator.PlayOperationAsync预约，与音轨播放/录音互斥；停止、离页、后台、超时都等待本次清理，清理失败继续封锁后续播放。无普通话音色给出系统设置提示，不自动下载、不用英文音色代替。设置页试听只使用固定“你好，欢迎学习汉语。”；阅读回退的后续实现见§14，设备离线状态仍待验收。

## 14. 压缩导入与显式阅读语音 · 2026-09-18

独立音频导入已接通MP3（MPEG1/2/2.5 Layer III）和单音轨AAC-LC M4A。先复制到随机私有缓存，按字节验证容器、样本表/帧连续性和预计PCM容量，再调用Windows MediaTranscoder、Android MediaCodec或Apple AVAudioFile，流式输出PCM16 WAV并严格复验。输入及输出各100MiB，转换超时5分钟。加密、分片、外部data reference、HE-AAC及不支持的变体拒绝；此为保守支持集合，不承诺所有同扩展名文件。原文件不修改。只有解码完成后进入既有pending→ready→保存协议，取消/预校验失败不登记新草稿。分享/备份/资源包继续只接收严格PCM16 WAV，没有放宽压缩包协议。

阅读默认`localOnly`；设置显式持久化`localWithSystemFallback`后，仍需点击独立朗读按钮、确认发送缺失目标的中文正文并选择普通话音色。已匹配录音优先，不静默跳过缺失段，语法slot不读。普通点击和选段自动播放不初始化TTS。人工拼音不传入系统引擎，UI明确它不能验证人工改音。每段及Unicode安全小块播放前重验目标/文本/读音hash和策略；整个混合队列仍属于一个可取消会话。声音ID不入库/不备份，音频策略依现有备份设置规则迁移。

平台实际结果见tracking/evidence/W3-W4-compressed-speech-migration.md；托管编译不是iOS原生通过，已安装候选也不是飞行模式或教学发音证明。

## 15. 拼音练习使用离线 AI 声音 · 2026-09-19

拼音页和例字词页共用已下载、启用的 AISHELL-3 声音。设置中的拼音资源页提供 AI 优先开关，默认开启；没有启用声音时仍用已署名内置录音。经过内容/读音哈希检查的导入录音优先，不自动下载模型。练习页不增加管理按钮或顶部说明。

教学合成从课程注音生成 AISHELL-3 音素，声母明确使用 bo/po/mo/fo/de 等读法，处理 ü、j/q/x 省略两点、整体认读音节、舌尖元音和轻声；韵母直接合成其音素，包括单独 ong。例词要求全部汉字有明确拼音，整词合成，不让文字前端重新猜多音字。当前只适用于拼音练习；普通阅读仍是文字 TTS，不能推定已支持手工改音。

每次合成创建独立临时读音表，使用生产下载模型的音素清单验证，并在退出时删除临时表；不改已验证模型或原词典。准备、合成和播放在同一 PlaybackCoordinator 会话中，以项目/例词 ID 区分目标，连点同项停止、不同项切换、离页取消。失败明确反馈，不用任意汉字或字母读音代替。

原始录音来自 audio-cmn，与教育部或 chinese-xinhua 字典独立。AI 音素路径、WAV 非静音检查和教学听审分别记录；合成出声不等于人工确认发音标准。内置音源许可版本未决、独立 ong 录音缺失及教学终审继续保留。

## 16. 内置默认中文语音与字典段落（ADR-108/109）

应用资源随附约31.2 MiB的既有AISHELL-3固定模型，模型SHA256及每个资源大小/哈希与Voices.catalog一致。初次语音使用从应用资源解包并校验，在全新voices目录启用默认音色66。已有选中音色或停用状态保留；旧版本已移除语音时也不自动恢复。首次解包的取消/失败保留初始化意图，可重试，半成品不成为安装目录。

设置提供试听/换音色/停用、清除语音缓存、离线恢复。清除只删已解包副本并停用，不删除安装包中的资源，不影响正文/收藏/录音；恢复后需要用户选择启用。完整备份仍不复制模型或本机音色。平台网络权限不等同于默认联网：应用语音资源供应器只打开包内文件，不发模型HTTP请求。

字典词头、释义段落、例句均可点击文字播放，无额外播放图标。不同段落以文档/单元稳定ID与原文范围区分；同段落跨96原子视觉块或折叠边界时共享完整语音目标。辅助例句与替换“～”的显示句不得错绑原单元录音。已有单元若完整匹配则优先已核对录音，部分段落只合成选中段落。中文段落合成前校验全部分块，遇不支持的字符显式提示，不先读半句再跳过后文。

全部播放共享PlaybackCoordinator，重点击停止、换段切换、录音互斥、离页取消及原生清理规则不变；旧请求不能覆盖新请求错误提示。当前验证见tracking/evidence/DICTIONARY-AUDIO-BUNDLED-20260920.md；未执行设备/UI点读及真人听审。

## 17. 恢复教学录音优先（ADR-110）

用户反馈拼音及例字例词音色变差后，默认恢复已有完整录音。原pinyin.prefer-ai以true为默认值，会随全局语音包启用而切换大部分教学音源；新的pinyin.prefer-ai.v2默认false，不继承旧值。用户仍可在拼音资源设置显式启用AI优先，已知错音和导入录音的优先规则保留。缺少完整录音时使用已启用语音包补充，不拿单字录音冒充整词；不变更语音包音色/启停，也不替换课程录音文件。

字典词头、释义和例句继续独立使用语音包。透明原生点击层置于文字上方；准备/朗读提示、失败原因常驻列表外的底部区域，避免滚动后看不到页首提示。未启用语音时提供进入语音包设置的入口，不偷偷恢复已清除模型或覆盖停用选择。未知字符仍明确报错，不承诺全库任意正文均可合成。见tracking/evidence/AUDIO-ROUTING-20260920.md；手机实际点击和听感未复验。

## 18. 双模型与系统文字转语音（ADR-111/112）

随应用提供MeloTTS中文模型（44100Hz、官方单女声、191246123字节）与Kokoro中文v1.1 FP32（24000Hz、414330311字节，含前处理数据；真机修复后替换原INT8）。两者分别固定来源版本，按嵌入目录逐文件校验解包，运行时不下载。模型及Kokoro voices.bin不修改；模型元数据包含103音色，其中55中文女声、45中文男声在界面可选，3英语音色不作为普通话选项。资源另附Melo MIT、Kokoro Apache-2.0及espeak-ng/分词数据许可；正式许可审查与发行义务仍后置，开发接入不视为发行批准。

“设置→朗读声音”统一选择MeloTTS、Kokoro、系统文字转语音，支持音色选择、固定句试听和语音包缓存管理。新安装默认MeloTTS。旧AISHELL启用状态在校验新模型成功后迁移到Melo默认音色0；旧停用/移除保持，失败保留旧选择可重试。旧模型缓存不删除，但不再随新版打包。两套模型分别存储、启停和恢复，操作一种不改变另一种。

字典头词/释义完整段落/完整例句和普通阅读缺录音目标共用当前音源。选择系统语音就是对后续点读使用设备语音提供方的明确选择，不再逐段弹确认；系统音色ID仅存在本机偏好，不进个人备份。Android只枚举已安装且声明不需联网的普通话音色，Windows使用已安装普通话；vivo系统语音已有真机清楚试听确认，断网场景仍需另验。系统TTS不遵循人工拼音，也不自动换成AI音色。

## 19. 真机修复与缓存边界（2026-09-20）

Kokoro INT8在vivo产生非有限采样，现使用固定源FP32 `model.onnx`，明确语言zh；固定语音包上限512MiB。新包完整验证后按相同speaker ID保留选择，失败保留旧选择，旧缓存不删除。来源、哈希和实际验证见 `tracking/evidence/DEVICE-SPEECH-20260920.md`。

进程内缓存已验证文件的长度/修改/创建时间，文件变化或缺失时重新校验；安装、移除清缓存。首次进程及安装仍完整验证SHA256。最多缓存一个原生引擎和一个字符词典，调用串行；模型或明确音素表变化时重建，窗口停止/销毁先停止播放再释放。缓存不使模型首次解包或长段落合成变为即时。

Android支持zh-Hans/zh-Hant/zh/cmn等普通话标签，排除粤语及不合适地区标签，保留已安装/无需网络过滤。音色ID由转义名称加语言标签构成，兼容旧名称偏好，避免多个zh同名冲突。字典点击时懒加载播放服务；常见标点归为停顿，未知字符不静默略读。

拼音教学不随正文音源切换：原录音优先，缺完整录音时仍由MeloTTS按课程音素/声调补读，保留已知错音录音保护。Melo适配独立音素和逐音素声调，字典可解析词头同样适用；Kokoro/系统按正文合成，不声称受展示拼音控制。

用户明确要求字典点读：重复点击同一目标，在准备或播放期间取消；点击其他文字/段落，先等待旧任务停止和原生清理，再开始新任务；离页取消。所有引擎和录音共享PlaybackCoordinator；字典按稳定目标ID切换，旧请求不得更新新请求状态。
