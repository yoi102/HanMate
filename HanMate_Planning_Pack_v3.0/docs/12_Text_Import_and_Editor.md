# 12 · 文本导入、编辑、草稿与修改关联

> HanMate 文档包 v3.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 正式名称：HanMate / 汉语小伴；R01—R22 为需求基线，其余明确标注的规则为可调整默认设计。

## 1. 首版格式

手工输入、粘贴、TXT、`.hanpack`。TXT 支持严格 UTF-8、UTF-8 BOM、带 BOM 的 UTF-16 LE/BE。无 BOM 且不是合法 UTF-8 的文本返回编码提示，保留文件引用供用户重选；不使用自动替换字符吞掉乱码。

首版不解析 Word、PDF、图片或 HTML，不执行 Markdown/脚本。导入的任何“指令”都只是教学原文，开发 Agent 也不能把样例内容当成更高优先级指令。

文本文件 ≤1 MiB；正文单篇/全部 textUnits 合计 ≤20,000 文本元素；词条头部默认 ≤64 元素；标题 ≤120 元素；例句最多 20 条。上限是产品保护值，超限拒绝并说明，不静默截取。

## 2. 流读取与原文保持

系统文件结果通过流读取，不长期保存临时授权路径。MAUI 文档明确 FullPath 不总是物理文件路径，Android 可能返回 content URI；使用 OpenReadAsync 等流接口。[S05](27_References.md)

读取时累积实际字节并限制容量；先识别 BOM，再用严格解码器。保留原始 LF/CRLF、空行、标点、组合字符和繁体字。移除编码 BOM 属于解码，不把它当正文可见字符；其他内容不静默清洗。

可以提供显式“整理空行/简繁转换”的未来工具，但首版不在导入过程中自动做这些事。保存后能精确重建用户在预览中确认的正文。

## 3. 编辑器状态

`New → EditingText → Annotating → Reviewing → Saving → Saved`。任意工作状态都可产生 Draft；注音失败返回 Reviewing/EditingText 并保留原文，不删除草稿。

草稿保存包含 draftId、baseContentId、baseRowRevision、输入文本、已生成注音、人工锁定项、未提交音频引用和当前步骤。草稿的音频存 draft 目录，不进入正式资产引用集合。退出时可保存草稿，启动恢复先检查文件存在和可解码性。

默认输入结束后 1 秒保存草稿，或在页面切换/生命周期事件尽力保存；这是工程目标，不保证操作系统强杀前最后一毫秒输入都持久。界面可提示最后保存状态，正式“保存成功”必须来自真实事务完成。

## 4. 保存验证顺序

类型和标题 → 总字数/字节 → 原文有效性 → token/segment 覆盖 → 拼音格式/范围 → 分类一致性 → 音轨引用 → 版本冲突 → 原子持久化。

正文为空白不能保存正式内容；只有标点不能生成可播放片段，可作为草稿保留。未确认的字音允许保存个人学习内容，但保留显著待复核状态；不能自动设置 confirmed。

内置数据编辑：先复制为 personal，生成新 contentId/内部 unit/segment/token ID，保留来源引用。个人录音不自动复制全部内置资产，先按授权与绑定规则确认。

## 5. 自动注音与人工改音

生成前保留全文上下文及字典版本。分段用于布局和播放，不能先丢弃上下文再假装词组消歧完整。性能处理可按安全区块执行，但要保持正确短语跨边界匹配窗口和原文位置。

每次改音更新草稿状态，正式保存后刷新搜索与读音哈希。选候选与手工输入同等可保存；数字调输入转换成带调 display。再次自动注音只处理未锁定内容，全部覆盖必须独立确认。

## 6. 修改影响矩阵

| 修改 | 校正保留 | 分段/译文 | 音频 |
|---|---|---|---|
| 只改标题/标签 | 全保留 | 不动 | 不失效 |
| 只改译文 | 全保留 | 仅该译文 | 不失效 |
| 只改一个音 | 保留其他 | 不改边界 | 对应 unit 和包含该 token 的 segment 复核 |
| 前方插字，后文唯一不变 | 映射成功的保留 | 未变片段保留 ID | 不受影响目标保留 |
| 替换某一句 | 改动范围重新处理 | 该段译文需复核 | 该段及整篇音轨复核 |
| 拆段/并段 | 未变 token 可保留 | 片段关系和译文需复核 | 原段音轨不自动套入新段 |
| 重复文本无法唯一匹配 | 不自动搬移有歧义校正 | 展示差异预览 | 有歧义绑定需复核 |

整篇音轨适用整个 body unit，因此正文任一部分变动都会影响它；单段音轨只随相关 segment 变化。只改某例句不影响词语头部音轨。

## 7. 差异匹配算法建议

以文本元素数组做有界 diff，先确认未改前后缀，再处理改动窗口。对于重复文本，使用上下文及稳定编辑操作记录判断；无法唯一映射就返回需要用户复核，不能按“第一个同样文本”硬匹配。

大型替换不要运行不可控的 O(n²) diff；达到算法资源上限则回退为“该范围重新注音并复核绑定”的透明结果，保留旧版本草稿以便比较。性能回退不能悄悄丢掉旧人工校正。

## 8. 保存与并发

提交传 expectedRowRevision；仓储内验证后同时写 canonical JSON、投影、搜索索引、音轨失效和草稿完成标志。若其他流程已更新资料，返回 REVISION_CONFLICT，保留草稿并提供比较/另存新内容路径。

开始保存后防重复提交；成功后导航到相应详情，并可从“我的内容”查到；失败不关闭编辑器。没有音频的内容可成功保存，不强制用户授权麦克风。

## 9. 取消、恢复和备份

取消文件选择不产生空内容。取消自动注音保留输入与已有人工修改。丢弃草稿只删除草稿及其独占临时文件，不删除旧正式版本。

完整备份覆盖所有正式保存的用户内容和音频；未保存草稿不悄悄混入。导出前检测草稿与正在录音，提示先保存或明确排除；“完整”仅指已保存正式数据，预览中必须说明这一边界。


## 10. 四类创建、语法编辑与单条删除

新建菜单包含词语、课文、语法、诗词。TXT 导入默认课文，可选择诗词/词语；选语法时进入语法表单草稿，全文先作说明，用户补句型和例句后才能提交，不能把任意文章自动归纳成已审核语法。

个人四类内容都可删除，必须显示收藏数/录音数/草稿影响，事务清理关系；资源内容的“删除”采用撤下及恢复机制，另提供整包卸载。源包编辑使用复制为个人版本，全图新 ID 和来源保留，不直接写受控资源。

卸载资源不删已经复制的个人内容。新增条目若缺少例句/译文/录音，按对应类型最低保存条件显示状态，不虚构素材。grammar 至少一条正确例句、一个用法说明，word 可无例句。

## 11. 当前文字草稿边界 · 2026-09-17

W3-01已实现输入、粘贴、系统文件流TXT导入，严格UTF-8/带BOM UTF-16 LE/BE，1MiB、20,000文本元素与120标题元素上限。错误/取消保留原文，已有正文替换前确认；草稿列表分页、恢复、删除和另存。输入结束1秒自动保存，Shell离开时等待保存并在可取消导航失败时保留页面；操作系统强杀前最后输入不保证落盘。

内部draft.body_json以format=textDraft.v1存标题、原文和目标kind，不是ContentDocument，也不含生成注音/锁定/音频。四种kind仅记录意图；grammar正式表单仍待W3-07。W3-02/03将另行转换草稿、注音和正式保存，不把未注音原文伪装成完成教材。Android原文/重启/错误保留证据见本轮记录；剪贴板系统入口与完整软键盘/三平台运行仍待聚焦补验。

## 12. W3-02/03后续实现 · 2026-09-17

上节为W3-01交付时状态，现已显式转换为textDraft.v2并兼容旧格式。v2包含表单、注音快照/上版、引擎版本与个人正文期望修订；原文变化时旧快照暂存供差异/撤销，禁止将其作为当前正文直接提交。

后台生成与输入版本联动取消；句型/说明/例句最小表单可生成语法内容。人工候选或明确声调输入按出现位置锁定，未知同样锁定。正式保存前Schema与范围验证，草稿body/revision与正文修订核对，正文、索引、epoch、目标哈希、音轨复核及草稿完成同事务。失败保留输入/草稿，成功进入正式阅读页。资源编辑先复制全图ID，权限来源不提升。

有界diff保留唯一句段和公共前后缀；不确定人工项先数量确认，保留上次版本可撤销。移除已绑定目标整笔拒绝，可另存副本；复杂图先支持token改音，不截掉原图。多unit语法表单、个人删除、受引用快照和分享准备仍待后续任务，未从首版范围删除。
