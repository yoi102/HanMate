# 31 · 学习内容与资源包生命周期

> HanMate · 汉语小伴 · 文档 v3.0 · 2026-09-14
> 正式产品名已确认；这是开发规格与数据契约，不是已实现或三平台测试报告。


## 1. 两级管理，不把“删除”写成一句话

单条内容和资源包分别管理。单条包含 word/text/grammar/poem；资源包有稳定 resourceId、版本、来源、条目映射和可选音频。首版支持本地文件安装；将来下载得到同样的文件后使用同一安装管线。

| 动作 | 对象 | 默认结果 |
|---|---|---|
| 新建/个人分享导入 | personal 单条/多条 | 保存为可编辑个人内容 |
| 从本地安装 | `.hanresource` 学习包 | 校验预览后安装，管理包与条目身份 |
| 禁用 | 已安装包 | 隐藏普通列表/查询，可恢复；文件仍占空间 |
| 删除单条 | personal | 先显示引用影响并确认移入回收站；保留正文与关联，可恢复，不释放磁盘空间 |
| 撤下单条 | builtin/resource | 持久化 entry override，正常列表不出现；源数据不改写 |
| 恢复单条 | 已撤下条目 | 撤下标记复位；不重复造 ID |
| 卸载包 | installed_resource | 移除未受引用内容/可清理字节；默认保存受引用快照 |
| 更新包 | 同 resourceId 的新版本 | 完整验证、差异预览、同事务切换；不按发布时间覆盖 |

“禁用”不是“卸载”。卸载时明确显示能释放多少、仍保留多少；应用安装包里的原始资源不能由业务删除保证从安装体积消失，运行时投影和外部文件可按规则回收。

## 2. 页面 P13 与入口

学习页右上角“新建/导入”提供新建四类内容、导入文本/内容包、安装学习资源包；“管理内容”进入 P13。设置→内容与字典也可进入同一管理页，不复制一套管理逻辑。

P13 显示名称、来源、版本、各类型数量、启用状态、已撤下数量、占用与保留占用。操作包含本地安装、启用/禁用、查看条目、撤下/恢复、卸载。线上下载未实现时不出现能点击却假成功的商城按钮。

## 3. 持久数据

`installed_resource` 为安装登记、当前版本、distribution、is_present、enabled、priority、rowRevision；`resource_entry` 为 `(resourceId,entryId)→contentId`；`resource_entry_override` 保存用户撤下决定，不从内容标题猜身份。详情见 07 与 SQL。

descriptor 内容本身不授予官方身份。`distribution=bundled` 只能由应用可信安装路径设定，不能接受外部 JSON 声称“我是内置”就覆盖随附基础资源。`publisherId` 是声明，不等于身份签名。

一个 active content 只属于一个安装资源。学习资源和字典资源即使文字相同也各有稳定内容身份；个人复制完全独立，不被源包卸载删除。

## 4. 身份与版本

resourceId 是作者首次建立的 UUID，跨版本不变；entryId 在资源内稳定，字符串范围由 schema 限定。默认 contentId=UUIDv5(resourceId,entryId)，按标准 UTF-8 名称算法计算；不是把 .NET Guid 内存字节顺序直接当网络字节序。嵌套 unit/segment/token ID 在未改内容区域保留，变动按编辑映射规则处理。

安装版本形如 `1.2.3`，首版只接受无前导零的三段非负整数；比较按数值元组。应用版本、文档版本、Schema 版本不拿来代替资源版本。相同 ID/版本但内容指纹不同返回 RESOURCE_VERSION_COLLISION；更新不能改变 resourceKind。

外部包与可信内置资源 ID 碰撞直接拒绝。外部已安装资源的更新仍需预览及用户确认，来源不一致显示风险；不能仅用相同 publisherId 当成签名验证通过。

## 5. 安装事务

选择流→私有 staging→包类型/路径/限额/哈希校验→descriptor 和内容身份验证→构造安装计划→显示新增/复用/冲突及空间→用户确认→文件安装→SQLite 事务写内容、映射、索引、收据→提交后刷新→清暂存。

验证失败正式库不动。计划携带 expectedDataEpoch，确认后资料变化则重算。取消在提交前生效；短事务开始后完整提交或回滚，不暴露半安装状态。没有任意代码插件，资源只能带规定 JSON 和音频。

## 6. 卸载与引用保护

先扫描：收藏、用户录音/默认音轨、编辑草稿、拼音教学例词与高亮、正在播放/导出文件租约，以及明确保留项。停止相关播放；录音和草稿须先保存/取消。默认把仍被用户引用的内容改为 `origin=retained`，保留原 contentId 及内部音频目标 ID，写 `retained_content` 来源记录，从 resource_entry 解绑。

这样收藏/用户音轨不需要先断开再重绑，且原始来源版本可追踪。retained 不混入普通学习和字典结果，通过收藏、音频管理或“保留的资料”进入。用户可明确“复制到我的内容”使其成为新的 personal 学习条目。

无引用条目从索引、目标、内容中删除；音频实体/字节只在无其他引用且租约结束后 GC。不能用数据库级级联先删正文，再尝试补回录音。完整操作先生成预览，关系解绑/快照化/删除在同一事务内。

用户明确要求“同时删除收藏和用户录音”才执行破坏性路径，需单独确认并推荐安全备份；不能预先勾选。

## 7. 撤下单条和后续更新

包条目撤下持久化 `(resourceId,entryId,removed=true)`。查询过滤该条，但收藏仍可打开明确标为撤下的内容；录音不被默认删除。源包更新必须继续遵守撤下标记，不能重启或升级后让删除的内容重新出现在列表。

上游后来删掉此 entryId，override 仍保留，防止未来重引入时忘记用户决定。恢复时只清目标标记，不恢复整个包。若内容已经因卸载移除，恢复单条需要源包可用或使用保留快照，不默默联网。

## 8. 更新内容和录音

相同 resourceId/version/完整语义指纹且仍完整安装时重导入幂等；已经卸载或数据缺失时按当前状态重新生成安装计划，不能仅因旧收据存在就跳过重装。同资源更高版本展示新增/修改/移除；更低版本默认拒绝，显式回退另行实现后才开放。个人副本不被更新。

未被引用的条目可直接替换投影；受用户收藏/音轨引用且正文或读音变化的条目，先生成旧版本 retained 快照并全图重映射旧依赖到快照，再用稳定资源条目 ID 安装新版本。若未实现此迁移，不得声称已支持无损更新。只有标题/标签变化可以保留音频有效性；指纹与读音哈希用途区分。

安装收据与更新结果同数据库事务提交。失败旧版仍完整可用，不先删除旧文件腾空间。

## 9. 备份与分享

完整备份包含资源描述、启停、优先级、撤下记录以及可备份资源正文/音频；不允许的资源只作 referenceOnly 并显示缺失范围。引用身份不等于授权，来源限制不能被备份按钮绕过。详见 15、33。

用户分享一个包中的三条内容时，默认导出三条个人导入内容，不顺带分享整个安装包和管理状态。专门制作可安装资源包是生产/维护流程，不是普通学习内容分享的默认副作用。

## 11. 上限、错误与验收

初始安装资源上限 100、单资源最多 10,000 条，包字节限额复用 specs/limits.json；这是产品保护值，不是框架限制。超限不静默丢条目。关键错误 RESOURCE_VERSION_COLLISION、RESOURCE_KIND_MISMATCH、RESOURCE_ID_RESERVED、RESOURCE_DEPENDENCIES_EXIST、PLAN_STALE、INSUFFICIENT_STORAGE。

测试覆盖完整安装、重复安装、坏包、撤下持久化、卸载保留依赖、恢复条目、更新保留旧录音、禁用不是卸载。用例 HM-T141—HM-T152。


发布音轨身份由资源descriptor的`audioBindingIds`和`audioDefaults`固定保存；不能把用户后录音轨、改选的默认声音算入发布载荷指纹。此字段随descriptor_json迁移，完整规则见文档14第11节。

## 12. 启动安装与教学引用保护

随附资源仅在首次见到 resourceId 时默认安装。已登记但 is_present=0 的卸载记录保留 descriptor、版本和撤下偏好，启动或应用升级不得自动重装；用户从管理页显式重装才激活。已禁用的资源更新后仍禁用；缺失且未曾安装的 referenceOnly 登记也不能当首次安装请求。真实资源损坏与用户主动卸载分别诊断。

依赖扫描还包含 pinyin_item 中四声例词的 content/unit/token 引用。撤下或卸载这些例词时，普通列表照常移除，但拼音教学入口保留必要正文、拼音、高亮和已审核示范音频；用 retained_content.reason=explicitKeep 表达教学目录保留，管理页说明占用原因。教学引用解除之前不能被 GC。更新若派生旧快照，同事务重映射教学引用和 highlight，不把新读音自动当成已审核示范。

无当前拥有者时 descriptor.entries 是来源目录，不要求与空 resource_entry 相等；只有 is_present=1 的安装资源要求完整对应。卸载后仍有 override 时保留登记，不能因移除 installed_resource 被外键阻止而先清空用户撤下记录。

卸载保存descriptor、版本、优先级与override。外部相同原包重装和随附固定嵌入包显式恢复保持稳定ID及偏好；已存在同包仍幂等，停用状态不被偷偷重置，启动仍尊重缺失登记。真实SQLite和Android模拟器证据见tracking/evidence/W2-08-resource-management.md；完整三平台验收不由聚焦结果替代。

## 15. 个人内容回收站内部协议

`draft`中的`draft_kind=content`、`body_json.format=contentTrash.v1`为回收站标记，`target_content_id`指向原正文；该标记不是文字编辑草稿，TextDraftStore只列出textDraft.v1/v2。正文、拼音图、播放目标、收藏、音轨、文件与草稿均保留，不通过先删除再重建模拟恢复。本轮没有新增表或数据库版本。

预览包含正文revision、membershipRevision、dataEpoch和四类引用计数；移动前在写事务重新检查。移入和恢复均推进正文rowRevision及dataEpoch，使旧编辑提交过期；学习/搜索/收藏列表隐藏移入内容，正式正文写入、收藏变更及音轨目标操作拒绝修改回收站内容。恢复删除精确marker并重新显现原图。已有编辑草稿仍可另存副本；恢复后重新打开原文编辑。回收站允许只读预览。

暂不提供彻底删除或释放空间。未来完整备份必须分别处理已保存正文与回收站标记，分享不得把标记当教材正文或自动选中回收站资料。该内部格式尚未成为跨设备备份协议；W4需迁移/验证后才声明可完整恢复。最新证据见tracking/evidence/W3-07-W3-08-content-lifecycle.md。

## 16. 外部纯文字资源跨版本更新 · 2026-09-18

已安装的external纯文字资源支持严格更高三段数值版本，按整数比较而非字符串。更低版本、kind变化、bundled/保留资源ID、跨内容UUID冲突拒绝；已卸载资源先显式重装原版，不能借更新自动激活。发布者声明变化必须在确认中提示，但相同声明也不是签名认证。

同一读快照生成新增/变更/移除/未变及保留数量，20条分页差异和最终确认。语义比较只忽略source.resourceVersion与原有指纹规则中的时间/修订字段；其他来源、标题、标签、正文、注音或图结构变化均保守视为变更。未变条目原位更新版本、保留音轨/默认。变更或移除的受引用/已修改条目先复制旧完整图为新UUID retained快照，再迁移收藏（保持顺序/时间）、音轨target、默认和图实体import_mapping；资产、文件、binding UUID及读音复核状态不改。原资源稳定contentId安装新版，新版不继承旧录音；个人副本不修改。

更新保留enabled、priority与所有entry override，含上游移除条目的撤下记录。保留快照的source仍指向旧版，独立于卸载原位保留图，不会在同版重装时误接回。当前保守策略也会保留row_revision>1的变更条目，因此多次版本更新可能保留无外部引用的历史内容；暂不提供自动GC。

提交在同一SQLite事务重新计算依赖和正文快照守卫，再写快照/关联/新版/索引/descriptor/epoch/operation收据。旧内容rowRevision与membershipRevision不会重置，拒绝过期界面操作；重复operation幂等。纯文字更新不搬动媒体文件，不涉及文件系统与数据库的双事务。

草稿和教学引用的规范迁移见第17节；未知格式、未完成录音及无法核实的引用阻止整笔更新，不对任意JSON字符串做猜测替换。未支持资源音频、跨版本卸载残留接回、降级或完整备份。W3-08与W4-07保持IN_PROGRESS。实际验证见[资源更新证据](../tracking/evidence/W4-resource-version-updates.md)。

## 17. 已落盘音频草稿与规范教学引用迁移 · 2026-09-18

ResourceReferenceMigration在预览和提交中按已知字段识别引用。textDraft.v1/v2严格反序列化，检查当前/上一份annotation都为有效personal图且与受影响图ID不重叠，并核对target_content_id。资源复制编辑本来就使用独立UUID；source.resourceId、source版本和正文中的UUID字面值是来源/文本，保持原样，不再因为来源声明误阻止更新，也不因此额外保留原资源图。直接持有资源图ID的异常编辑草稿仍拒绝。

localAudio.v1只迁移ready音频草稿，核对draft ID、数据库target_content_id、目标所属图、合法哈希和已知字段。只替换Target.Id/ContentId；草稿ID、音频路径/字节、sourceRole、文本/读音哈希和Wave信息保持。更新draft行revision使旧界面保存/复核失败，用户从保留内容重新打开即可继续。旧哈希若已过期，迁移不予确认，必须按现有流程重新核对。pending仍阻止更新，先安全停止并恢复完整文件；不在迁移期间操作采集文件。FinalizeAsync写回增加原body比较，避免迟到的收尾覆盖已迁移或修改的草稿。

pinyin_item.body_json只接受现有pinyin-catalog.schema的item，包装验证后核对表内id/groupCode/display/sortOrder，四声唯一、available/unavailable闭包。对受影响的例字，证明content→unit→token真实所属、声调一致和文本元素高亮匹配，然后只改example.contentId和highlight的contentId/unitId/tokenId。高亮范围、note字面文字、reviewStatus、demoAudioAssetId及教学item身份均保持。一个教学行跨多条资源内容时，各映射在同一事务累积。未知字段/范围错误/所属不明整笔拒绝。
