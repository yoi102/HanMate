# 23 · AI 开发执行、审查与接续规则

> HanMate 文档包 v3.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 正式名称：HanMate / 汉语小伴；R01—R22 为需求基线，其余明确标注的规则为可调整默认设计。

## 1. 文档如何进入仓库

当前本包位于工程根目录下的 `HanMate_Planning_Pack_v3.0/`，保留这一目录作为唯一规划来源；不要求平铺或复制到工程根目录。开始应用开发时显式读取本包 AGENTS；如需在工程根增加导航规则，只链接本包并保留已有规则。已有同名文件时先比较、保留历史，不能无提示覆盖真实进度。archive 是历史，不是第二份当前需求。

先读根 README、AGENTS、总体规划、PRD、STATUS、最近 ADR，再读取当前任务对应细节。不要把整套文档每次无差别塞入上下文，也不要只读一张任务卡而遗失全局不变量。

```text
结束时更新 STATUS、TEST_MATRIX、ISSUES、HANDOFF，并提交本次实际改动摘要。
```

## 3. 单任务提示词

```text
当前任务：<W编号和名称>。
先读取该任务前置证据、关联需求与模块文档，确认当前代码状态。
给出本次修改范围后实现正常路径、取消/失败路径和自动化用例。
涉及数据格式/交互规则变化先记录变更，不默默改变已约定行为。
实际编译测试，列出运行命令、通过/失败/未运行项和证据路径。
只提交与任务相关的必要变更，更新进度与下一次接续位置。
```

## 4. 独立审查提示词

```text
你负责审查，不把作者的“已完成”陈述当作证据。
按需求→入口→服务→持久化→异常→测试追踪当前任务。
重点查：假按钮/Mock残留、拼音范围错位、旧音频回调、空值唯一约束、
备份缺音频、ID映射不完整、提交后失败状态误判、权限/隐私和来源伪造。
输出可复现缺陷与严重度，指出实际覆盖及未覆盖的平台；不随意重写全仓库。
```

## 5. 中断后接续提示词

```text
读取 AGENTS.md、tracking/STATUS.md、HANDOFF.md、ISSUES.md 和最近决策。
检查 git 状态与实际变更，区分已提交、未提交、未完成和别人修改的文件。
先复现最后一个失败/阻塞点，再推进下一张满足前置条件的任务卡。
不要根据历史对话摘要宣称测试通过；重新核对记录及当前构建。
```

## 6. 决策与范围控制

U 表示用户明确需求；D 表示本文默认设计；V 表示仍需技术验证。改变 D 也须记录原因与影响；改变 U 必须得到明确需求变更，不用“为了 MVP”替用户删除功能。第三方库必须查对应版本官方文档/源码并编译验证，本文接口名不是现成库承诺。

不因为某个平台环境缺失就停止所有可独立进行的工作；标明 BLOCKED，继续纯逻辑/数据测试，但最终不夸大平台完成状态。发现矛盾时按需求优先级解决并记录，而不是复制两个相互冲突的实现。

## 7. 每次结束必须留下什么

当前 commit/分支、修改文件、需求/任务 ID、实际执行命令和结果、未执行原因、未提交风险、下一次具体文件与操作。禁止只写“继续优化”。任何用户数据破坏风险优先写入 ISSUES，不藏在结尾。

测试结果不可由 AI 自己改标 PASS 代替执行；目录素材审核不得伪造人名；录音为空/静音不能冒充标准教学声音；云服务必须另行批准。
