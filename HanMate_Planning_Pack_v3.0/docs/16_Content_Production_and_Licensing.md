# 16 · 教学内容、音频素材与来源治理

> HanMate 文档包 v3.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 正式名称：HanMate / 汉语小伴；R01—R22 为需求基线，其余明确标注的规则为可调整默认设计。

## 1. 内容不是程序占位数据

正式内容和开发样例分开目录/版本。页面能显示不等于拼音、译文与录音已经审核。AI 可以起草词条、例句、翻译和元数据，但不能写入虚构审校人、授权号、真人音频或“官方教材认证”。

本包所有语言样例均为开发草稿；除明确说明的容器验证外，没有人工教学审核结果，也没有正式教学录音。程序在正式构建中不能把 testFixture 自动提升为 published。

## 2. 初始内容计划

| 资源 | M1 技术样例目标 | 首版正式目标（可调整） |
|---|---|---|
| 词条 | 12 个，包含不同字数、轻声、多音字、ü | 100 个；每条原则上两条例句 |
| 课文 | 1 篇原创短文 | 6 篇短文，场景/难度明确 |
| 语法 | 1 个结构化语法点 | 12 个；说明、句型和至少两条例句分别审核 |
| 诗词 | 1 个来源明确的分行样例 | 6 首，正文与读音逐项校对 |
| 基础查词字典 | 一套少量词条的开发包 | 至少一套可管理字典，数量按实际审核清单登记 |
| 拼音表 | 完整条目结构、重点交互样例 | 完整教学清单、示范音频、四声例词可用性矩阵 |
| 日英译文 | 足够覆盖语言规则 | 正式发布词条/句段满足预期译文覆盖 |
| 音频 | 验证真实播放与录音的小样本 | 拼音专用示范必须齐全；正文音轨按实际音源清单说明 |

以上数量不是已经完成的内容资产。正文可按已确认标准录音/TTS 回退规则播放；如果宣传“全套真人离线朗读”，必须另外准备并审核完整对应音频，不能用系统 TTS 顶替宣传。

## 3. 分类体系

场景初始建议为问候、日常、家庭、学校、饮食、交通、购物、工作。难度为入门、基础、进阶、高级；学段/年级为另一套标签，空值表示未标注。不依据字数自动断言某词属于小学或某套教材。

分类 ID 使用稳定 ASCII code；标签由 UI 资源翻译。内容可以多个场景，难度默认单值，学段/年级按一致性规则校验。后续更名不改分类 ID。

## 4. 拼音教学目录

声母、y/w 拼写辅助项、单韵母、复韵母/特殊韵母、前后鼻韵母、整体认读音节按上一版建议编排，正式发布前统一教学口径。不要混合多套教材分类后仍宣称完全标准。

每项需要：稳定 ID、分组、拼写、说明、示范音频、四声例词列表、每个例词的目标 token 与高亮范围、缺例词原因。声母示范采用已选教学读法录制，不能用英语字母名替代。

例词必须真实且适合学习。四声不完整的项保留缺失说明；声母本身不是能直接加四调的完整音节。轻声解释单独放置，不占四声行位。

## 5. 审核流水线

来源/原创登记 → 中文正文与释义 → 拼音和多音字 → 日译 → 英译 → 音频 → 音文一致性 → 格式/交互校验 → 发布。

各维度独立状态：draft / needsReview / approved / rejected / missing。发布要求由内容类型决定，例如拼音教学项必须音频 approved；个人导入内容允许 draft，但不能带官方认证标志。

审核记录保存资源 ID、版本、审核维度、真实审核者、日期、问题和结论。表单见 `templates/CONTENT_REVIEW.md`。没有审核者就留待审状态，不填 AI 伪造的人名。

## 6. 文本与音频对应

录音脚本使用明确 contentId/unitId/segmentId 和正文/读音哈希。音频录制时记录读法、语言、说话者或提供方、实际格式、来源与可使用范围。音频替换不改变正文身份，但更新资产哈希和绑定。

儿化、轻声和自然连读需用同一教学口径核对；本调显示与自然变调发音的差异可以说明，但不能用该理由掩盖真正多音字读错。只对已有事实标“真人录音”，合成音标明合成来源。

## 7. 许可和分发边界

文本、现代译文、注释、音频、字体、字音词典数据分别登记来源与许可。仓库许可证与其合并的上游数据并不自动构成所有具体分发用途的结论；须核对具体文件与来源。[S14a / S14b](27_References.md)

产品策略默认只有明确允许的资源可出现在分享包；私有备份所需文字快照也应在内置内容选型时纳入授权范围。不要先收录不能满足迁移要求的素材，再在备份时静默丢掉依赖。

来源表保存 `sourceId / assetKind / title / authorProvider / sourceReference / licenseIdentifier / permissionNotes / canDistribute / canShare / backupPolicy / reviewStatus`。本包是工程治理建议，不代替具体发行地区和资料的授权判断。

## 8. 目录打包与升级

内容源在版本控制中维护，构建脚本输出只读 catalog 及索引种子，附文件哈希、schema 和目录版本。正式构建拦截缺源、缺审批、坏范围、错拼音格式和拼音示范缺音频。

升级保持稳定内容 ID；纠错更新 revision；用户复制版本不被覆盖。目录删除已被收藏/用户音频依赖的内容时保留必要快照。对新增字典或修音规则建立回归样例，避免一次修正另一批词条变错。

## 9. 发布统计

分别统计：已审核词条数、已审核例句数、课文/诗词数、ja/en 译文覆盖、拼音项示范音频覆盖、四声例词缺口、正文录音覆盖、来源待核项。不得把草稿计入“已完成资源”。

建议用 `tracking/content-inventory.csv` 管理素材。当前文件是待填清单结构与真实样例状态，不代表正式内容生产完成。


## 10. 语法与字典发布内容

初始正式内容目标调整为100词、6短文、12语法点、6诗词，另至少一套可管理基础字典。目标不是已审核数量。语法检查中文规则、句型槽位、正例、拼音、日英译文；字典检查词头、读音/义项、中文释义、来源以及重复项。

制作安装包需稳定 resourceId/entryId、版本、完整 entryMap、来源许可、真实录音清单；不得把公开网页“能下载”当成允许应用内再分发。工程样例为 draft，没有真人录音或教材认证。

代码许可、正文、译文、录音分别记录。canShare/backupPolicy 是审核结果的结构字段，不可因 AI 自动填 true 就当已获得授权。初版资源不混入受限文件后再交由用户“自己负责”。
