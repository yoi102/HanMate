# 08 · 离线注音、标调与人工校正

> HanMate 文档包 v3.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 正式名称：HanMate / 汉语小伴；R01—R22 为需求基线，其余明确标注的规则为可调整默认设计。

## 1. 能力边界

目标是离线生成可校对的拼音，而不是承诺理解任意人名、地名和古文。算法必须能够解释“词组命中、多候选、单字回退、未知”，不能伪造精确概率或“AI 已确认”。

内置教学资料通过人工审核提供确定注音；用户输入先自动生成，再允许修改。拼音源与语音源分离，显示校正不会自动驱动系统 TTS 的逐字发音控制。

## 2. 引擎路线

默认构建期加工合法可用的字音与词组数据，运行时由纯 .NET 引擎读取。字典使用 code point 访问汉字，文本范围使用文档规定的文本元素映射。词组数据和单字数据是候选来源，不自动等于准确教材。

pinyin-data 和 phrase-pinyin-data 分别提供字音与词语数据，词语库也可能包含多读音及上游合并数据；具体数据文件、版本、来源和许可须分别登记。[S14a / S14b](27_References.md) python-pinyin 可用作构建期参考/对照，不要求手机运行 Python。[S14c](27_References.md)

## 3. 确定性处理流程

```text
保存原文与文本元素映射
→ 识别可注音汉字段和非汉字范围
→ 读取当前内容中已锁定且锚点仍有效的校正
→ 在可处理区匹配已审核局部短语
→ 词组词典匹配（优先覆盖更完整的匹配）
→ 单字候选回退
→ 输出拼音、候选、来源、待复核状态
→ 合并有效人工校正
→ 生成带调 display 并做范围/词音数校验
```

词组候选选择首版采用可复现规则：人工覆盖 > 已审核短语 > 最长合法词组 > 显式词典优先级 > 单字。相同优先级仍有多个读音时保留候选并标待复核，不随机选一个并标 confirmed。最长匹配是基线，不宣称解决所有歧义；有实际错误样本再引入更复杂分词/消歧。

人工锁定范围是匹配边界，词典命中不可跨越并覆盖锁定项。词音数与汉字段元素数不一致（如儿化）需有显式映射，不能 `zip()` 截掉多出的字或音。

## 4. 拼音数据形式

标准保存形式是 base + tone + erhua。例：`base=lü,tone=4,erhua=false,display=lǜ`。轻声 tone=0；无可靠读音用 null。base 小写，保留 ü，不以 v 作为正式展示。

| 输入 | 规范结果 | 说明 |
|---|---|---|
| ni3 | nǐ | 数字声调 |
| liu2 | liú | iu 标调位置 |
| gui4 | guì | ui 标调位置 |
| lv4 / lu:4 / lǜ | lǜ | 输入别名统一 |
| ma5 / ma0 | ma，tone=0 | 轻声 |
| huar1 | huār，erhua=true | 只在合法儿化上下文使用 |
| nu | nu，无指定声调 | 搜索可用；编辑需用户确认 tone |
| ni6 / ni33 | 拒绝 | 不支持的/重复声调 |

无调输入在查询中表示“不限定声调”，在人工编辑中表示“尚未指定”，**不能无条件存成轻声**。用户编辑必须选 1—4、轻声或未知状态。

显示一般采用本调。连读变调的自然声音可能与本调显示不同，这是教学口径，不是每次 TTS 都错。若未来提供教学变调显示，需另设明确模式，不能混入首版默认数据。

## 5. 标调和 ü 规则

实现维护明确标调规则与合法音节表：先定位主要元音，处理 a、o/e 与 iu/ui 等情况；生成 NFC 带调拼音。不要把调号一律放在末字母上。`j/q/x/y` 相关拼写、缩写韵母和儿化以经审核音节规则处理，不以全局 `u→ü` 替换实现。

ü 的去调只去声调，不去两点。输入 `nǚ/nv/nu:` 可归一到 nü；`nu` 保持 nu。组合形式 `u + 分音符 + 声调` 和预组字符应得到相同 base/tone。`ê`、成音节 m/n/ng 等特殊输入可作为显式高级候选，未实现的形式标需复核，不能改成随便一个常用音。

教学规范来源和标调参考登记于文档 27；规则测试以 `examples/pinyin-cases.json` 为起点，发布前需教学校对扩展。

## 6. 人工校正与重生成

用户点击 token，可选择候选或输入新的合法拼音；保存记录 annotationSource=manual、locked=true、修改时间。校正默认只作用当前内容当前出现位置，不全局修改词典，不把整篇所有“行”改成同一读音。

“补全未确认读音”不碰锁定项；“重新自动注音”默认保留锁定项；“全部重新生成”先列出将覆盖的人工项并二次确认。确认后仍保留编辑前版本作为本次撤销/草稿恢复基础。

读音改变后同步刷新个人词条索引，增加 annotationRevision；对应目标的 pronunciationHash 变化时将绑定音轨标待复核。显示修改必须先进入草稿，正式提交失败时不谎称已保存。

## 7. 原文变化的锚点规则

每个 token 和 segment 拥有稳定 ID。编辑正文后，按未变区间和上下文做差异匹配；**只有唯一确定的原文范围映射才自动保留校正**。重复文本导致无法唯一判断时，宁可要求复核，也不能错误迁移读音。

改变片段复核：拆分/合并不按数组下标复用音轨；仅前面插入一段而后面原文唯一未变时保留后段 ID/校正/音频。正文完全重新替换时重新生成身份和绑定预览；标题变化不触发正文重建。

## 8. 本地字典覆盖

首版人工校正是内容级。开发侧可以维护审核后的短语覆盖文件，但每条须记录来源、原因、测试样本和版本。用户级“总是这样读”的全局个人词典属于 P1，不在本次编辑里暗中创建。

字典更新不覆盖已经确认的内置资料或人工锁定项；新算法结果以预览形式应用到未锁定范围。记录引擎版本和字典版本，便于复现不同版本的注音结果。

## 9. 必测样例与评估

最小样例含：银行/行走、音乐/快乐、重新/重量、长大/长度、得地的、轻声、ü、儿化、诗词多音字、姓氏、生僻字、Emoji、组合字符、拉丁字母和数字。词组正确与否以审核样例为基准，不用引擎自己的输出作为金标准。

分别报告字音准确率、词条全对率、多音字子集结果、未知率和人工锁定保留率。人工锁定保留率与范围一致性要求 100%；任意古文的自动注音准确率不承诺 100%。核心已审核样例必须全部正确或明确待复核，不允许安静误读后显示 confirmed。


## 10. 与新增模块的边界

Grammar 的说明和例句复用注音/锁定服务，句型 slot/operator 不强制生成拼音。新增/卸载查询字典不改变当前 IPinyinEngine 基础词典和已保存 token；语法资源更新也不能覆盖个人复制版的校正。

词条释义 definition 可以注音，但搜索主键仍从 headword 的已确认读音生成，不从释义的任意汉字反向扩展出假词条。词典来源不确定的多音字仍须候选/人工确认，不能因资源名含“官方”就认为已审校。
