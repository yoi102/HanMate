# 15 · 备份、恢复、冲突与崩溃一致性

> HanMate 文档包 v3.0 · 2026-09-14 · 状态：开发基线提案，非已实现报告。
> 正式名称：HanMate / 汉语小伴；R01—R22 为需求基线，其余明确标注的规则为可调整默认设计。

## 1. 完整备份集合

包含：所有已保存个人四类内容及其人工校正；全部用户音频与音轨选择；全部收藏夹和收藏；可迁移设置；依赖的正文/注音快照；安装资源描述、启停/优先级/撤下状态；来源许可允许备份的学习包与字典正文和音频。未保存草稿、正在录制的流、临时缓存不悄悄算作已备份，预览必须显示排除项。

首选“可携带的完整备份”：许可允许时携带已安装资源的正文和标准音频，并包含用户音频。受限来源或容量不能满足时，先阻止完整导出并列明原因；用户明确接受后才导出标为“部分资源未包含”的备份，resources 使用 referenceOnly 和 missingReason。目标设备缺源时不宣称完全恢复，也不默默联网。

## 2. 导出一致性步骤

1. 检查无正在写入的录音，提醒保存草稿；估算大小与剩余空间。
2. 获取数据快照和对应音频文件租约；抓取关系闭包和设置版本。
3. 读取不可变正式文件生成导出临时包；可进度/取消，逐文件计算哈希。
4. 写 manifest，关闭 ZIP，重新执行包校验。
5. 调用系统保存或分享；根据真实结果反馈。用户取消保存不是成功。
6. 释放租约；临时分享文件保留到安全期限或可确认不再使用，再清理。

不能直接复制正在使用的 SQLite 主文件作为可靠备份，尤其不能漏掉 WAL 相关状态。首版采用逻辑导出，SQLite 快照与文件租约由仓储协调。

## 3. 导入计划不等于执行

预检输出不可变 ImportPlan：包指纹、所有 ID 映射、新增/复用/派生统计、缺失目录音频、设置应用选项、目标数据 rowRevision/epoch、将删除项（替换）、需要写入的文件及空间需求。

计划预览后数据如果变化，执行前重新检查 epoch，必要时返回 PLAN_STALE 重算，不能使用旧冲突计数直接覆盖新资料。用户更换包或模式必须重新生成计划。

## 4. 合并规则

| 情况 | 默认处理 |
|---|---|
| 同 packageId + 同 packageFingerprint | 同次操作重试幂等；新的明确恢复按当前实体重新规划，见第 14 节；允许同清单 ZIP 重压缩 |
| 同 packageId + 不同 fingerprint | 拒绝 PACKAGE_ID_COLLISION，不把改过的包当旧包 |
| 同 contentId + 相同语义指纹 | 复用本机数据与内部目标 ID |
| 同 contentId + 不同语义指纹 | 保留本机，导入为新 ID 的个人/快照版本 |
| 新 contentId | 新建；内部 ID 同样检查冲突 |
| 同 folderId | 合并成员去重，保留本机名称/说明/排序并列出警告 |
| 不同 folderId + 同 nameKey | 保留双方；导入名加 `(导入)`、`(导入 2)` 等稳定后缀 |
| systemRole=default | 映射到本机唯一默认夹 |
| 音频 SHA-256 相同 | 复用物理文件；逻辑关系按映射保留 |
| 默认音轨冲突 | 已有本机选择优先，导入音轨仍可在管理页选择 |
| 设置冲突 | 合并默认保留本机；用户明确勾选才应用 |

不根据设备时间较新就自动覆盖。不同 contentId 即使汉字相同也不自动合并，它们可能是不同读音/义项。内容标题/分类/译文不同同样保留双方，避免只比较正文而丢掉用户编辑。

## 5. 全图 ID 重映射

冲突派生内容必须生成新的 content、unit、segment、token ID，不能只换根 ID 后让播放目标冲突。完整映射覆盖：tokenIds、grammar 的说明/例句/注意事项 unitIds、音轨 targetId、音轨默认选择、收藏 contentId、保留快照、内部例句关系和必要来源链接。来源 resourceId/entryId 作为出处保留，不能误当个人副本拥有的资源身份。

ImportMapping 记录源实体类型、源 ID、源语义指纹、目标本地 ID，并与提交结果同时入库。重复导入同一冲突包先查映射，不再新建第二个“导入副本”。导入中断但没提交时不留下“已导入”的 receipt。

多个包携带同一源 ID/同一语义数据可复用既有映射；同源 ID 数据变了则产生新的派生版本。外部包的“审核通过/内置”标记仅作来源声明，不赋予覆盖本机 catalog 权限。

## 6. 内置目录版本差异

本机内置内容 ID 与快照语义一致可复用；不一致默认保留快照为只读历史版本，记录源 catalog ID/版本并映射收藏/音频到该版本，避免把旧录音直接套到新正文。用户可主动切换到新目录版本，但不能在恢复中静默替换文字。

若用户想修改快照，复制为 personal。目录后续升级不删除仍被用户引用的快照。目录音频不存在时显示缺失；用户 package 音频缺失是包损坏，提交前拒绝。

## 7. 替换恢复

仅 backup 支持。含义是**替换已保存用户资料**，不是卸载应用、删除内置目录或改系统权限。先列出被替换的个人内容、收藏和音轨数量；二次确认后生成且校验本机安全备份，失败禁止继续。

取得维护门后将“删除现有用户关系/资料、写入恢复资料、映射设置、建立 receipt”放入同一数据库事务。数据文件先准备好，旧不可变音频在提交前不删除。新的默认夹与关联一次提交，避免短暂暴露无默认夹状态。

存在未保存草稿时先让用户保存/丢弃/取消恢复；不在后台清掉草稿。正在播放/录音时先按明确规则停止，不能与替换操作并发引用将被删除的目标。

## 8. 数据库与文件系统协议

| 阶段 | 已做的事 | 中断后的恢复 |
|---|---|---|
| Preparing | 私有 staging，解析/校验/计划 | 删除无正式引用的暂存 |
| FilesReady | 已校验新音频安装为不可变文件，持有操作标记 | 旧数据库仍有效；新孤立文件待 GC |
| Committing | 单个 SQLite 事务写关系与 receipt | 由数据库提交/回滚结果决定 |
| Committed | receipt 与正式数据同事务可见 | 数据已成功，不能按外部旧日志误回滚 |
| Cleaning | 清暂存、释放租约、排队 GC | 幂等重复清理 |

外部操作日志只帮助恢复，不作为“是否已提交”的唯一证据。启动时先查数据库 receipt/operationId：有 committed 记录就完成清理；没有且事务已回滚则保持旧数据并清孤立新文件。不能因写日志失败而删除已成功导入的内容。

每次操作使用唯一 staging 目录，文件拷贝采用临时名→关闭/校验→同文件系统改名；跨卷移动不假定原子。正式文件不覆盖同名不同哈希文件，已有哈希相同文件先核对再复用。

## 9. 取消与空间

校验、复制、压缩阶段可取消。进入短暂数据库提交阶段后停止接收取消，完成一个完整提交或回滚，并在 UI 说明正在完成保存。用户误点多次不启动并发恢复。

剩余空间预算至少覆盖暂存包/展开内容、新音频、安全备份、数据库/WAL 增长和余量；数值由实际文件估算。恢复过程中空间不足，旧数据仍可用；不得先删旧音频腾空间再发现新包损坏。

## 10. GC 与安全备份保留

GC 查数据库实际引用、草稿引用、播放/导出租约与操作保护标记；只有无引用且超过保护期才删除。首版保留最近 3 份本地安全备份为默认，但删除前展示体积，受磁盘压力时先通知；不能以后台清理误删唯一可回滚副本。

安全备份仍含私人文本与声音，默认未加密且只在应用私有区保存。系统是否备份该目录需发行阶段核查，不把私有路径等同于跨设备绝对保密。

## 11. 必测故障注入

在解压前、音频复制中、文件安装后/数据库前、事务中、事务提交后/日志前、清理阶段分别模拟进程终止与磁盘满。检查旧/新数据完整性、receipt、孤立文件、收藏引用、人工校正、默认音轨和索引。

跨平台执行 Android↔iOS、Android↔Windows、iOS↔Windows 六个方向。只有 JSON 相同不够，还要实际试听用户音频、检查语音偏好重匹配和平台保存/选择流程。


## 12. 新增资源状态的恢复

先验证资源 descriptor/指纹和所有 included 条目，再规划资源安装或同版复用；同资源同版本不同载荷拒绝，不当普通个人 ID 冲突悄悄派生为另一个“相同字典”。同 resourceId 不同版本不能同时 active；合并默认保留本机活动版，源版本按可读快照恢复用户依赖，预览提供显式替换资源版本操作。

合并备份默认保留本机已有资源启停/优先级/撤下，新资源使用包内状态；勾选“应用资源设置”才以备份值覆盖。替换用户资料时应用备份列出的资源设置，备份未列出的本机额外包默认保持安装但禁用，预览明确说明；彻底卸载这些额外包需另外确认。旧 v1 备份根本未记录资源状态，不能据空记录禁用/卸载新机现有包。

referenceOnly 只在本机找到完全一致源时激活，否则 is_present=0、enabled=0，显示缺失清单。用户保存的源 enabled 偏好可随恢复报告记录，但不写出“缺失却启用”的无效运行状态。保留快照、个人词条和独立注音词典仍可用。

## 13. 资源与用户资料的原子可见性

资源条目安装、用户收藏/音轨/快照映射、设置和收据在计划确定后一起事务提交；音频先安装不可变文件。出现语法引用丢失、字典类型非法、资源所有权冲突、磁盘不足，都在正式变更前拒绝或回滚。

可携带资源超过当前单文件上限时，不能静默丢字典后仍称完整离线迁移；先预估，明确请求用户减少内容或选择部分资源备份。用户录音不得在未说明情况下丢弃。

## 14. 重复包、重装与再次恢复

packageId/指纹是输入身份，operationId 是本次执行身份；收据只证明某次提交完成，不能证明其实体今天仍存在。同包连续重试且目标资料未变时复用；用户删除导入条目、卸载资源或编辑后再次恢复同一备份，必须重验当前实体与映射。默认不重放已完成操作；用户明确选择“重新恢复/重新安装”时生成新计划与 operationId，保留当前修改或经替换确认恢复，不能直接返回旧成功结果。

目标 DDL 新增 import_operation，允许同一 package_id 对应不同 operation_id；import_receipt 仍保留输入身份和首次结果。复用相同 operationId 的网络式重试只查询该次结果；新的显式恢复产生新 operationId，按当前实体和 epoch 规划。数据变更和操作收据同事务提交，回滚不保留成功记录；资源操作使用 resource_operation。实际仓储和平台恢复由 W1-03/W4 实现，本轮 SQL 内存检查不等于应用已支持重复恢复。

## 15. 文字内容包合并的已实现子集 · 2026-09-18

ContentPackageImportStore仅做增量个人文字内容合并，不提供backup恢复或替换全部。先完成三文件严格校验，再固定dataEpoch、扫描已有content图的全部实体ID并生成计划。任一content/unit/token/segment ID碰撞使整张源图重映射；语法三类unit引用、segment.tokenIds随图变换。无标题推测合并，无静默覆盖或恢复回收站内容。

import_mapping的content.v2命名空间以整张源文档的contentFingerprint作为source_fingerprint，为图内每个实体记录映射。只有映射完整、目标为仍存在的active personal图且重映射源图与当前语义一致时复用；旧副本被修改或移入回收站则重新另存。即使已有package receipt，也必须重新核验本机状态。同包规范指纹不同拒绝，ZIP重压缩不冲突。

提交重验epoch、冲突与复用语义，正文/播放目标/索引/映射/package receipt/operation结果一起事务写入。重复同operation返回既有结果；新预览生成新operation。取消在提交前回滚，成功commit后显示实际结果。这里没有媒体文件安装，因此不假装已解决文件系统与SQLite的备份恢复事务。

四类及语法全图往返、嵌套ID冲突、改动后再导入、回收站、过期计划、重复操作和故障触发器回滚已有真实SQLite测试；Android已验证新增4/冲突1→重复复用4。完整备份的收藏/设置/音频/资源/回收站语义、旧协议转换及六方向迁移仍待W4完成。

## 16. WAV资产安装与重复导入 · 2026-09-18

ContentAudioImport在正文映射之后规划asset/binding，并与正文共用epoch。content.audio.v1命名空间以资产语义、源绑定和目标本地UUID计算映射身份；复用时重新核查现有资产元数据及绑定语义。绑定被删或改过则新增并保留本机修改；正文全图改ID时，音轨目标同步改ID。源user/imported均以接收方imported落库。

媒体安装到应用私有audio/packages/SHA256.wav，先写随机.part、Flush(true)、同目录无覆盖改名，再验证实际字节。已存在文件必须重新验证，损坏文件不覆盖。所有文件可读后，asset/binding/preference与正文、索引、映射、收据在同一数据库事务提交；本机已有默认优先，needsReview不建立新默认。

文件系统与SQLite并非单一事务：提交失败或进程中断可能留下未引用但完整的文件，以及强杀时未完成的.part。旧文件不删；重试重新校验并复用完整哈希文件，数据库无成功收据则不认为已导入。当前不自动清理孤立文件或.part，GC必须另行证明引用和正在进行的操作安全。触发器失败及重试有SQLite/真实文件证据；真实设备强杀/满磁盘窗口仍NOT RUN。此流程仅增量合并，不提供完整备份替换。

## 17. 已保存有效资料的逻辑备份与合并恢复 · 2026-09-18

BackupExportStore在同一SQLite事务捕获有效正文、音轨元数据、收藏/顺序、可迁移设置和资源状态，并为实际文件登记export租约。离开事务后在大小限制内读取与校验不可变WAV，finally释放租约。预览持有已经读取的正文/音频快照，后续编辑不能混入同一个包。导出重新打包、严格回读验证后才写到ShareFileStore；每次导出使用新的packageId。未包含资源必须在预览列出并由用户明确接受；缺必要依赖或损坏音频则整体失败。

BackupImportStore复用ContentPackageImportStore的规划与单事务提交。正文、所有嵌套目标、语法引用、音轨/默认、收藏、资源/retained登记、设置、映射和操作收据一起提交。预览到确认之间重验dataEpoch和实际状态摘要，补足收藏夹/设置等仅更新rowRevision的路径。文件先安装到哈希路径；DB失败不留下成功收据，完整孤立文件可安全复验重用。本轮增量恢复不会删除或覆盖已有正文；完整替换及其安全备份/崩溃日志仍属于W4-04。

默认夹映射到本机唯一默认夹；同ID夹保留本机名称/排序，同名不同ID夹用不超过40文本元素的导入后缀保留双方。收藏成员按映射去重，保留本机已有顺序。设置默认保留，显式勾选才恢复UI语言/阅读/音频/最后使用夹；本地非迁移字段不经包泄露或覆盖。备份保留音轨user/imported/standard角色，普通分享接收仍转为imported，两条映射命名空间隔离。

资源在身份无碰撞、版本/完整载荷符合且不是外部伪装bundled时，可随备份首次安装；包括已验证的标准PCM16音轨。完全相同且存在的资源复用，保留本机启停/优先级/撤下选择。不同版本、载荷冲突、身份冲突或保留ID只能保留历史快照，不覆盖或降级本机资源，并在预览及结果列出。缺源登记保持is_present=0/enabled=0。这不替代W4-07的资源媒体更新/卸载/教学目录UI闭环。

未保存草稿、正在录制和回收站的内容不作为本轮备份输入：预览显示排除数量，pending录音阻止预览。回收站不被恢复操作悄悄复活；恢复相同来源时仍按当前状态创建独立图。备份界面不使用“完整替换完成”等误导表述。全部压缩格式、旧协议/旧库、六方向迁移、真实设备强杀满磁盘仍为后续门禁。


## 18. 当前完整替换与中断恢复 · 2026-09-18

前述历史阶段的“替换未实现”不再适用于当前版本。BackupReplacementStore以将回滚的事务模拟删除保存用户数据，生成真实影响及导入计划；保留已安装资源目录。设置页第一确认后，以同一SQLite读快照生成私有数据库和资产字节副本，Flush/哈希/完整性核验并写ready.json，然后要求第二次确认。未保存草稿/活动文件租约阻止，先处理草稿再重试；不删除真实麦克风采集文件。

安全副本包含回收站与旧资产，区别于正常逻辑备份的“有效已保存数据”范围。提交重验epoch、实际状态摘要和安全副本；删除个人/快照与旧收藏、写入恢复图/媒体关系/资源状态/设置/教学以及replace operation收据同SQLite事务。新图revision高于旧库，旧编辑不可覆盖恢复结果；同备份新预览可再次恢复。新备份教学集合显式替换；旧包缺该字段保留旧教学，有悬空风险则拒绝。

资源只恢复包实际携带且本机版本/载荷相符的状态；旧包空资源登记不卸载已有资源。版本冲突转历史快照并预览缺口，不自动降级。新媒体文件先安装，旧媒体文件保留；本段为2026-09-18状态，当前物理清理见第19节。

启动后SQLite执行自身事务恢复；“恢复记录”只查import_operation判断提交，ready.json或残留文件不能当成功收据。桌面独立进程四时点强杀及真实SQLite限页SQLITE_FULL已通过，详见evidence/W4-recovery-resource-compatibility.md；设备存储卷满盘、原生iOS与六方向迁移未验。

### 私有安全副本位置与人工恢复

数据库相邻recovery/<operationId>/hanmate.db和相对audio目录为整套安全副本，ready.json列出SHA256。应用不在后台自动删除它们。优先使用下节恢复向导；人工处理应先停止应用、保全当前库与音频并核验整套副本，不能运行时只覆盖main文件或忽略WAL/SHM。未对真实用户库执行破坏性恢复验证。

## 19. 安全副本恢复向导与孤立音频清理 · 2026-09-19

设置→备份与合并恢复→查看安全副本，列出时间、已验证体积、完整性及当前数据库中的提交记录。副本损坏、未完成或版本不兼容时保留目录并禁止恢复。当前只支持同schema版本的私有副本；旧版逻辑备份仍走既有包导入迁移。下载的AI模型与设备音色配置不属于此恢复范围。

恢复先预览将替换的正文、音频、收藏夹及回收站记录，保存当前数据库与全部资产为新的安全副本，再最终确认。SafetyRecoveryStore逐项核验SHA256、SQLite完整性/外键、表列兼容性与状态摘要；草稿和活动播放/导出租约阻止提交。媒体以临时文件核验后无覆盖安装；同路径不同字节拒绝。已知业务表按依赖顺序在同一SQLite事务中恢复，正文/资源/设置/草稿revision及data_epoch提高，旧编辑和操作计划失效。不会运行时替换DB主文件；WAL页由原生BackupDatabase读取。过期file_lease不恢复。

私有恢复沿用import_receipt/import_operation的replace模式，每次唯一UUID；result_json明确标为safetyRestore.v1并记录sourceId/rollbackId。数据和收据同事务，重复同operation不重放。schema保持v2，无新增表或假迁移；原ready.json兼容。恢复前状态的新副本可再通过同一向导取回。当前库必须可读且能生成完整安全副本；此功能不宣称修复已损坏的主库或覆盖损坏的同名录音。

扫描孤立音频不删除学习数据，只更新私有观察记录audio-orphans.json。仅识别audio/local与audio/packages中应用生成的GUID/哈希文件名，包括中断产生的.part；未知文件保留。首次观察后至少7天且大小/哈希保持一致才进入可清理清单；当前引用过的文件在下次扫描时清除观察时间。任一草稿或回收站记录、活动租约、损坏/未完成安全副本会保守阻止清理，提示先处理后重扫。正常副本所引用的媒体、有效audio_binding及非规范历史路径均受保护。

确认后再次检查引用、观察记录、字节身份及保护期。先在写事务中删除无绑定的asset元数据；提交后另开写事务重验新引用再删除文件。第二阶段若新增asset即跳过，不删除刚重新引用的音频。导入/资源安装同样持有SQLite写事务，录音在写文件前登记draft；安全副本创建/替换/恢复/保留与GC共用跨进程文件锁。崩溃在第一阶段后只留下未引用字节，第二阶段后没有指向已删除文件的旧asset行；重试幂等。audio-cleanup-last.json记录最近一次完成结果，不能据文件日志判断数据库是否提交。

整理安全副本先展示待删数及体积，默认保留最近3份完整副本；损坏、不兼容及未知副本不按年龄删除，唯一完整副本不会入选。确认后先把已批准目录改名到recovery-retired，再清理；独立批准标记支持中断续清，未批准未知目录保留。应用私有目录及其子目录拒绝链接/目录联接与路径越界；平台拥有的上级目录不属于扫描/删除范围。全部故障验证在TEMP隔离库和工程音频中完成，设备真实数据未做替换或删除。

本阶段验证范围与平台限制见[阶段B证据](../tracking/evidence/STAGE-B-20260919.md)。

## 字典收藏恢复（ADR-107）

字典收藏是用户引用，独立于“应用设置”选项迁移。合并按(provider,entryId)去重，重复键保留本地标题；v1备份合并不清除本地字典引用。完整替换在已有安全副本和同一事务内清除旧引用，再恢复来包引用；v1完整替换因此清空旧字典收藏。安全副本包含原user_settings，失败回滚保留原引用；收藏变化推进row_revision并使旧导入预览失效。来源丢失保留引用与标题，不以正文快照绕过默认字典的导出限制。
