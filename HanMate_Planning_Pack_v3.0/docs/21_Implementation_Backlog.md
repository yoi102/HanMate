## 2. 执行说明

连续区间如W1-04..06表示该阶段所有指定任务。基础安装任务先完成真实文本资源通路，音频依赖在后续共享音频服务中接通并全量回归；不得把仍未完成的用户录音迁移算作首版完成。页面可在存储服务具备后并行，但无效按钮不能进入正式版本。

每项完成需要代码位置、构建/测试命令、实际结果和关键异常路径。状态TODO→IN_PROGRESS→REVIEW→DONE；环境受限写BLOCKED，不能为了通过而删P0测试。

## 3. 开始与升级

首次从W0-01审计真实仓库、SDK/平台和已有数据开始。已有v2实现先按34制定迁移，不用目标新库DDL清空用户数据。每次完成更新STATUS、HANDOFF、ISSUES、TEST_MATRIX。文档校验与应用测试分别记录。

## 4. 实施顺序的补充约束

M0 技术试验与基础 Core 建模可交错推进：W1-01 只依赖仓库审计，不能让缺少某台设备锁死全部纯逻辑工作；真实平台能力与依赖版本仍由 W0-06 关闭，不标为已验证。48 项是工作包，不是 48 天工期，每项可拆成有验收记录的小任务。

W1-09 必须从第一条外部安装路径就执行严格容器和数据校验；W4-01 是音频/备份扩展，不是到 M4 才补输入安全。文本阶段遇到含音频资源应提示当前开发阶段尚未支持并拒绝整个包；正式发行前接齐完整音频链。

W2 播放页共享最小音频协调器，先完成单会话、取消、完成与迟到回调规则；W3-04 扩展录音和平台生命周期，不能各页面先创建一套临时播放器。W4-04沿用W4-02的快照/媒体校验基础，另用私有SQLite与音频一致安全副本覆盖回收站等本地状态；综合故障与迁移（本轮依ADR-105为Windows/Android两方向）覆盖 W4-07/09 的资源和兼容链之后才能结项。

内容来源收集、许可核查和教学示范准备从 M0 开始，随可用页面抽样验证，W5-02 是终审关口。不得到 M5 才寻找第一批录音或字典。没有已发布用户库的证据时，W4-09 先使用归档 DDL/包构造兼容夹具；发现真实历史库后再增加其迁移路径。

2026-09-17（ADR-030）：W1-09 不再等待 W0-05 的三平台保存/分享全部关闭；它依赖内容、资源模型和五入口，并自行验证当前可用平台的 FilePicker→流→预览→安装。W0-05 继续承担其余平台、保存和分享验证，不将 Android 的聚焦安装结果扩大到三平台。M0/M1 仍未整体完成。
